# .NET API, memory, and ownership

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

Baseline `net11.0`/C# 15, nullable enabled, explicitly pinned qualification/shipping software development kit (SDK) per [29](29-project-setup-build-and-deployment.md); no net48, mandatory preview-language features, custom garbage collector, replacement general collections/numerics/task framework, or rule forcing all application state into unmanaged ECS components. [12](12-entities-components-and-queries.md) defines unmanaged component storage and separate managed resources. Chapter [06](06-owned-geometry-and-numerics-interchange.md)'s small owned public geometry family reuses base class library (BCL) kernels rather than expanding into such a framework. Release candidate 1 (RC1) qualification does not certify a future GA binary.

## 1. Public library conventions

The root namespace is `TerraFX`; [29 section 1](29-project-setup-build-and-deployment.md#1-repository-and-assembly-dag) defines namespace placement. Use `PascalCase` for types and members, `camelCase` for parameters, descriptive nouns/verbs, `I` prefixes for interfaces, an `Async` suffix for asynchronous methods, and conventional `EventArgs`/events. Acronyms follow .NET conventions (`GpuBuffer`, `DpiChangedEventArgs`); do not suffix types with `Manager`/`Impl`/`System` merely to hide ownership.

Members that implement or override a .NET contract match the official framework declaration, including parameter names. If a TerraFX declaration or example differs, correct the documentation to match the official signature rather than suppressing diagnostics such as CA1725 to preserve the mismatch.

Physical assembly/package boundaries do not mirror every namespace. Keep logical subsystem dependencies and issuer/ownership restrictions enforced when code shares Runtime; internal visibility does not broaden an owner's authority. Library packages have one product assembly, not a bundle of subsystem DLLs; precise feature registration/rooting and native-asset selection determine publish contents, not package count.

Sealed reference types own mutable services, native storage, and disposable leases; structs model small values, handles, and components. Public handles are `readonly`, equatable values with invalid all-zero defaults, not pointers, `Dangerous*` accessors, or native-handle escapes. Configuration uses typed options with validated `init` properties and owner-defined defaults, frozen at creation. No marker `IComponent` interface, mandatory component inheritance, public mutable service fields, virtual-by-default API, or global mutable singleton service is required.

The API baseline lists every public constructor explicitly; no class relies on an implicit public parameterless constructor. Public value constructors take all validation inputs and have no optional parameters. Options classes declare either an explicit input constructor or an explicit parameterless constructor plus named `init` properties. Factory/owner-created services and operation-produced records have no public fabrication path. Language zero-initialization does not establish a configured option, identity pose, or valid handle. Declaration initializers must match the owning contract's defaults.

`EngineHost`, `World`, `GraphicsDevice`, `AudioMixer`, `InputRouter`, `AssetStore` and `EditorSession` are feature entry points. Convenience must preserve the full owned lifetime; no factory returning an apparently self-contained object with hidden process-global engine dependency. Interfaces are justified by backend/host substitution, not generated for every concrete value.

Performance-critical synchronous callbacks use [05](05-owned-buffers-and-internal-collections.md#6-shared-callable-protocols)'s reusable IAction/IFunc/IReadOnlyRefFunc conventions with an `Invoke` member and constrained generic dispatch. Buffer windows, chunk queries, object-pool use and per-hit physics visitors take `scoped ref TAction`/`TVisitor`, constrained to `struct`, the applicable interface, and `allows ref struct`. This admits ordinary value types, including managed-reference-bearing state, and stack-only callable state without interface boxing or a captured delegate. Keep the concrete generic type through internal adapters; do not erase it to an interface object. The engine neither copies nor retains the callable, so its mutations remain visible to the caller even when invocation throws. Borrowed ref-struct/span arguments cannot escape; an ordinary managed-reference argument is not revocable merely because the generic protocol is scoped. Coarse host dispatch, publication notifications and render-pass recording may use ordinary delegates where invocation cost is amortized. These are the three used conventions, not a universal `IFunc` framework or a claim that every constrained call is inlined.

Use enums for operation/status kinds and validated `[Flags]` plural sets, not `bool` chains or magic integer material/shape kinds. Use conventional exceptions for argument/disposal/ownership misuse, unexpected I/O/device/solver failures and internal invariant violations. A `bool` Try method has one expected false condition and documented out validity; false does not hide invalid arguments, a foreign owner, corruption or a device fault. Where several expected outcomes matter, return an operation-specific enum plus documented outputs, or a dedicated domain response/receipt carrying meaningful metadata. Do not introduce generic `Result<T>`/`Option<T>`, public union-based outcomes, or a universal error-code layer. Do not catch broad `Exception` to continue in a successful state; [13](13-jobs-and-frame-pipeline.md)'s isolated post-commit subscriber boundary reports explicit delivery failure.

Public API/schema compatibility follows recorded major/minor rules; reject unsupported serialized major versions. Public data uses named classes/structs and explicit documented members, not positional tuples/records whose synthesized constructor, deconstruction, equality or formatting accidentally becomes a versioning promise. The sole current tuple exception is `Angle.SinCos()` returning `(float Sin, float Cos)`: a fixed mathematical pair with immediate deconstruction and no planned extensible payload. It is not a domain receipt, stored schema, general outcome protocol or permission to expose unrelated tuples. In prose, "record" means a data contract, not a C# record declaration. Enums and sealed shape/command definitions require compatibility review when extended. C# 15 unions/closed hierarchies may be application/internal choices; they are not reusable-framework defaults or plugin extension points, including when a custom representation avoids boxing.

> **Informative rationale:** Application-oriented synthesized APIs do not provide a stable framework versioning contract by themselves. Ordinary object-backed unions also box value cases and cannot serve as `unmanaged` ECS/solver/audio storage. Rare exceptional paths do not justify replacing the established .NET error model without workload evidence.

### Integer types and boundaries

Prefer `int` over `uint`, `nint` over `nuint`, and `long` over `ulong` for arithmetic-facing counts, indices, dimensions, sizes, offsets and ordered counters. A nonnegative domain is established by validation, not by choosing an unsigned type. Use `int` for span/array counts and bounded indices, `nint` for contiguous CPU-storage extents and offsets, and `long` for fixed-width logical extents, aggregate budgets and timelines. A GPU resource or large file does not by itself require an unsigned public size.

Use `byte`, `sbyte`, `short` or `ushort` where their range, packing or representation suits the scenario; do not narrow an ordinary loop counter merely to suggest optimization. Ordinary arithmetic on these narrow operands promotes to `int` and may provide useful input-range information, but intermediate results and narrowing still require the field's overflow rules. This is a CLS-friendly default, not universal CLS compliance: `byte`/`short` are CLS-compliant; `sbyte`/`ushort` are not. Signed arithmetic/indexing conventions and compiler range analysis motivate the default; neither signedness nor narrow storage guarantees better JIT/AOT code. Measure consequential hot-path choices under [28](28-diagnostics-performance-and-validation.md).

Retain unsigned types for an actual full-width value/bit domain or an explicitly frozen representation, not merely native API spelling. Existing exceptions are [03](03-shared-conventions-and-clocks.md)'s `uint` owner/slot/generation and device/surface/swapchain identity tokens, permanent numeric schema tags/profile codes, [14](14-custom-input-actions-and-text.md)'s 64-bit context masks, [22](22-custom-physics-world-and-solver.md)'s 64-bit collision masks/32-bit contact clip codes and frozen exact tolerance ratios, and [27](27-state-serialization-replay-and-recovery.md)'s modulo PRNG state/output. Shader/native/wire packers preserve their independently specified unsigned bits. Retaining an identity token's full domain also retains its unsigned comparison/retirement rules; do not reinterpret its high bit as a negative arithmetic index.

Negative counts/storage offsets or an inadmissible domain value reject before mutation/native admission; zero remains valid only where the owner contract permits it. Signed quantities such as priorities, registered system order and draw base-vertex adjustments retain their owner-specific negative-value semantics; this is not a blanket ban on negative integers. Check count-times-stride, alignment rounding, sums, next-counter values and narrowing before using them. Bounds may instead use subtraction after validating `0 <= offset <= extent`; never rely on an overflowing `offset + length`. A signed count does not make a native pointer's high address bit invalid. Native calls use checked, field-specific conversion after validation, not unchecked bit reinterpretation or clamping. Ordered-counter exhaustion refuses before the next value or any externally visible work is published. Observational telemetry may saturate only under an explicit owner policy with observable saturation; it never silently wraps.

Public type selection does not rewrite [10](10-binary-data-and-authoring-formats.md)'s permanent wire kinds, tags or binary layouts. Unsigned wire counts/revisions mapped to signed semantic fields must fit that field's admitted range; decode rejects unrepresentable values before allocation/activation, and encode accepts only validated values. Truly opaque/mask fields retain all specified bits. Generated schemas/accessors, adapters and consumers follow the same distinction; an accepted schema's validation/compatibility rules cannot be narrowed silently.

### Public type boundary

Review implementation reuse separately from public type identity. A BCL implementation choice does not authorize that type in public parameters, returns, properties, base types, constraints, callbacks or transitively reachable payloads. Foundational status follows the boundary's semantic/interchange role, not merely BCL membership, widespread use, immutability or equal layout. The goal is stable TerraFX contracts, not eliminating BCL dependencies or renaming every framework type.

| Boundary role | Public design rule |
|---|---|
| Foundational interchange values and .NET protocols | Use primitive numeric types, `string`, `Guid`, `TimeSpan`, `Span<T>`/`ReadOnlySpan<T>`, `ImmutableArray<T>`, `Task`/`Task<T>`, `CancellationToken` and standard equality/formatting/disposal contracts directly where their semantics fit. Preserve the documented borrowing, completion and cancellation rules; do not add engine substitutes merely to hide their namespaces. |
| Replaceable implementation services and storage | Keep `Stopwatch`, clock-source implementations, concrete general-purpose collections, scheduling queues and similar backing machinery private. A needed public component has a TerraFX semantic contract whose representation/implementation can change without requiring callers to adopt the backing type's state model or methods. |
| Explicit ecosystem interchange | External types belong in a reviewed adapter/conversion boundary whose purpose is that interoperability, such as the named `System.Numerics` conversions. Such a boundary does not make the external type the core engine's representation or require every consumer to depend on the adapter. |

Using `Stopwatch` timestamps or `TimeProvider` internally does not require callers to create, pass, retain, subclass or interpret those objects. Public timing uses the engine's clock-domain values/operations and suitable foundational durations. If public clock substitution or a stateful measurement component is needed, define its epoch/unit, ordering/conversion, running state, ownership and threading semantics in [30](30-public-api-review-surface.md), including frequency when raw ticks are exposed. Do not introduce a public Stopwatch-shaped wrapper or clock interface merely because the private implementation uses one.

`ImmutableArray<T>` is accepted as foundational array interchange: its documented representation is a trivial `T[]` wrapper whose public surface blocks element writes. That intentional array contract is not a commitment to a general collection algorithm. It does not make referenced elements deeply immutable or erase the existing validation, aliasing and retained-ownership obligations.

Do not expose `Dictionary<TKey, TValue>`/`List<T>` simply because they store the data internally. `ImmutableDictionary<TKey, TValue>` is likewise an implementation-specific dictionary, not a foundational exemption; private storage may instead use `FrozenDictionary<TKey, TValue>` or a custom implementation. Public lookup boundaries use `IReadOnlyDictionary<TKey, TValue>` where that protocol fits. For measured hot paths with a known concrete caller type, a scenario-specific constrained `TDictionary` can avoid interface-erased dispatch/boxing; it does not promise inlining or allocation-free enumeration. Do not make coarse response types generic merely to use that mechanism.

Review collection boundaries for ordering, lookup, mutation, snapshot/copy, lifetime and allocation behavior. `IReadOnlyDictionary<TKey, TValue>` does not itself establish immutable backing: an immutable result must publish stable contents without writable aliases. Mutable backing needs a nonwritable facade and no later mutation; never return a mutable dictionary itself merely typed as read-only. Dictionary enumeration does not become canonical serialization/replay order unless explicitly specified. [30](30-public-api-review-surface.md) owns the concrete signatures, and each owning implementation unit under [35](35-implementation-roadmap.md) verifies these semantic boundaries independently of the reuse ledger.

## 2. Reuse ledger

This ledger records reuse candidates, not a public-signature whitelist. [The public type boundary](#public-type-boundary) determines which reused types cross an API boundary.

| Need | Reuse candidate | Engine-owned responsibility |
|---|---|---|
| Geometry/numerics | `System.Numerics` kernels/explicit interchange, scalar type methods/generic math and BCL intrinsics | [06](06-owned-geometry-and-numerics-interchange.md)'s six `readonly` `TerraFX.Numerics` public types, engine factories/units/layout/profile and bounded kernels in [08](08-binary32-kernels-and-predicates.md); no general BCL replacement |
| Time | Private `TimeProvider`/`Stopwatch` backing; `TimeSpan` duration interchange | Engine clock domains, conversion, tick/event ordering and sample clock; no required public backing object |
| Buffers | `Span<T>`/`ReadOnlySpan<T>`, typed arrays/`ArrayPool<T>`, `NativeMemory` privately | [05](05-owned-buffers-and-internal-collections.md)'s large unmanaged owner/leases/windows/chains and actual-completion retention |
| Collections | Private `Dictionary`/`List`/`ImmutableDictionary`/`FrozenDictionary`/`PriorityQueue` where appropriate; `ImmutableArray` array interchange | Independently reviewed public collection contracts; contract-defined observable order; private managed-value/native-value stores and specialized archetype/BVH/rings with explicit owner/view/copy invariants |
| Threads/async | `Thread`/`Task`/`CancellationToken`/`Channels`/`Interlocked`/`Volatile`/`Lock` | Engine stage DAG, worker ownership, audio nonblocking protocols |
| I/O/data | `FileStream`/`RandomAccess`/`SafeFileHandle`/`BinaryPrimitives`; JSON/XML tooling parsers | [10](10-binary-data-and-authoring-formats.md)'s native binary formats/schema/bounds/migration and interchangeable authoring adapters |
| Native | `LibraryImport`/`NativeMemory`; boundary-appropriate `SafeHandle` and pinned reviewed low-level API bindings | ABI/thread/fence ownership, direct native ownership where lifetimes coincide, and private unsafe operations |
| Telemetry | `EventSource`/`ActivitySource`/`Meter`; optional `Microsoft.Extensions.Logging` adapter | Engine error identities, spans/counters and overlay |

Modern private candidates include `SearchValues`, span splitting, alternate span-key dictionary lookup, scalar/span/UTF-8 formatting, explicit Guid byte-order and lower-case hex operations, and resettable compression codecs. Selection records exact framework availability, equivalent semantics, bounds, AOT rooting and matched workload evidence. Reuse does not change UUIDv8 bytes, canonical ordering, EBIN1/EPKG2, None/Brotli codecs or the numerical profile. Estimate/FMA/minimum/NaN variants are not interchangeable kernels. .NET 11 decimal/BigInteger floating conversions now round the exact source once; runtime upgrades require semantic requalification even where API signatures are unchanged. Do not substitute an intermediate decimal/double conversion for the engine's exact rational-to-binary32 evaluation. Experimental transport APIs and `Microsoft.Extensions` conventions are not core-BCL requirements.

`ReadOnlySpan<T>` is a view, not immutable backing data. `Span<T>` may be returned/stored in a `ref struct` where legal; it cannot live in an ordinary heap field. Mainline native owners expose only scoped callback windows, not escaping spans. Engine-authored runtime and tooling code does not use `Memory<T>`, `ReadOnlyMemory<T>`, or `ReadOnlySequence<T>`; there is no private BCL-bridge exception. This constrains engine source, not the internals of reused framework libraries. Synchronous operations use spans or typed managed storage; retained work uses explicit owners/leases. I/O uses bounded synchronous span operations on dedicated I/O workers or reviewed native asynchronous operations with actual-completion ownership, not spans retained across an `await`.

Geometry's `AsSystem`-prefixed forward members and `AsTerraFX`-prefixed extensions on the BCL types are bit-preserving by-value interchange, not a lease or borrowed alias. Raw IEEE arithmetic deliberately follows chapter [06](06-owned-geometry-and-numerics-interchange.md)'s nonfinite/equality rules; constrained helpers have conventional throwing/Try pairs. Immutable row/component values are copied, and engine-owned type identity is not waived by equal layout. The current ordinary C# 15/BCL surface not requiring an unsafe context for `Unsafe.BitCast` is a point-in-time fact, not an authoring invariant. Treat its use as an unsafe implementation boundary now: put it in a narrowly scoped `unsafe { ... }` block with reviewed size/layout/no-reference proofs, preparing for Unsafe Evolution's requires-unsafe classification. Keep proved by-value public facades safe-callable rather than marking them unsafe merely because their implementation uses this primitive.

## 3. Leases and asynchronous operations

Synchronous borrowed input uses `scoped` `ReadOnlySpan<T>`/`Span<T>` and is consumed only during the call. If queued, copy before returning or admit an independent explicit buffer-range lease with a completion contract. Async/native operations acquire their own read/write access credit before acceptance and retain it until actual consumption ends, even if the caller disposes its lease. Managed reference-bearing data uses copied immutable snapshots or a separately specified managed owner, never native raw-byte storage.

Output snapshots are immutable copies, pinned immutable versions, or explicit owners disposed by the recipient, never live mutable collections. Descriptor inputs validate before allocation/admission and freeze for their lifetime. A consumer must not return pooled storage or reuse a mapped graphics processing unit (GPU) range while an active lease/fence needs it; owner disposal follows the retained-credit protocol. `Span`'s compiler restrictions are not a general borrow checker. Unsafe escape invalidates API safety guarantees.

Public ECS chunk access is synchronous `scoped` callbacks, not escaping native spans or public unrestricted `ref` getters. Managed pooled column storage keeps garbage collection (GC) memory safety; structural mutations remain forbidden until all callbacks/jobs have completed. Scoped callbacks cannot await/capture spans; copying values/entities is legal.

An operation's returned `Task` cannot become terminal while it still accesses retained storage. Canceling a separate `WaitAsync` observation may end that wait early, but the original operation/access lease remains live until actual completion. Observer cancellation never grants a writer permission to reuse bytes still being read by a native/GPU consumer.

Use `Task`/`Task<T>` for public async operations. Discretionary `ValueTask` use requires a measured frequent synchronous completion path with single-consumption semantics; standard protocol signatures such as `IAsyncDisposable.DisposeAsync` are exempt from that selection test. Repeated disposal invocation is idempotent under the owner's contract, not permission to await one returned ValueTask repeatedly. A caller requiring shared observation obtains and retains one Task representation. Do not demand callers infer reuse legality. Cancellation after upload submission cannot free staging bytes until GPU completion. Cancellation of waiting does not cancel an already accepted native operation.

Ordinary cancellable asynchronous methods place `CancellationToken cancellationToken = default` last. The synchronous `TryInvoke` keeps its required token before the required completion output; no ambiguous convenience overload is added. Accepted noncancelable native/audio work does not gain rollback cancellation merely to make signatures uniform. Value constructors continue requiring every validation input.

Engine-controlled completion sources use asynchronous continuations. Complete them outside owner/storage locks and after operation-scoped borrows, retained accesses and protected mutation have ended, on a permitted control thread, never from native or real-time callbacks. This applies to standalone services as well as hosting. Internal awaits avoid capturing an arbitrary caller synchronization context; an explicit owner dispatch is still required for owner work. `ConfigureAwait(false)` neither yields nor grants affinity, and awaiting an already-completed Task can continue inline. Completion-source options do not replace the admission/lifetime protocol.

### Async errors and admission

The following delivery channels are independent of whether a method body uses the `async` keyword. Validate owner/disposal state, then arguments and operation mode, then pre-cancellation, before reserving/admitting work; a more specific existing operation precedence is documented explicitly.

| Condition | Caller observation |
|---|---|
| Invalid argument/enum/range, wrong owner/thread, disposed receiver, or `NotRequested` audio command misuse | Synchronous conventional exception before retention or admission; an async wrapper must not accidentally defer this usage error |
| Pre-canceled ordinary cancellable Task operation after valid usage checks | Canceled Task, no admitted work; synchronous Try admission instead throws `OperationCanceledException` |
| Expected capacity/admission refusal | The operation's established Try false, dedicated receipt, or contextual faulted Task; non-Try host/audio queue-full remains a faulted Task, not a new synchronous failure |
| Initialization, I/O/native/device/solver or unexpected execution failure | Faulted Task after actual consumer cleanup; preserve the original exception and contextual diagnostic |
| Expected outcome after valid admission, such as stale-at-application, deadline, compositor denial or save rejection | The existing operation-specific status/receipt, never another Try false or success-shaped fallback |
| Cancellation after admission | The owner's established cancellation/commit boundary; Task becomes terminal only after actual consumption ends, or the committed receipt wins where already irrevocable |

Synchronous factories/operations retain their conventional throwing/Try contracts. Snapshot properties are cheap immutable observations with documented freshness, not hidden event drains, fresh histogram assembly or storage recycling beneath a retained result. Expensive snapshot work uses a named method.

Runtime Async does not change these signatures or public success/fault/cancellation contracts. Choose `Task M() => task` versus `async Task M() => await task` based on intended exception timing, lifetime/finally/disposal behavior, and diagnostic context; Runtime Async readily optimizes an await wrapper, which is not inherently wasteful. Do not remove or add wrappers mechanically or create engine-specific async abstractions. Qualify the chosen code generation in the optional lane in [Chapter 29](29-project-setup-build-and-deployment.md); dedicated owner/worker/render/audio scheduling, `ExecutionContext` behavior, and borrowed-context rules remain unchanged.

## 4. Native memory, handles, and disposal

Native pointers are private to interop/resource layers; narrow unsafe methods establish checked extent, alignment, pinning, owner/thread and callback lifetime before dereference. Never pin an ordinary managed array for an unspecified future GPU/audio operation. Use persistent native/`unmanaged` staging where required, or explicit `scoped` pins for synchronous native calls.

Author for Unsafe Evolution without requiring its preview mode: mark individual members unsafe when their caller must discharge an unsafety obligation, including contracts whose types alone do not express it; otherwise confine unsafe operations to `unsafe { ... }` inside the method body. Do not mark a whole class/file unsafe merely for convenience or treat a pointer declaration as a complete lifetime proof. Public safe facades continue establishing the full invariant internally. The optional `Features=updated-memory-safety-rules` lane audits propagation and generated bindings; it does not define a new signature family or a default preview dependency. `safe`/other preview-only syntax is not inserted into baseline C# 15 sources; [Chapter 29](29-project-setup-build-and-deployment.md) keeps that lane separately configured.

`SafeHandle` is a boundary-specific ownership tool, not a mandatory owner base or extra wrapper. Reuse it for independently owned operating system (OS)/native handles, framework interop that requires it, or boundaries needing its marshaling/critical-finalization protections. When native handle(s) and a managed owner form one lifetime unit and no distinct handle owner is needed, store the handles privately in that owner and implement direct release. Do not derive a public service/resource from `SafeHandle` or add a co-lifetime wrapper merely to obtain cleanup. A normal finalizer does not automatically reproduce `SafeHandle`'s critical-finalization or interop lifetime protections; the boundary review must identify and establish the protections actually required.

Native-owning disposable reference types implement deterministic `IDisposable` cleanup with a finalizer fallback for their unmanaged ownership. Sealed types share a private release core; a conventional private `Dispose(bool disposing)` may serve that purpose without adding protected/virtual disposal members. Host-owned facades use their existing host shutdown path, not new caller disposal authority. Initialize each native field to its API-defined invalid sentinel, unwind successful acquisitions on construction failure, and make the shared release gate safe for partially constructed instances, repeated disposal and disposal/finalizer races. Each acquired ownership reference releases at most once; successful cleanup releases all acquired ownership in dependency order. `GC.SuppressFinalize` follows completed release or an accepted ownership-retaining retirement transfer, not merely a timeout or canceled observation.

Acquire an active-use credit before reading a raw handle, atomically against closing admission. Every admitted native call, callback and asynchronous operation retains a strong managed owner reference through actual last use; an unrooted cycle beneath the owner is not proof of native retention. An admitted call sequence can reuse an existing owner/lease/job/recording credit; do not add redundant per-call wrappers or reference counts when that enclosing admission already protects the sequence. Use `GC.KeepAlive` where the call's GC liveness is not otherwise established, but do not mistake it for protection against concurrent `Dispose`. Credits, native callbacks, loader lifetimes and all applicable GPU/presentation fences gate physical release under the existing owner protocol.

Finalizers perform no engine-controlled waits/joins, blocking queue admission, user callbacks or disposal/traversal of other managed engine owners. They release only their own native ownership when the native API permits that thread and actual-use state; otherwise use an established nonblocking retirement handoff that preserves ownership. Thread-affine graphics objects and Component Object Model (COM) apartment-bound resources still obey their legal release context. If no legal handoff is available, retain/quarantine native ownership and report a leak through existing bounded diagnostics rather than reclaiming it unsafely. The finalizer path cannot throw; explicit cleanup failure remains caller/host-visible, and leak diagnostics do not constitute successful shutdown. Finalization never submits GPU commands or waits on the audio thread. It is a leak fallback, not guaranteed execution at process exit or a substitute for deterministic shutdown.

`Dispose` is idempotent and rejects further use; device resource disposal invalidates logical use immediately but physical release follows last-use fences. `EngineHost` implements only `IAsyncDisposable`, not `IDisposable`; it has no synchronous Dispose. `StopAsync`/`DisposeAsync` request orderly shutdown of its dedicated owner, and canceling a stop observation does not undo accepted shutdown. They never synchronously self-join; owner callbacks request shutdown and return rather than block on its completion. Ordinary resource `Dispose` may enqueue thread-affine retirement without blocking. No owner thread waits for a callback that needs that blocked owner.

Five-second configurable native wait budget emits timeout/fault and preserves still-live ownership. Cancellation/timeout cannot interrupt arbitrary blocked driver calls or guarantee physical release; never unload a DLL/callback or free storage while its thread/native user remains live. `Process` termination is the application's final remedy for an unresponsive driver, not a falsely successful `Dispose`.

## 5. Runtime and performance choices

ObjectPool.Dispose closes new admission under [05](05-owned-buffers-and-internal-collections.md#7-first-class-bounded-object-pools); outstanding Return and RetryCleanup remain legal until explicit drain. It does not force-return borrowers or claim native completion. This cleanup exception does not reopen ordinary use of a disposed native owner.

Native ahead-of-time compilation (`NativeAOT`) is the baseline for the runtime, editor and executable tools, not a reduced-feature alternative. Generated or explicitly typed registration supplies component storage, query adapters, codecs, factories, module entry points and editor metadata; build diagnostics reject missing registrations and unsupported generic instantiations. No core feature requires just-in-time (JIT) compilation, dynamic managed assembly loading, runtime code generation, expression compilation or reflection-only type activation. Necessary reflection is bounded over explicitly rooted known metadata, not a discovery mechanism or a blanket suppression of trimming/AOT warnings. Compiler-hosted source generators remain build-time tools rather than runtime dependencies. Optional JIT runs compare the same feature set and cannot replace AOT qualification. [26](26-csharp-systems-plugins-and-hot-reload.md) owns statically registered modules and managed-code rebuild/restart.

.NET 11 `Process` lifecycle/output and UTF-8/UTF-16 validation APIs are reused where appropriate. The buffer/I/O policy above applies equally to source adapters, codecs and executable tools. Native runtime data uses `EBIN1` and `EPKG2`; text serializers are authoring/migration tools. None/Brotli remain required codecs; BCL Zstandard availability does not silently add a wire codec.

New scalar code uses `float.Sin`, `float.Sqrt`, `float.Clamp`, `int.Clamp`, and other type-specific/generic-math members, rather than preferring `Math`/`MathF`. The supplied future repository determines build infrastructure and NUnit setup, not engine architecture.

Use allocation budgets and measurements rather than universal no-GC claims. Avoid per-entity boxing/LINQ/delegate allocation in steady-state hot loops; cached callbacks/pools are appropriate. Dedicated render/audio threads avoid `ThreadPool` blocking, but modern .NET is not a hard-real-time runtime. Intrinsics/single instruction, multiple data (SIMD) are optional measured internal accelerations with scalar reference behavior and explicit numerical profile; no public instruction set architecture (ISA)-shaped API.
