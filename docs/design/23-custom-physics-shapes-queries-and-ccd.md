## 1. Exact version-one geometry set

All public vector/quaternion/matrix fields, ray/cast inputs and copied witnesses use chapter [06](06-owned-geometry-and-numerics-interchange.md)'s `TerraFX.Numerics` family. Shape/pose/query validity remains this document's existing finite/geometric bounds, not raw type validity. The same copied component wire values are validated/cooked into private bounded binary32 geometry with certified/exact predicates; raw default quaternion never becomes an identity pose.

All shapes are immutable copied/cooked definitions, not mutable public vertex arrays. Convex input is already a boundary representation; arbitrary point-cloud hull generation or automatic convex decomposition is not a hidden runtime dependency. Offline tools may produce such input but must then pass these validators. Shapes have stable vertex/edge/face indices, local AABB, and enclosing radius. Body-local transforms contain only rotation/translation.

| Dimension / shape | Required fields and exact interpretation |
|---|---|
| 2D Circle | Radius; center is local zero, offset with collider `LocalPose` |
| 2D Box | `Vector2` `HalfExtents`; axis-aligned in its local frame |
| 2D `ConvexPolygon` | Integer vertex count in `[3, 16]`; `Vector2` vertices in CCW boundary order; no rounding radius |
| 2D `StaticSegmentMesh` | Copied vertices and indexed segment pairs; zero-thickness, two-sided *surface*, open chains or closed loops, not filled polygon interiors |
| 3D Sphere | Radius; center is local zero |
| 3D Box | `Vector3` `HalfExtents`; no hidden bevel |
| 3D `ConvexPolyhedron` | <= 64 vertices, <= 128 planar convex faces, <= 192 unique edges; oriented face index loops with outward normals |
| 3D `StaticTriangleMesh` | Copied vertices and indexed triangles; zero-thickness, two-sided surface, with welded adjacency and patch IDs; not a solid even when closed |

Mesh geometry may be attached only to static bodies, including sensors. Static mesh transforms can be explicitly teleported/replaced at a boundary, not animated as kinematic/deforming meshes. Dynamic/kinematic concave geometry must be an explicit compound of <= 16 supported convex colliders; overlapping compound colliders are intentional independent contact sources and their computed masses add, not Boolean-union mass.

Excluded: capsules, cylinders, cones, rounded boxes/polygons, heightfields, infinite planes, one-sided/one-way surfaces, collision with render tessellation, mesh-mesh response, dynamic/kinematic meshes, runtime shape deformation/scaling, soft bodies, cloth, fluid, particles-as-fluid, and automatic convex decomposition. A capsule-like approximation made from independent colliders is not called an exact capsule. Approximate import must identify its generated geometry; no unsupported shape is silently mapped to a box.

`ShapeDefinition2D`/3D uses engine-owned abstract base classes with private-protected constructors and sealed named definitions for this table, not C# closed/record/union syntax as a public contract. `CookShape` returns the dedicated sealed immutable `ShapeCookResponse2D`/3D with Status enum `Cooked`/`Rejected`. `Cooked` supplies a valid `ShapeHandle` and dimensional `ShapeStatistics2D/3D`, `Rejected` supplies `ShapeCookFault`; engine-controlled construction admits exactly the applicable payloads. Null/NaN/invalid enum and malformed application programming interface (API) arguments throw conventionally; invalid geometric content/budget is an expected named rejection. Unexpected allocation/invariant failure throws after cleanup, not a successful task/response with generic Error. Arrays/spans are copied before returning. Statistics include the selected spatial settings and nullable vertex/edge/face counts, scaled signed area/volume, local bounds, enclosing radius, connected components and nullable mesh-processing statistics under section 1.2; schema-version-owned behavior supplies validation, with no copied validator/formula identity.

### 1.1 Validation and asset cooking

Circle/sphere radii and box half-extents satisfy the bounds in [Chapter 22](22-custom-physics-world-and-solver.md). Polygon validation requires finite local coordinates, edges >= 0.01 m, no duplicate adjacent vertices within `GeometryTolerance`, no self-crossing edges, positive signed area >= 0.0025 m^2, every edge's inward half-space containing all other vertices within `GeometryTolerance`, and width across every edge normal >= 0.05 m. Collinear consecutive vertices with normalized turn <= `AxisTolerance` are rejected, not removed with unstated feature renumbering.

**M03 CPU primitive boundary:** the immutable circle/box 2D and sphere/box 3D definitions, dimensional bounds and pure validation/statistics are Physics-owned. The typed validators use `PrimitiveShapeGeometryContext2D/3D` and section 1.2's exact identity/measure contract, without a `PhysicsWorld`, process owner allocation or `ShapeHandle`; their copied fields and geometry rules are exactly those used by later world `CookShape`. M03 native collision assets may serialize and load these inert definitions and their computed statistics only after independent descriptor/fixture acceptance. `TerraFX.Assets` transports the typed payload but does not own a second shape definition or validation rule; offline cooking and Runtime `Integration` supply adapters through the allowed dependency direction. A request to bind a body or otherwise require authoritative physics refuses when the actual integration service is unavailable. Polygon/polyhedron/mesh cooking and every solver/handle-producing path retain their M06 ownership.

Polyhedron faces have an integer index count in `[3, 64]`, edges >= 0.01 m, no repeats/crossing boundary, planar vertices within `GeometryTolerance` and strictly convex turns. Face loops are clockwise as viewed from outside in the canonical left-handed (LH) world; normalized numerical `cross(v1 - v0, v2 - v0)` is their outward polar normal. Every undirected edge belongs to two oppositely oriented face edges; connected vertex stars/surface and Euler characteristic 2 are required. Every vertex lies behind every outward plane within `GeometryTolerance`. Signed volume >= 0.000125 m^3 and minimum face-normal width >= 0.05 m are required. `Near`-duplicate/inverted/zero-volume/non-manifold/concave inputs reject with indices; exactly coplanar split faces reject instead of adding arbitrary separating axis theorem (SAT) axes. 2D polygon CCW/positive-area rules above do not change.

Meshes have <= 262144 vertices and <= 262144 segments/triangles per asset, within the body-local 64 m radius. Indices and checked sizes validate before allocation; unused vertices are rejected. Segment lengths and triangle minimum altitudes are >= 0.01 m. Segment meshes have vertex degree <= 2 and no intersections except shared adjacent endpoints. Triangle meshes prohibit repeated triangles, triangles of zero area, non-manifold edges ( > 2 incident triangles), inconsistent adjacent winding, and self-intersections except shared topology. Open boundaries and multiple disjoint components are permitted; each vertex fan must be connected within its component. Validation uses the mesh BVH plus certified binary32/exact triangle/segment intersection predicates; budget 16777216 candidate primitive pairs per cook, exceeding it returns `CookBudgetExceeded` without an asset.

For a 3D sheet, numerical edge cross defines its oriented normal/clockwise front side in the LH basis; either globally coherent orientation is allowed because physics surfaces are two-sided and open sheets have no solid outside. `Query` normals still follow the query/relative-side rule, not render culling. An importer reflects right-handed (RH) coordinates and reverses triangle indices once; standalone LH definitions are already canonical and receive no automatic extra reflection.

Mesh welding is explicit `WeldMode.ExactPosition` default: identical binary32 vertex coordinates merge, with lowest input index retained. Optional finite `SnapTolerance` in `[0, GeometryTolerance]` is recorded in the asset, clusters by sorted vertex index against the cluster representative (not transitive drifting), then revalidates all geometry. Convex cooking never implicitly snaps vertices. A tolerance cannot rescue a degenerate triangle or reverse winding.

Adjacent mesh faces form a coplanar patch only if normal dot >= `1-1e-10` and vertices satisfy the same plane within `GeometryTolerance`. For such a patch, the cook projects vertices onto its first triangle's plane; maximum displacement must be <= `GeometryTolerance` and is recorded even with exact-position welding. Revalidate after projection. Bound a patch to <= 256 triangles; larger planar components split deterministically by BFS in triangle-index order and mark their connecting edges as coplanar continuations. Patch ID is the smallest triangle index in that patch; stable after a given cook. 2D collinear consecutive segments use the same plane/continuation principle.

These projections are the sole declared mesh geometry approximation. Normal smoothing across a real crease is excluded. Internal coplanar edges/vertices are not exposed surface edges; boundaries and noncoplanar creases are genuine features. `Input` errors never become a successful empty collider.

### 1.2 Inert primitive validation and statistics

`PrimitiveShapeGeometryContext2D/3D(SpatialSettings)` is immutable and geometry-only. `Default` uses `SpatialSettings.Default`; invalid/default settings reject conventionally. The context exposes settings, `MinimumPrimitiveExtent` and `MaximumLocalExtent`, not density, inertia, material, solver, frame-spacing or world admission. `PhysicsNumericalProfile2D/3D` keeps its complete internally constructed meaning under [22](22-custom-physics-world-and-solver.md). The owning `physics/primitive2` and `physics/primitive3` schema versions fix the dimensional admission and statistics behavior; records and public statistics carry no validator or formula identity.

Use public Core `SpatialMath.ConvertQuantity(1, 40, 0, e, 1)` and `ConvertQuantity(64, 1, 0, e, 1)` for the exact physical source literals at unit exponent `e`. The context publishes their nearest-even binary32 results. Admission compares against these **published converted limits**, not a second exact-SI cutoff or tolerance expansion. At kilometer exponent 3, exact minimum conversion publishes `0x37D1B717`, whereas conversion of already-rounded `0.025f` publishes `0x37D1B718`; the published exact-literal endpoint is admitted even though its physical value is slightly below unrounded 0.025 m.

Finite-only definition constructors copy every input bit, including signed zero. NaN/infinity throws `ArgumentException`; null definition/context throws `ArgumentNullException`. Finite negative/zero/undersized/oversized values produce `ShapeValidationStatus.Rejected`, not repair/clamp. First fault order is minimum radius/X/Y/Z, component maximum in that order, then exact box corner-radius rejection. With finite binary32 encoded as exact `N * 2^-149`, box admission requires every half-extent at least the published minimum and `sum(N(halfExtent)^2) <= N(MaximumLocalExtent)^2`. Circle/sphere radius lies within the two published limits. `None = 0` is the default non-result sentinel for validation status, fault code and field; validation emits only `Valid = 1` or `Rejected = 2`, and each rejection has a non-`None` fault code and field. `PrimitiveExtentBelowMinimum = 1` and `LocalExtentExceeded = 2` are the M03 `ShapeValidationFaultCode` values; corner faults report a finite outward-rounded observed radius. Responses are sealed and engine-constructed: `Valid` has statistics/no fault, `Rejected` has fault/no statistics, and both retain the context. Typed primitive overloads do not turn this context into a later polygon/mesh validator.

Each positive `ShapeMeasure` represents `Significand * 2^BinaryExponent`, with finite binary32 `1 <= Significand < 2`, 24-bit significant precision and exponent in `[-512, 512]`. Evaluate the complete exact formula over copied dyadics/rationals, determine the binary exponent, round the normalized significand once nearest-even, and renormalize a rounded two to one at the next exponent. Canonical zero/default has positive-zero significand and exponent zero. This domain value extends measure range without introducing a new coordinate family or arbitrary-precision public arithmetic.

The coefficient `pi32` is the exact dyadic value of binary32 bits `0x40490FDB`, not mathematical pi. The owning primitive schema versions fix this coefficient and these complete expressions:

| Primitive | Scaled measure formula | Vertex/edge/face counts | Components |
|---|---|---|---:|
| Circle | `pi32 * r^2` | null / null / null | 1 |
| Box 2D | `4 * hx * hy` | 4 / 4 / null | 1 |
| Sphere | `4 * pi32 * r^3 / 3` | null / null / null | 1 |
| Box 3D | `8 * hx * hy * hz` | 8 / 12 / 6 | 1 |

`ShapeStatistics2D.SignedArea` is engine-unit squared; `ShapeStatistics3D.SignedVolume` is engine-unit cubed. Bounds are copied local extents/negations in engine units; circle/sphere enclosing radius is copied radius. Box enclosing radius is the smallest binary32 value enclosing the exact radius, never an unconditional extra-ULP guard. Statistics retain the spatial settings used in the calculation, but no validator/formula ID or version. All three mesh-processing fields are null for primitives.

`ShapeMeasure.TryGetSingle` performs nearest-even conversion of the **stored pair**, not another evaluation of its original formula. It succeeds for finite normals/subnormals and exact positive zero. If a nonzero stored value rounds to zero or infinity, it returns false with default positive-zero output. Failure to materialize one float is not shape rejection; every geometrically valid primitive retains a positive scaled measure. Failure to produce the bounded representation is an implementation invariant exception, not a measure-representability content fault.

The independent unit-exponent-12 sphere witness has radius bits `0x28E12FB1` and stored volume `(significand bits 0x3FB67680, exponent -134)`. That pair is exactly halfway between subnormals `0x0000B676` and `0x0000B677`; `TryGetSingle` succeeds with the even lower encoding `0x0000B676`, while direct formula rounding produces `0x0000B677`. Preserve both rounding boundaries and independent expectations under [33](33-physics-acceptance-and-reference.md).

For M06, these same dimensional statistics types describe final indexed boundaries/topology. `FaceCount` means indexed 3D boundary facets and is null for every 2D shape. Triangle-mesh faces count triangles, not patches; edges include indexed internal adjacency even when not exposed as collision features. `WeldedVertexCount` is the final retained count when welding ran and equals final `VertexCount`, not a removed-vertex count. `PatchCount` counts resulting declared patches. `MaximumSnapDisplacement` records actual declared geometry adjustment, including patch projection; zero means applicable processing ran without displacement, null means inapplicable. Valid segment/triangle surfaces have canonical zero signed area/volume even when closed; empty/degenerate/inverted solid input still rejects, never absolute-value repairs or an empty successful collider.

For an admitted full Physics profile, M06's primitive `CookShape` invokes the fixed dimensional implementation selected by the owning primitive schema version and matching settings. Primitive rejection maps to `ShapeCookStatus.Rejected` with `ShapeCookFaultCode.PrimitiveValidationRejected` and the unchanged `ShapeValidationFault`, no handle/statistics. Success plus owner/storage admission maps to `Cooked` with a valid dimensional handle and the same statistics; a subsequent capacity refusal has its named cook fault and no published handle/statistics. Nonprimitive indexed faults and cook budgets remain M06. Mass/inertia uses robust geometry and admitted density under [22 section 6](22-custom-physics-world-and-solver.md#6-mass-integration-and-contact-solver), never the rounded measure or its optional single-float materialization.

Definitions and context settings carry no separate algorithm identity. Assets retain the selected `SpatialProfileId`/settings and complete foundation binding under [09-11](09-native-assets-and-source-adapters.md). The owning primitive schema version fixes validation and statistics formulas; the asset carries no duplicate validator identity. Revalidation under changed settings is reinterpretation. Explicit registered migration/re-cook converts copied geometric components through public Core conversion, recomputes statistics and rebuilds the affected package with its existing AssetIds and selected profile. Ordinary loading/`StrictLocal` performs no implicit rebind or formula upgrade; StrictLocal rejects a changed package digest.

## 2. Predicates and bounded distance algorithms

`Transform` both shapes into a pair-local frame by subtracting the midpoint of their centers of mass (COMs) in a bounded shared spatial frame with compensation retained. Normals are transformed by rotation, not scale; compute AABBs with outward-rounded binary32 extrema. Classification tolerance is `GeometryTolerance` = 1e-6 m. Public pose/point quantization at the operational edge can add <= 0.000244141 m per component; [33](33-physics-acceptance-and-reference.md) uses an appropriate observation tolerance separately.

For unit-axis projections, interval comparisons use `GeometryTolerance`. `Normalize` an edge cross-axis only if `|cross(eA,eB)|/(|eA| * |eB|) > AxisTolerance`; exactly/near-parallel cross axes are redundant, not a numeric failure. Squared lengths use squared length tolerances. For determinants/barycentric systems compare magnitude against `1e-12` times the product of column lengths; if singular, reduce to lower-dimensional edges/vertices. This is a relative predicate rule, not comparing a cubic determinant to a length.

`GeometryResult` is `Separated`, `Touching`, `Penetrating`, or `Indeterminate`, with signed separation, normalized A-to-B normal when defined, witness anchors, feature IDs, and test count. Separated separation is Euclidean surface distance when a distance query asks for it; SAT's largest separating projection is merely a separation certificate during collision rejection. Touching means absolute separation <= `GeometryTolerance`. Penetration separation is negative minimum translation depth for the selected feature model, not an assertion of a unique smooth signed-distance field.

| Pair / distance query | Bounded computation; overlap policy |
|---|---|
| Circle-circle / sphere-sphere | Center difference and radii; s = distance-`rA`-`rB`. Coincident centers: cached normal if compatible, else local/world +X, explicit `CoincidentCenters` diagnostic |
| Circle-polygon / sphere-polyhedron | Point-in-convex half-space test, then closest boundary point by segment / triangulated-face enumeration. Outside s = distance-radius; inside choose nearest exit face and s = `faceSignedDistance`-radius |
| Circle-segment / sphere-triangle | Closest point on segment / triangle using Voronoi-region barycentrics; s = distance-radius; a surface has no "interior" volume |
| Polygon-polygon / polygon-segment | SAT for overlap; if disjoint and distance requested, minimum of vertex-to-segment distances in both directions |
| Polyhedron-polyhedron / polyhedron-triangle | SAT for overlap; if disjoint and distance requested, enumerate vertices against triangulated faces in both directions and every edge-edge closest pair |
| Mesh versus convex | BVH candidates, apply the appropriate surface primitive algorithm, preserve subshape/patch keys; mesh-mesh simulation/shape casts unsupported |

Closest triangle routine projects into the face only for nonnegative barycentrics within tolerance; otherwise chooses closest of its three closed segments. Segment-segment routine solves two bounded parameters, clamps/re-solves after endpoint selection; parallel lines reduce to four endpoint-to-segment candidates. A degenerate intermediate feature reduces to its valid endpoints, although degenerate cooked input itself is refused. Witness ties within `GeometryTolerance` use `(FeatureA,FeatureB,TriangleIndex)` lexicographic order. Maximum feature tests are finite from the shape counts; no iterative GJK/EPA nonconvergence exists in this profile.

For a separated distance result, derive normal from `normalize(WitnessB-WitnessA)`, not the SAT projection axis. Count each axis generation/projection, feature-distance test, clipping plane/intersection and retry predicate against chapter [22](22-custom-physics-world-and-solver.md)'s tick budget or the query/cook budget. Exhaustion is `CapacityExceeded`/`QueryBudgetExceeded`/`CookBudgetExceeded` as appropriate, never geometric Miss.

Inside a sphere or polyhedron, each face has a center signed distance `di <= 0`; choose the largest `di` (nearest exit, with face index breaking ties). If the outward face normal is `f`, the A-to-B normal is `n = -f`, the sphere anchor is `center + n * radius`, and the hull anchor is `center - di * f`, so the signed anchor gap is `di - radius`. Use the same rule for a circle or polygon. If the center coincides with a mesh surface, use the last compatible contact-side normal; otherwise choose the surface normal opposing relative velocity, or the lexicographically positive normal at zero velocity. Report this tie policy; never invent a zero unit normal.

Distances to surfaces in a closed mesh are distances to its sheets. A point in a closed mesh's enclosed empty region is not "inside collider." Surface normals in query results face the query shape/ray according to the query rule, independent of input winding; winding exists to validate adjacency. No parity/solid-angle solid-fill inference in version one.

All comparisons/root solves must validate finite intermediates. If incompatible witnesses, empty output for a proven penetration, invalid normalization, or inconsistent predicates cannot be repaired by feature reduction and a second recentered computation, return `Indeterminate` with indices/operands. Simulation converts it to a tick fault; queries return `Indeterminate`, never Miss. The retry uses the same geometric meaning and no inflated hidden fallback shape.

## 3. SAT and manifold construction

### 3.1 Candidate axes and signed overlap

2D polygon axes are all normalized outward edge normals from both polygons; a segment contributes its perpendicular normal. 3D axes are all outward face normals of both polyhedra plus cross products of all edge pairs. A triangle contributes its plane normal and its three edges for the cross-axis tests. `Process` in stable face-then-edge-index order; redundant nonzero axes may remain. Optional deduplication removes only bitwise-equal canonical normalized axes, retaining first provenance; do not add an unbounded all-axis pairwise proximity pass. Include both interval directions, regardless of winding.

For axis a let interval extrema be Amin/Amax and Bmin/Bmax. Compute `sPlus = Bmin - Amax`, `sMinus = Amin - Bmax`; use the larger gap, with n = a or -a respectively. Select largest gap across axes (least penetration if all negative). Gap > `ContactMargin` rejects solver contact. This uses translation depth, not interval-intersection length, so contained convex shapes have meaningful escape depths. Selection ties within 1e-5 m prefer a supporting face normal, then A's face, B's face, then edge indices; retain exact separation even when choosing a tied face.

If SAT finds a positive gap within `ContactMargin`, compute closest physical features. Euclidean distance > `ContactMargin` rejects; otherwise produce one speculative closest-witness point with its witness-direction normal. Do not try face clipping on separated corner pairs and then fault because their face polygons do not intersect. `Zero`/negative-gap pairs use the overlap manifold construction below.

`IsSpeculative` means separation > `GeometryTolerance`, not merely that an event has not begun. Continuous collision detection (CCD) candidates may retain a geometric speculative witness for diagnostics/events, but [Chapter 22](22-custom-physics-world-and-solver.md) omits its speculative solver row until time of impact (TOI). This prevents early speculative stopping from suppressing a real restitution impact.

Mesh surface tests use these same *directional* depths; a zero-width triangle interval does not imply zero penetration when a convex volume straddles its plane. Normal side for an exact tie is the compatible cached side, then the side opposing relative COM velocity, then the positive canonical surface normal. Triangle-plane/segment-side selection is distinct from polygon/polyhedron solid containment.

### 3.2 Anchors, clipping, and persistence

Circle/sphere pairs produce one point. Closest-feature contacts use the two physical surface witnesses and the normal defined above. For a sphere near a corner do not replace the closest-feature normal with an arbitrary neighboring face normal.

For faceted pairs classify each shape's support set in the chosen n/-n direction within `GeometryTolerance`: face, edge, or vertex. If a support set is a face, use it as reference (A first on ties); its outward normal is n for A or -n for B. Choose the other shape's most antiparallel incident face, or its supported edge/vertex when no face supports the direction. A provenance face facing the wrong direction is not a valid reference; do not clip against its opposite plane by mistake.

Clip incident face polygon / edge against every reference-face side half-space using binary32 Sutherland-Hodgman with certified/exact side/intersection predicates; reference faces are convex. Classify signed side distances within `GeometryTolerance` as inside. Intersection parameter is `d0/(d0-d1)` only with nonzero denominator; nearly parallel edges keep their inside endpoint (s), never divide by epsilon. Maximum intermediate vertices is `incidentCount` + `referenceCount`, bounded at 128. For each retained incident point, project along the reference normal to the reference plane, producing paired physical anchors. Reject points with signed gap > `ContactMargin`.

Without a face reference, edge-edge contact uses closest points on the selected support edges, including clamped endpoints; vertex-edge/vertex-vertex uses the corresponding exact closest witnesses. If SAT penetration is certified but selected features do not yield consistent anchors, enumerate tied axes in provenance order and retry; if all fail, `Indeterminate`. Never return a successful empty manifold.

Deduplicate anchors closer than `GeometryTolerance` in both shapes. Feature IDs derive from nearest vertex within 1e-5 m, else nearest incident edge within 1e-5 m, else containing face; tie by lowest topology index. `ClipCode` is 0 Original, 1 `SideIntersection`, or 2 `ClosestWitness`; no process hash or floating-point coordinate hash is a persistent ID. If multiple candidates have the same complete key, retain deepest then lexicographically smallest local anchor.

Reduce to <= 2 2D / <= 4 3D points deterministically: keep deepest; keep farthest tangent-plane point from it; in 3D keep the point maximizing triangle area; then maximize minimum tangent-plane squared distance from retained points. Equal scores within squared `GeometryTolerance` tie by feature key. Sort retained points by feature key before solving. Reduction is the explicit contact-patch approximation; do not silently truncate manifolds/counts when a resource ceiling is exceeded.

Mesh contacts whose witnesses lie on coplanar internal edges/vertices use the patch's face plane/normal rather than treating that internal topology as a boundary. Clip against each candidate triangle/segment in that patch, merge/deduplicate candidate anchors, then reduce. Coplanar continuation patches touching the same convex collider merge before reduction with lowest `PatchId` retained. A query or contact across a real boundary/crease keeps closest edge/vertex features. This prevents a planar triangulation seam from becoming a fictitious collision ridge.

A collider pair can have up to 32 distinct normal patches (e.g. a body in a mesh corner); compatible normals have dot >= 0.9999 and plane offsets differ <= `GeometryTolerance`. Merge only compatible coplanar patches, not different floor/wall normals. Beyond 32 fails the tick/query explicitly. Cache keys contain collider handles, shape revisions, subshape/patch identity, and the `ContactFeatureKey` in [22](22-custom-physics-world-and-solver.md). Patch transitions cannot synthesize collider-pair End/`Begin` when the same touching episode persists.

## 4. Queries and public contracts

Queries synchronously read one locally committed immutable `PhysicsWorld` snapshot plus a pinned structural revision. They run on its caller/owner thread, outside solving and structural/rebase operations, without entity-component-system (ECS)/scene/scheduler dependencies. Result Tick/`FrameRevision`/`StructuralRevision` identify the local view. `Integration`'s resource access rules order its tick-local queries; only the encompassing stage 9 snapshot is externally world-committed. A physics-faulted service can query its last locally valid snapshot, never staging. Invalid/stale/wrong-physics-owner handles or frame revisions throw/refuse before traversal.

```csharp
public enum QueryStatus { Uninitialized, Complete, BufferTooSmall, Indeterminate, VisitorStopped }
public enum HitKind { Surface, InitialOverlap }
public enum HitNormalKind { Defined, UndefinedInside }
public enum RayInsidePolicy { ReportInitial, IgnoreInitial, Exit }
public enum SweepInsidePolicy { ReportInitial, IgnoreInitial }
public enum GeometryStatus { Separated, Touching, Penetrating, Indeterminate }
[Flags]
public enum QueryBodyTypes { None = 0, Static = 1, Kinematic = 2, Dynamic = 4, All = 7 }
```

The constrained `IReadOnlyRefFunc<PhysicsHit2D, bool>`/`IReadOnlyRefFunc<PhysicsHit3D, bool>` declarations are in [30](30-public-api-review-surface.md#8-standalone-physics).

`SpatialRay2`/`SpatialRay3` are ordinary named `readonly` structs with `SpatialPosition2`/`SpatialPosition3` Origin and `Vector2`/`Vector3` Direction and `float` `MaxDistance` properties and explicit validated constructors. `QueryResult` is an ordinary `readonly` domain struct with `QueryStatus` Status, `int` `RequiredCount`/`WrittenCount`, `long` Tick/`FrameRevision`/`StructuralRevision` and nullable `PhysicsQueryFault` Fault; construction enforces the status/payload/count invariants below. Its default is Uninitialized, never returned by a query and never interpreted as successful zero hits. No positional record/deconstruction API or generic Result/Option is required.

`QueryFilter2D/3D` is a frozen value: `CollisionFilter(category 1/mask all/group 0)`, `BodyTypes(QueryBodyTypes.All)`, `IncludeSensors(false)`, `IncludeSleeping(true)`, optional `IgnoreBody`, and `FrameRevision`. Unknown flag bits are invalid; `None` is a valid empty selection after input validation. `IncludeSleeping = false` excludes sleeping dynamics, not statics. Filtering obeys groups/masks in [Chapter 22](22-custom-physics-world-and-solver.md) against the query's filter; query geometry has no implicit body type. `IgnoreBody` is owner/generation checked. Query filters do not invoke user code.

`PhysicsHit2D/3D` contains `Body`, `Collider`, `BindingId(Guid.Empty = unbound)` from `Core`, `SubshapeIndex`, `PatchId`, `Feature`, `Kind`, `NormalKind`, `Point` (`SpatialPosition2` or `SpatialPosition3`), `Normal` (`Vector2` or `Vector3`), `Distance` (`float`, engine distance units), `Fraction` (`float`), `Separation` (`float`), `Tick`, `FrameRevision`, and `StructuralRevision`. `BindingId` is copied opaque body data; `Physics` performs no `Entity` lookup or enrichment. Ray/sweep `Normal` points from the hit collider toward the query, opposite the simulation's query-A-to-obstacle-B manifold normal; `Point` is the obstacle-side physical witness. Sweep `Distance` is `Fraction * length(Translation)`. `UndefinedInside` has a zero `Normal` *with the explicit flag*, not a purported unit normal. A valid surface `Normal` is unit length within `1e-5`; distance and fraction are finite. Initial-overlap `Point` is the query origin/shape origin and `Distance = Fraction = 0`; overlap witnesses come from overlap/distance, not fabricated ray surfaces.

Required dimensional world methods: `RayCast(SpatialRay2/3 ray, filter, insidePolicy, Span<PhysicsHit>) -> QueryResult` with an equivalent visitor overload; `Sweep(shape, BodyPose2D/3D pose, Vector Translation, filter, insidePolicy, Span<PhysicsHit>)` with a visitor overload; `Overlap(shape, BodyPose2D/3D pose, filter, Span<OverlapHit>)`; `OverlapPoint(SpatialPosition2/3 point, filter, Span<OverlapHit>)`; `QueryAabb(SpatialBounds2/3 bounds, filter, Span<ColliderHandle>)`; and `Distance(shapeA, BodyPose2D/3D poseA, shapeB, BodyPose2D/3D poseB, long frameRevision) -> ShapeDistanceResult`. Shapes are checked world-owned handles; sweeps/overlap accept only convex query shapes. `Distance` accepts convex-convex or convex-mesh, not mesh-mesh. AABB is explicitly coarse proxy-candidate output with an exact collider AABB test, not shape overlap.

`OverlapHit` contains Body/Collider/`Core` `BindingId`, `GeometryStatus`, Separation, `NormalKind`/Normal, immutable reduced Manifolds, Tick/`FrameRevision`/`StructuralRevision`. Optional `Entity`-enriched query wrappers belong to `TerraFX.Integration` and carry the raw hit plus a copied historical `Entity`; they add no assembly reference to `Physics`. `ShapeDistanceResult` is a named `readonly` domain struct with `bool` `IsInitialized`, `GeometryStatus` Status, `SignedDistance` (`float`, engine units), spatial `WitnessA`/B, `NormalKind`/Normal, `FeatureA`/B, `TestCount`, Tick/`FrameRevision`/`StructuralRevision` and nullable `PhysicsQueryFault` Fault. Returned values always have `IsInitialized` = true; Status/data access on the default uninitialized value throws `InvalidOperationException`. A known Separated/Touching/Penetrating result has all distance/witness fields and no Fault; `Indeterminate` has Fault and accessing distance/witness properties throws `InvalidOperationException` rather than fabricating zero. A point is query-only zero-radius geometry, not an admissible dynamic collider. An overlapped solid's point distance is negative nearest surface exit; surfaces use nonnegative distance. Circle/sphere smooth feature is Face/index 0; boxes use lexicographic local vertices, edges by endpoint pair, faces by outward axis (-X, +X,-Y, +Y[, -Z, +Z]).

`PhysicsQueryFault` contains Code (`QueryBudgetExceeded`/`IndeterminateGeometry`/`NumericOverflow`), Operation, Tick, `FrameRevision`, `StructuralRevision`, optional shape/collider handles, `TestCount`, Budget, offending feature indices, and Message. `Indeterminate` `QueryResult` has `RequiredCount` = `WrittenCount` = 0 and a non-`null` Fault; `Complete`/`BufferTooSmall`/`VisitorStopped` has `null` Fault. `Complete` has `WrittenCount = RequiredCount`; `VisitorStopped` has `RequiredCount >= 1` and `WrittenCount` in `[1, RequiredCount]`. The span overloads never return `VisitorStopped`. `Unsupported` shape-pair operations are explicit `NotSupportedException`, not an indeterminate numeric result.

Default query budgets are 262144 broad/triangle candidates, 65536 output hits, and 16777216 feature tests per call. Count after filter plus conservative BVH pruning. Exceeding a budget or geometric uncertainty returns `Indeterminate` with stable `QueryBudgetExceeded`/`IndeterminateGeometry` fault; no callback and no destination write. `Unsupported` operations are explicit `NotSupportedException` or named cook/queued failure, never Miss.

Compute/validate/sort the entire result before touching user output or calling visitors. Sort by `(Distance,ColliderHandle,SubshapeIndex,FeatureKey)`; equal distances within `GeometryTolerance` form groups sorted by handles/features (group against first distance, not a nontransitive comparator). Merge coincident surface hits within one mesh collider on a coplanar patch. `RayCast`/`Sweep` reports first entry per collider by default; Exit policy reports its first exit. Different colliders remain separate hits.

If destination capacity < `RequiredCount`, return `BufferTooSmall` with `WrittenCount = 0` and an unchanged destination; a retry sees the same snapshot only if its revision is still pinned. Otherwise write all results and return `Complete`. Visitor overloads are `RayCast<TVisitor>`/`Sweep<TVisitor>` with `scoped ref TVisitor` and `TVisitor : struct, IReadOnlyRefFunc<PhysicsHit2D/3D, bool>, allows ref struct`. `bool Invoke(scoped in PhysicsHit2D/3D hit)` returns true to continue and false to stop. The callable is never copied, boxed, retained or adapted to a delegate; its state updates remain caller-visible. A false result produces `VisitorStopped` with the full `RequiredCount` and `WrittenCount` including the current delivered hit, even if it was the last hit. An empty result is `Complete` without invocation. Visitor stop ends *delivery*, not geometric validation; no unrestricted references escape, only copied records. Visitor exceptions propagate, with no physics mutation; earlier delivered hits remain caller-observed and are not pretended rolled back. Reentrant query/mutation/step from a visitor is refused; enqueueing a copied future command is legal.

### 4.1 Ray definitions and algorithms

Direction must be finite nonzero and norm within 1e-5 of 1; normalize the accepted near-unit value with the scaled binary32 kernel. `MaxDistance` is finite in `[0, 8192]` m; spatial start/end must admit the requested bounded calculation neighborhood and required residency. Fraction is distance/`MaxDistance`, zero for zero-length initial hit; do not accept a non-unit direction and silently reinterpret `MaxDistance`. Boundary points are within `GeometryTolerance` of a surface.

`ReportInitial` returns `InitialOverlap` at 0 for a start inside/on a collider, `UndefinedInside` for strict solid interior, or the surface normal for on-surface. `IgnoreInitial` returns no hit for *that entire collider* if initially inside/on it; it is not `Exit`. `Exit` returns the first departing boundary of a containing convex solid; an on-surface ray pointing outward exits at 0, while one pointing inward seeks the far exit. A zero-distance ray can report only initial state, not a future exit. Static-mesh interior means on a surface only; enclosed space inside a closed mesh is not an initial overlap.

For mesh Exit with an on-surface start: a noncoplanar departure exits at 0; coplanar ray/segment/triangle intervals are unioned and the exit of the connected interval containing 0 is returned. Internal patch seams are not exits. A ray starting off all surfaces reports ordinary first surface entry even under Exit, because no containing sheet interval exists.

Circle/sphere: solve `a * t^2 + 2 * b * t + c = 0`, with a = `dot(d, d)`, b = `dot(o - center, d)`, c = |o-center|^2-r^2. Classify discriminant against `1e-12 * (b^2 + abs(a * c))`; tiny negative rounds to 0, more negative Miss. Stable roots use `q = -b - copySign(sqrt(discriminant),b)`, roots q/a and c/q; if q = 0 use the repeated root -b/a. Sort/filter within closed [0, `MaxDistance`] with `GeometryTolerance` endpoint allowance; clamp only that tolerance.

Box/polygon/polyhedron: clip the ray against all inward solid half-spaces, maintaining entry/exit distances and originating face IDs. Parallel plane if `abs(dot(normal, d))` <= `AxisTolerance`: outside plane Miss, otherwise imposes no interval. Use ray slab/half-space intervals, not thousands of individual triangle ray casts for a solid hull. Face/edge/vertex tie chooses lowest face index; outward normal is returned for the selected boundary.

Segment/triangle: solve ray-plane intersection, then finite segment/triangle containment; two-sided normal opposes ray direction, tangent tie uses canonical positive normal. Parallel noncoplanar is Miss. Coplanar ray is clipped against triangle edge half-spaces / segment interval and returns the first boundary entry, or initial on-surface state according to policy. A parallel coplanar ray is not `Indeterminate` merely because a conventional ray-triangle denominator is zero. Shared edge/vertex hits use inclusive barycentric tolerance then deduplicate at collider level.

### 4.2 Overlap and distance semantics

Overlap uses exact narrow phase with touch at separation <= GeometryTolerance, not ContactMargin or the event hysteresis thresholds. Point overlap tests convex half-spaces/radius or distance to a mesh surface. Overlap does not insert contacts/wake bodies/fire events. QueryAabb includes boundaries, rejects min > max/NaN, and returns sorted collider handles. `Distance` may use the feature-enumeration methods of section 2; witnesses/normal at an ambiguous coincident inside point have the explicit tie/`UndefinedInside` policy, not unbounded iterations.

## 5. Translational sweep algorithms

A sweep holds each shape's orientation fixed; it is not a rotational swept OBB. Translation is finite; spatial start/end bounds must admit a bounded common neighborhood and required residency. Crossing a cell seam is not an operational world-edge failure. `Query` sweep obstacles are fixed at the queried snapshot; live obstacle velocities do not enter a query. `Zero` translation is an overlap query expressed as an initial hit. No `Exit` sweep mode is promised. Initial-overlap handling is per collider as for rays, with `ReportInitial` requiring explicit `InitialOverlap`.

| Pair | Exact entry/exit computation for fixed orientations |
|---|---|
| Circle-circle / sphere-sphere | Ray the relative center against summed radii, using stable quadratic roots |
| Polygon-polygon/segment; polyhedron-polyhedron/triangle | Continuous SAT: intersect swept interval-overlap times for the complete fixed axis set |
| Circle versus polygon/segment | Ray center against radius-offset edge strips and vertex circles, with finite feature checks |
| Sphere versus polyhedron/triangle | Ray center against radius-offset face planes, finite edge cylinders, and vertex spheres, with finite feature checks |
| Reverse sphere/circle versus faceted pair | Swap A/B, use opposite relative translation, then swap witnesses/normal back |
| Convex versus mesh | Swept AABB/BVH candidates, then primitive sweeps; first valid hit per collider |

For continuous SAT axis n, intervals overlap when `Bmin - Amax + dot(vRel,n) * t <= 0` and `Bmax - Amin + dot(vRel,n) * t >= 0`. Clip both linear inequalities into [0, duration]; a zero slope either permits all or certifies Miss. Keep maximum entry and minimum exit across axes; entry > exit by > `TimeTolerance` is Miss. `TimeTolerance` = 1e-7 seconds in simulation; query normalized fraction tolerance = 1e-10. Within a conflicting time band, recentered recomputation and closest features must certify separation or touching within `GeometryTolerance`, otherwise `Indeterminate`. `TimeTolerance` is not permission to inflate geometry or advance beyond the interval. Retain axis/feature causing latest entry, face-priority ties as in SAT. Inclusive tangent entry is Hit, not penetration.

Sphere versus facet feature enumeration is a cast against its exact Minkowski radius expansion: face roots satisfy signed center-plane distance = radius on outward solid faces (both orientations for a triangle); projected contact point must lie in that finite face. For an edge from `a` to `b`, remove components parallel to the unit edge from center offset and velocity, solve the radius-cylinder quadratic, then require the edge parameter in the closed interval `[0, length]`. Vertex roots ray against its sphere. Circle uses offset edge lines/finite projection and endpoint circles.

Validate each candidate root by closest-point/point-in-solid evaluation and the relevant Voronoi feature; discard roots outside that feature's region or with separation > `GeometryTolerance`. Select earliest entering/tangent root in the closed interval. Solid containment at start is `InitialOverlap`; a face/edge equation root inside another inflated feature is not an entry. If all candidates reject and start is disjoint, Miss is certified by complete feature enumeration. No maximum-iteration heuristic substitutes for checking all required features.

For moving faceted A against a sphere B, relative-center ray is transformed consistently into A's fixed frame. Motion fraction interpolates A's actual world pose; output Point/Normal are physical witnesses at that fraction, not witnesses at query-end pose. Mesh hits respect patch merging, crease/boundary features, and two-sided surfaces; queries report collision with a thin surface even though it has no solid interior.

## 6. Simulation CCD: bounded TOI segmentation

`MotionMode.ContinuousLinear` is dynamic-only. Its collision geometry must be orientation-invariant (one centered circle/sphere and no other colliders, with local COM at that center), or the body must be `RotationLocked`. Offset sphere compounds are *not* orientation-invariant. CCD uses actual collider geometry, with no bounding-sphere collision fallback.

For a filtered non-sensor pair with either endpoint `ContinuousLinear`, every non-static endpoint must guarantee fixed geometry orientation during this microstep: a `RotationLocked` dynamic body, a centered single-circle/sphere dynamic body, or a kinematic target with unchanged rotation. A static rigid pose is fixed. A broad swept-bound candidate with a rotating faceted/offset-compound endpoint returns `UnsupportedRotatingCcdPair` *before positional integration*. Refusal is conservative even if exact geometry might miss; it identifies both handles and the unsupported rotation. Static meshes are supported. Continuous sensors are excluded: trigger detection is discrete at temporal boundaries and can miss an entire intervening traversal; report this limitation, not a false continuous-trigger guarantee.

Ordinary Discrete bodies may rotate and may tunnel if their discrete/speculative contacts miss; that is the declared mode, not universal CCD. `RotationLocked` geometry sweeps and centered spheres cover common projectiles, translational crates, and kinematic platforms. Full rotational CCD, deforming-mesh CCD, and continuous trigger enter/exit are separate future scope, not partially implemented promises.

For each fixed microstep h:

1. Apply force/damping once for h, collect current contacts, solve velocity/joints using remaining duration h. Validate all provisional motion bounds and CCD-pair orientation restrictions.
2. Predict endpoints from current staged pose and constant solved velocities for the remaining duration. Rebuild conservative swept candidates; use section 5 with `vRel = vB - vA` for all eligible CCD pairs. Choose globally earliest TOI; near-time ties order by pair key, and solve together only pairs actually touching within `GeometryTolerance` at that earliest pose.
3. If no TOI, integrate every awake dynamic/kinematic for the full remaining duration. Otherwise advance every awake body to TOI (non-CCD rotations still use their exponential integration), recompute contacts, solve impact velocities/joints, and continue with the remaining duration. Do not reapply gravity, damping, force or warm-start impulses already applied in this segment.
4. After the remaining interval is consumed, run position iterations and final contact/event sampling; then proceed to the next microstep. All segments belong to one outer transaction and one fixed dt.

Kinematic prescribed velocity remains based on outer target, so temporal splitting cannot change its final target pose. Dynamic velocities may change at impacts; recompute later sweeps, not reuse obsolete predicted endpoints. A new impulse can activate a previously unconsidered pair; rebuild bounds/revalidate rotation restrictions. All CCD impact contacts use true pre-impact velocity for restitution; no speculative bounce.

Initial overlap/touch requires a separate safety certificate. If initial penetration exceeds `LinearSlop` + `GeometryTolerance`, fault `CcdInitialOverlap`; teleport deeply inside a wall does not fabricate a TOI. For each initially overlapping/touching eligible pair, solve contacts and find a valid supporting normal/anchors with signed gap s >= -`LinearSlop`-`GeometryTolerance`. Under fixed orientation, its support-plane gap is `s + dot(vB - vA,n) * t` (centered spheres have constant radii). Require this lower bound >= `-LinearSlop-GeometryTolerance` over the remaining interval. If satisfied, that pair may be omitted from entry searching in this straight segment: it cannot cross that support barrier. If not satisfied after the fixed solver iterations, fault `CcdInitialOverlap` with the residual; never just ignore a zero-time hit.

For a new touching TOI use the same certificate on the next segment; a normal impulse usually makes closing speed nonnegative. A zero-time newly encountered hit may solve once; repeated zero-time hit without a valid support certificate faults `CcdBudgetExceeded`. A TOI increment below `TimeTolerance` is not silently rounded up into penetrating motion. Ordinary joint velocity changes are included in the certificate; joint edits cannot bypass it.

`Position` correction is also motion, though it consumes no simulation time. Before each position row applies proposed COM/orientation changes, rebuild correction-swept candidates for every pair with a CCD endpoint. Validate orientation eligibility again, then cast simultaneous translations over normalized interval[0,1]. A new barrier before fraction 1, or an existing support gap becoming < -`LinearSlop`-`GeometryTolerance`, faults `CcdPositionCorrection` and discards the entire staged physics step. This local guarantee does not undo earlier ECS/world stages. Touching at fraction 1 is allowed. No unchecked correction, discarded remainder or silent pose clamp is used; ordinary non-CCD corrections retain discrete semantics. Count corrective casts against geometry/mesh budgets, not temporal impact batches. `Teleport`/rebase are explicit boundary operations, not certified continuous motion.

The CCD guarantee is conditional and measurable: for eligible fixed-orientation, finite geometry and admitted counts, either a complete tick prevents crossing a support barrier deeper than `LinearSlop` + `GeometryTolerance`, or the tick faults without publishing motion. It does not promise exact continuous rigid-body dynamics, free remainder motion after an unprocessed impact, rotation coverage, or perfect event timing for discrete sensors.

## 7. Failure and implementation obligations

Test the production feature, broad-phase, and sweep paths with explicit analytic counterexamples, selected supported-pair/feature cases, and directly specified expected candidate pairs. Do not maintain a second geometry engine, brute-force pair enumerator, or sweep solver as a test oracle. The table-driven public cases in [Chapter 33](33-physics-acceptance-and-reference.md) include supported misses, inside, coplanar, containment, initial CCD penetration, rotating refusal, maximum counts, rebase, and transaction rollback. A failure cannot be softened to a bounding-shape result or a "best available normal" without an explicit specification revision and affected acceptance review.

Record signed witnesses, selected SAT axis/provenance, clipped candidates, discarded roots/reasons, capacities, TOI certificates and solver residuals in optional diagnostic traces. Diagnostic geometry is immutable and outside solver callbacks. Do not require traces for correctness, allocate an unbounded trace in the hot path, or claim external reference-engine agreement proves this different numerical profile is identical.
