# Complete first 2D/3D renderer

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Draw extraction and portable semantics

Public `Renderer.Extract(World, RenderExtractionOptions2D/3D)` runs on the world owner at an idle committed boundary, with no staged tick or borrowed job, and only while the current canonical mutation revision equals the committed/restored marker. Any canonical write after that marker—including idle component/attachment writes, structural or scene commits, authoritative system/control state, asset activation, or replay-relevant frame/time-scale changes—makes extraction ineligible until the next successful tick publishes that exact revision; a validated restore may publish a coherent restored marker without a tick. Previously returned immutable snapshots remain valid and do not authorize re-extraction from subsequently changed storage. Options name the exact current dimensional frame, positive physical target extent and 1 through 16 unique nonempty camera GUIDs from that world. Validate owner/profile/settings/revision and cameras before copying. Extraction acquires one `FrameReadLease` over the current lower boundary/cohort record, then reads frame, camera and CPU actor roots from that same generation; independent getters cannot be combined into a mixed frame/cache snapshot. `Extracted` returns an immutable owned `RenderSnapshot2D/3D`; `CapacityExceeded` returns no partial snapshot and a typed `RenderExtractionLimitDiagnostic` with exact `Requested`/`Limit` and draw/light/bone kind. Invalid or stale input throws, rather than silently changing the requested camera/frame.

The extraction service is initialized even for `Headless`: logical data and CPU asset pins can be validated without native output. Native graph construction/submission still requires a real device. A snapshot records its unique identity, world/tick, ordered camera selection, target extent and complete dimensional frame; consumers never use live ECS storage on the render thread.

`RenderSnapshot` carries `TickIndex`, spatial profile/frame descriptor/revision, cameras, stable draw IDs, current/previous transforms, mesh/sprite/material versions, bone palettes, lights, user interface (UI) primitives and explicit discontinuities. Copy/pin during extraction, never traverse live entity-component-system (ECS) on render thread. Defaults limit 131072 draw instances, 16 cameras, 256 lights/scene, and 2048 bones/frame; overflow fails extraction with exact requested/limit, not invisible disappearance.

Per camera cull by declared layer mask then world bounds against clip planes (`-w <= x,y <= w`, `0 <= z <= w`, w > 0); infinite far omits far plane. Conservative transformed bounds include animation extrema; unknown bounds are diagnosed and conservatively drawn, never assumed empty. Stable instance sort and batching cannot change transparency/UI order.

Canonical triangle front face is clockwise in the camera's projected +Y-up plane before viewport; cooked 3D outward face loops follow the same clockwise-outside convention. With chapter [03](03-shared-conventions-and-clocks.md)'s screen mapping use D3D12 `FrontCounterClockwise` = false and Vulkan negative-height viewport with `VK_FRONT_FACE_CLOCKWISE`. Vulkan's specified area is NEGATIVE one-half of framebuffer shoelace: a source-negative XY triangle becomes framebuffer-positive shoelace and negative Vulkan area/front CLOCKWISE. Example normalized device coordinates (NDC) `(0,1),(1,-1),(-1,-1)` maps to pixels `(410,20),(810,620),(10,620)` at viewport (10,20,800,600), shoelace sum 480000/Vulkan area-240000. Reverse indices and both signs reverse. Negative world-transform determinant flips pipeline front-face parity once, not vertex buffers; importer reflection/reversed indices already belong to cooked canonical geometry and add no permanent extra parity flip. Double-sided materials disable culling and flip shading normal by facing. Native asymmetric-triangle tests verify both application programming interfaces (APIs).

Normals use inverse transpose of linear world transform and renormalization. Singular transforms were rejected on authoring; tangent W stores handedness, multiplied by transform parity. Clip/bone matrices/layout follow [18](18-shaders-and-material-pipeline.md); no backend-specific art assets.

#### M03 7.3 Real headless extraction and minimal public amendments

Add `Renderer.CreateHeadless()` to the existing Renderer type, returning the same CPU extraction implementation with no device, window, backend or thread activation. Do not replace it with CameraSnapshots or a mock renderer. A host later constructs the same service with its real selected device.

After a successful standalone Step, the returned `WorldStepReceipt.Publication` exposes the actual `WorldGuid`, `Frame3` and optional `Frame2` for that committed generation; receipt aliases equal those publication values and are not resampled from later World reads. A public caller never guesses or needs the private OwnerId. After restore, read `WorldGuid`, `CurrentFrame3` and optional `CurrentFrame2` from the actual replacement World only after its restored marker is installed. Restore does not synthesize a Step publication, delivery report or callback. An initial World frame is owner-issued revision1 with canonical zero origin and admitted explicit extent; default extent is physical +/-4096 m converted once under settings, both dimensions. No decoder frame default.

Extraction validates committed/restored revision, owner/frame/settings, positive physical target and 1..16 unique actual camera IDs. Order cameras by signed Order then RFC ID. Finite camera FOV is (0,pi32), orthographic height/aspect positive; perspective near positive; finite far>near. Far present iff Finite; Orthographic Infinite invalid. Viewport is `(x,y,width,height)`: x/y>=0, width/height>0 and exact copied-dyadic x+width/y+height<=1. Camera/ancestor scales positive; rigid view excludes inherited scale. No assignment renormalization on load/restore.

Preflight full eligible logical counts before allocating/pinning output: sprite=one draw, mesh=one draw per admitted group, unique lights regardless of whether a selected material is unlit, bone palette entries per skinned instance. Filter declared camera layers but do not evade ceilings by culling, batching or ignoring unlit lights. Candidate count is unique across selected cameras, not multiplied by camera count. If multiple limits fail, report DrawInstances then Lights then BonePaletteEntries with exact full Requested/Limit. No partial snapshot/pins on refusal.

Stable draw identity uses NameUuid with namespace=entity persistent ID and names `sprite/0` or `mesh-group/` plus eight-digit lowercase hexadecimal group index. Light identity uses that same Entity namespace and `light/` plus the component schema's RFC lowercase-N. Preserve sprite order `(cameraOrder,sortingLayer,sortingOrder,-cameraViewZ,stableDrawId)`; mesh transparent sorting/adjacent batching follows chapter 21. A snapshot copies camera/frame/current pose/static palette/light records and retains the package-backed asset leases it needs; missing previous history is an explicit discontinuity, not a fabricated previous pose.

M03 does not claim particles/UI/native passes/animated palettes. Default ceilings remain 131072 draws, 256 lights and 2048 bones. `BuildGraph`/`SubmitAsync` on this headless service fail with InvalidOperationException before native admission. Record M03 guard-precedence tests separately from M04/M05 tests with actual valid native target producers; do not describe null/default-target guard tests as native-output qualification.

## 2. 2D sprites, tiles, and pixels

### Approachable built-in path

The API-family influence includes XNA/MonoGame and its modern DirectXTK12 SpriteBatch, Model and common-state helpers, not only historical XNA. Preserve their discoverable ordinary workflows through TerraFX's existing typed host/assets/scene components and Renderer; do not create a duplicate SpriteBatch/Model owner hierarchy or expose native helper classes. A first sprite supplies atlas/frame, explicit identity pose and camera; a first model supplies cooked mesh/material/skin records. Existing renderer defaults choose blend/depth/sampler behavior and allow supported typed material overrides.

Both follow load/pin CPU asset, request GPU residency, commit scene/component setup, Extract, BuildGraph, Compile, SubmitAsync, then observe submission/presentation completion. Applications need no descriptor heap, allocator or backend queue for this path. Sprite ordering/adjacent-only batching and model material/skin/version rules below remain authoritative; Draw/End convenience cannot traverse live ECS or imply GPU completion. Required complete external-consumer samples exercise first sprite, imported model, input and offscreen/headless variants, including their failure diagnostics.

Sprite fields atlas/frame `Guid`, pivot normalized (default 0.5,0.5), size meters (default 1,1), tint linear RGBA(default white), flip axes, sorting layer/order, optional material and `pixelSnap`. UV rectangle has texel-safe padding/extruded border from importer; flipped sprites reverse UVs, not canonical winding. Sprite blend defaults premultiplied alpha, depth test optional, no depth write for blended sprites.

The default XY quad has local normal -Z, facing the identity +Z-looking camera placed behind it. For pivot `(px, py)` and size `(w, h)`, vertices 0, 1, 2, and 3 are `(-px * w,-py * h),(-px * w,(1 - py) * h),((1 - px) * w,(1 - py) * h),((1 - px) * w,-py * h)` at `localZ = 0`; indices `(0,1,2),(0,2,3)` are clockwise. UV top-left maps to vertex 1; bottom-left to 0, top-right to 2, and bottom-right to 3. `Physics` polygon CCW boundary order remains a separate mass/shape contract.

Draw order `(cameraOrder,sortingLayer,sortingOrder,-cameraViewZ,stableDrawId)` ascending: within equal layer/order, larger positive `viewZ` is farther away and draws first; higher sorting order renders later. `CameraViewZ` is transformed sprite-pivot Z in that camera's view, not global `worldZ`; stable IDs break equal-depth ties. Material batching only adjacent compatible draws. Pixel-art mode nearest sampling/orthographic integer output scale with letterboxing; `pixelSnap` affects screen vertices only, never physics/world coordinates. Fractional scale is explicit, not a pixel-perfect claim.

`TileLayer` stores chunk coordinate/map dimensions, cell size/origin, palette/atlas IDs, per-cell tile/transform/order. Chunks32x32 default; dirty cells rebuild affected chunk geometry before boundary publish; collision derived separately through physics asset builder, not one rigid body per visual tile by default. Sparse chunk culling, no entire map rebuild for one tile. Tile IDs outside palette fail import; empty tile ID 0 distinct from missing asset.

2D lit sprites are an optional material choice in core: an authored normal map plus shared point/directional lights, using the same linear color conventions; no implicit 3D collider is created from a sprite silhouette. Nine-slice UI is defined in [Chapter 25](25-ui-text-and-editor-tools.md).

## 3. 3D mesh/material/light

Meshes: indexed triangle lists, position/normal/tangent/UV0/UV1/color and optional four skin weights/joints; submesh material slot, per-level of detail (LOD) screen-size threshold, bounds. Uint16/Uint32 indices validated, triangle count divisible 3. LOD switches by projected bounding diameter/viewport height with 10% hysteresis, thresholds decreasing; no changing topology in physics. Default no LOD unless authored.

Material core metallic-roughness: `baseColorFactor` is linear RGBA; `baseColorTexture` is sRGB; metallic lies in `[0, 1]` (default 0), roughness in `[0.045, 1]` (default 1), and tangent-normal scale in `[0, 2]`. Packed metallic B/roughness G/occlusion R is linear; `emissiveFactor` is linear and nonnegative, and `emissiveTexture` is sRGB. Alpha mode is Opaque/Mask/Blend, cutoff is 0.5, and `doubleSided = false`. Alpha-mask cutoff uses sampled linear alpha; blending uses premultiplied source Over, with transparency sorted by back-to-front camera-space distance then `stableID`; the approximation is documented and does not claim order-independent transparency.

The bidirectional reflectance distribution function (BRDF) uses Cook-Torrance with the GGX/Trowbridge-Reitz microfacet distribution. Let `N` be the unit surface normal, `L` the unit direction toward the light, and `V` the unit direction toward the viewer. Define `nDotL = clamp(dot(N, L), 0, 1)` and `nDotV = clamp(dot(N, V), 0, 1)`; if either is zero, this light's contribution is zero. Otherwise define the unit halfway direction `H = normalize(L + V)`, with similarly clamped `nDotH` and `vDotH`.

The material terms are `alpha = roughness^2`, `D = alpha^2 / (pi * (nDotH^2 * (alpha^2 - 1) + 1)^2)`, and Schlick Fresnel `F = F0 + (1 - F0) * (1 - vDotH)^5`, where `F0 = lerp(0.04, baseColor, metallic)` componentwise. Smith correlated visibility is `visibility = 0.5 / max(nDotL * sqrt(nDotV^2 * (1 - alpha^2) + alpha^2) + nDotV * sqrt(nDotL^2 * (1 - alpha^2) + alpha^2), 1e-5)`. The outputs are `specular = D * F * visibility` and `diffuse = (1 - metallic) * (1 - F) * baseColor / pi`; incoming radiance multiplies `(specular + diffuse) * nDotL`. Preserve high dynamic range (HDR) radiance before tone mapping. Numerical references require nonnegative and roughness-extreme guards, not an exact photometric-realism claim.

Directional lights Color linear, Illuminance lux (default 10000), direction normalized. Point/spot flux lumens (default 1000), range meters > 0, spot inner/outer half angles 0 < inner <= outer < pi/2. Intensity point = flux/(4pi); attenuation = `1/max(r^2,0.01^2)` multiplied by smooth range factor `(max(0,1-(r/range)^4))^2`; spotlight additionally smooth cosine interpolation inner/outer, equal angles hard cutoff. Range/exposure are authored, not silently inferred from arbitrary brightness.

Forward renderer loops over bounded active lights per camera; clustered/bindless rendering is not required. Version-one ambient is authored constant linear irradiance (default 0.03 per channel), with contribution `irradiance * baseColor * (1 - metallic) * occlusion / pi`; there is no ambient specular approximation. An optional authored linear cube texture is an unlit sky only, sampled by world-space view direction using the face order in [Chapter 17](17-graphics-device-and-resources.md). Its absence selects an explicit clear color, not a failed-load substitute. Image-based lighting, irradiance convolution, roughness prefiltering, and BRDF lookup-table (LUT) generation are excluded from 0.1, not unspecified optional cook algorithms.

## 4. Shadows and frame passes

First core shadow budget: one directional light with 4 cascades, at most 4 spot lights; point-light cube shadows unsupported and reported at material/light validation. Atlas 4096 square D32, cascade resolution 1024 and spot slots 1024; stable `lightID` selection requires explicit priority. More shadow requests produce `ShadowBudgetExceeded` warning plus observable unshadowed state, not unreported omission.

The atlas uses sixteen 1024-square cells in row-major order. Cascades 0 through 3 occupy cells 0 through 3; selected spots, sorted by descending priority and then `stableID`, occupy cells 4 through 7. Remaining cells are reserved, not unspecified dynamic packing. Each view/scissor clamps percentage-closer filtering (PCF) taps to its own tile to prevent adjacent shadow bleed.

Main-camera shadow slices start at `Near` and end at `min(ShadowDistance, finite camera Far)`, or at `ShadowDistance` for infinite perspective. The default `ShadowDistance = 100 m` is finite and positive. Require `end > Near` before allocating views; otherwise report `ShadowRangeInvalid` rather than evaluating or clamping an empty range. For a perspective camera with `Near > 0`, compute each practical split for the integer split index `i` in `{1, 2, 3, 4}` as `lambda * near * (end / near)^(i / 4) + (1 - lambda) * (near + (end - near) * i / 4)`, with `lambda = 0.5`. Orthographic slices are linear: `near + (end - near) * i / 4`; native `Near = 0` or a negative value is valid and never enters a logarithm or division by `near`. Split 0 is `near` and split 4 is `end`, with finite, strictly ordered boundaries.

Fit each slice's eight world corners in a light-view basis; choose cardinal up least parallel to normalized light direction, ties X/Y/Z. Square XY extent is the larger span, with one-texel border and center snapped to extent/1024 world units. Extend caster bounds 10 m toward light; admit only overlapping casters. Directional shadow projection is orthographic in light space: fitted finite signed `Near`/`Far` are ordered and distinct, not required to equal/be as positive as main-camera clipping planes. Spot shadow projection is perspective with positive `Near`/ordered `Far`. Validate derived view/projection entries/extents before submission. Reversed-Z depth/bias below applies to both projection kinds without changing signs.

Reversed-Z shadow compare is `GreaterEqual`: a tap is lit when its receiver reference is at least the stored caster depth. Receiver depth bias is `clamp(ConstantDepthBias + SlopeScale * max(abs(ddx (depth)), abs(ddy (depth))), 0, MaxDepthBias)`, defaults 0.001/1.0/0.05, with constant/max in normalized depth units. Evaluate depth derivatives before divergent cascade/sample branches; add this nonnegative bias, so sample reference = `receiverDepth` + `receiverBias`. Larger reversed-Z depth moves the comparison toward the light and relaxes self-shadowing; subtraction would make it worse. No additional unspecified normal-offset/hardware bias is enabled. The 3 x 3 equal-weight PCF kernel uses the Cartesian product of texel offsets `{-1, 0, +1}` on each axis, clamped to the selected cell; outside light clip volume is lit. Finite bias values satisfy `ConstantDepthBias` in `[0, 0.05]`, `SlopeScale` in `[0, 4]`, and `MaxDepthBias` in `[ConstantDepthBias, 0.1]`. These are tuned defaults, not guarantees against acne/peter-panning.

Pass order: upload admitted resources; shadow depth; opaque/masked 3D color + depth; unlit/opaque world 2D if configured; sky/environment where depth == 0; sorted transparent3D; ordered blended2D; post-tone-map compositing; UI; final standard dynamic range (SDR) encoding/output. Camera clear/order specifies composition; secondary cameras may target named textures with graph dependencies; recursive camera texture cycles fail.

HDR working target RGBA16Float and D32 depth, sample 1; exposure multiplier default 1, Reinhard tone map `c / (1 + c)` for nonnegative radiance; linear SDR UI over tone-mapped linear color; hardware/shader sRGB encoding exactly once. Version one has no multisample anti-aliasing (MSAA)/FXAA/TAA/bloom/motion blur; these require a later separately specified feature, not an unspecified optional preset. Pixel-art has no antialiasing by default.

## 5. Particles and extension

Central processing unit (CPU) particles core: bounded pooled emitters, maximum 131072 particles total, fixed-tick spawn/integration with recorded engine RNG stream; billboard sprites/materials, lifespan/position/velocity/color/size curves. Capacity overrun has declared `RejectSpawn` result and counter; effects do not change authoritative physics. Deterministic particle output only if admitted to state profile; otherwise cosmetic excluded hash.

`Renderer.BuildGraph` accepts the snapshot and either its matching interactive `Surface` or real offscreen color `GpuTexture`. Applications may extend that graph through typed imports/transients, range-scoped resource versions and `AddRasterPass`/`AddComputePass`/`AddCopyPass`, then `Compile` and `SubmitAsync`. A custom recorder binds an owned pipeline's handle with `SetPipeline` and declared bindings only. The final `PresentationSource` is linear SDR after the single tone-map/UI stage; terminal output performs only format/output encoding. Snapshot/resource/pipeline pins survive actual GPU completion; an interactive presentation wait is separately fenced. Full members, statuses and target-specific receipts are in [30](30-public-api-review-surface.md).

Custom render passes register typed access/binding/reflection, execute only `scoped` render-thread callbacks against immutable data, obey graph validation. Feature requests for ray tracing/mesh shaders/HDR/bindless return `UnsupportedEngineFeature` in 0.1 even if hardware supports them; absence never disables core rendering. API evolution must add full lifetime/pipeline/acceptance contracts before reporting implemented support.

## 6. Render-ID picking

Picking is an explicit separate raster pass to R32UInt plus the same reversed-Z depth convention; zero means background. Assign dense IDs in the inclusive integer interval `[1, drawCount]` in snapshot stable draw order, storing ID -> stable entity/draw globally unique identifier (GUID) in an immutable side table. Render the same admitted mesh skinning/culling/alpha-mask silhouette; blended sprites/meshes use authored pick-alpha cutoff (default 0.5), not unpredictable blend-order IDs. Resolve visible 2D/UI overlap by the same draw order; UI is ordinarily hit-tested on CPU and omitted from world picking.

Copy the requested physical pixel through the graph to owned readback storage; acknowledge after its fence. The request retains snapshot/camera/viewport/metrics/`SurfaceEpoch`/`SwapchainEpoch`/`DeviceEpoch`/`FrameRevision` and side-table leases. `Zero` is a valid `NoSelection`; device fault, out-of-range pixel or stale identity is a distinct outcome. Never interpret a dense pick ID as an `Entity` index or return the current snapshot's table for an older graphics processing unit (GPU) result. `Physics` picking is a separately selected policy and can disagree with visual silhouettes.
