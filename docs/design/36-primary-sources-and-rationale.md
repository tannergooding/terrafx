# Primary sources and rationale (informative)

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

This chapter cites published references and explains design rationale; it does not establish additional engine requirements. Binding decisions live in the linked owner chapters. Native/library standards constrain their implementations, while engine defaults and budgets are design decisions. Source inspection does not qualify a selected SDK/runtime binary or establish measured performance. No third-party implementation is reproduced here.

## 2. Graphics

The design integrates selected mechanisms from the separately researched Microsoft/GPUOpen libraries, not their complete engines or required dependencies. [DirectXTK12](https://github.com/microsoft/DirectXTK12) modernizes the approachable XNA-family SpriteBatch/Model/common-state path used as an API influence in [21](21-2d-and-3d-rendering.md). [DirectX-Graphics-Samples](https://github.com/microsoft/DirectX-Graphics-Samples), [D3D12TranslationLayer](https://github.com/microsoft/D3D12TranslationLayer), [Cauldron](https://github.com/GPUOpen-LibrariesAndSDKs/Cauldron) and [D3D12MemoryAllocator](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator) motivate explicit backing/version/completion and allocation policies in [17](17-graphics-device-and-resources.md), without adopting an immediate-context illusion or static append-only pools as general allocators. [DirectXMesh](https://github.com/microsoft/DirectXMesh), [DirectXMath](https://github.com/microsoft/DirectXMath) and [DirectStorage](https://github.com/microsoft/DirectStorage) inform [11](11-assets-import-streaming-and-packages.md)'s validated offline conditioning and bounded read boundary, and reinforce the existing storage/compute/packing separation.

[FidelityFX-SDK](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK)'s inspected FSR SDK 2.3.0 root explicitly says Vulkan is not currently supported; general introductory wording is not backend-parity evidence. Effects stay excluded behind [19](19-render-graph-synchronization-and-presentation.md)'s typed algorithm/history/capability gate. Selected implementation revisions require actual platform/code/license/binary review, including telemetry and nonuniform binary licensing, before dependency admission. Window-system integration (WSI) maintenance is a deliberate admission requirement beyond Vulkan 1.3, chosen instead of pretending `QueueWaitIdle` proves presentation release. Old/new swapchains may overlap; actual fences and epochs determine retirement. The D3D12 legacy-barrier baseline avoids requiring enhanced-barrier hardware.

Neither D3D12 nor Vulkan mandates world handedness. Left-handed (LH) +X-right/ +Y-up/ +Z-forward is engine policy so the identity camera's forward movement increases Z; importing glTF does not justify overriding that user-facing convention. Base class library (BCL) component cross/Hamilton algebra is retained, with axial versus polar reflection explicitly distinguished. Clockwise outward3D faces preserve numerical cross normals/positive signed volumes; 2D physics boundaries stay CCW. Row vectors, reversed depth in `[0, 1]`, and viewport Y mapping are independent policies with separate witnesses.

The [Vulkan registry XML](https://raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/xml/vk.xml) directly confirms matching `swapchain_maintenance1 -> surface_maintenance1 -> VK_KHR_get_surface_capabilities2` dependencies for the EXT/KHR paths. [Chapter 19](19-render-graph-synchronization-and-presentation.md) lists required instance/device enablement; a device extension name alone is insufficient.

The engine owns mixing, digital signal processing (DSP), resampling and action mapping; operating system (OS) device/protocol libraries do not substitute an audio/input engine. .NET offers no hard real-time guarantee; even an allocation-free callback can be paused by the runtime or OS.

Runtime Async changes lowering/performance/diagnostics rather than the established public async model: a forwarding `Task` and an async await wrapper are chosen by exception timing/lifetime/finally semantics, not a blanket rule that the wrapper is wasteful. Unsafe Evolution changes how caller obligations are declared/audited, not the API signature family. Application-friendly unions, tuples and positional records do not become stable framework/plugin contracts just because the compiler supports them.

## 4. Physics, Unicode, and reproducibility

[Catto publications](https://box2d.org/publications/) provide contact, sequential-impulse, continuous collision detection (CCD), constraint and BVH references, not a dependency on Box2D. Chapter [33](33-physics-acceptance-and-reference.md) maps individual sources to the derived algorithms in [22](22-custom-physics-world-and-solver.md), [23](23-custom-physics-shapes-queries-and-ccd.md). This engine specifies separating axis theorem (SAT), feature enumeration and translational CCD rather than delegating to an unspecified GJK/EPA implementation. Published2D techniques do not certify the custom3D solver; its stability and native integration tests remain implementation obligations.

[HarfBuzz shaping](https://harfbuzz.github.io/what-is-harfbuzz.html), [ICU bidi](https://unicode-org.github.io/icu/userguide/transforms/bidi.html) and [FreeType glyph retrieval](https://freetype.org/freetype2/docs/reference/ft2-glyph_retrieval.html) distinguish shaping, bidi and rasterization from input events and UTF-16 storage. Engine user interface (UI) owns layout, widgets and focus; Unicode behavior is not implemented by reversing strings or splitting chars.

[PCG reference](https://www.pcg-random.org/download.html) supplies defined generator mathematics and seeding; [Chapter 27](27-state-serialization-replay-and-recovery.md) specifies the exact transition, output, state, and unbiased bounded selection. A fixed tick alone does not make `System.Numerics`, `Math`, just-in-time (JIT), and operating-system behavior bit-identical. Replay declares exact profiles and checks actual state, without claiming general portable certification.

## 5. Rationale boundaries

32 KiB logical chunks, 256-row limits, 60 Hz defaults, 512 MiB budgets, queue capacities, shadow counts and process limits are engineering defaults, not natural constants. [04](04-capacity-and-workload-profiles.md) and the relevant subsystem owners define their admission/failure behavior. Units and row-vector algebra are defined in [03](03-shared-conventions-and-clocks.md); the game's twelvefold mathematics remains game-owned.

Dependency checksums, licenses and security servicing must be resolved and locked when implementing, then revalidated; the specification does not invent binary hashes for downloads that were not performed. This specification fixes architecture, behavior and algorithm contracts while leaving generated build outputs and empirical optimization to implementation.
