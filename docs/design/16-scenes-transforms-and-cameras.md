# Scenes, transforms, cameras, and spatial frames

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Scene and hierarchy records

Scene asset contains stable `Guid`/version, entities keyed by `Guid`, schema-tagged components, parent globally unique identifier (GUID) or `null`, ordered child list, prefab references/overrides and required asset IDs. Scene instance maps GUID -> `Entity` under one `World` owner. `Entity` GUID uniqueness, resolved references, acyclic hierarchy and depth <= 256 validate before instantiation. Maximum 1048576 scene entities and 65536 entities per prefab expansion; nested prefab depth <= 32 with cycle detection. [09](09-native-assets-and-source-adapters.md) owns native semantic records; [10](10-binary-data-and-authoring-formats.md) owns binary persistence.

### Repeated and nested occurrence identity

A native hierarchy has ordered entries of exactly one kind: `Entity = 1` or `PrefabPlacement = 2`; zero/unknown kinds reject. An entity or placement occurs exactly once in its containing hierarchy, and parent metadata agrees with the ordered entries. Expanding a placement replaces that entry in place with the target prefab's expanded roots in declared root order. Nested placements create provenance occurrences, not synthetic live entities or nested top-level `SceneInstance` assignments.

Let `NameUuid(namespace, name)` be chapter [10](10-binary-data-and-authoring-formats.md)'s frozen name-UUID recipe, with GUID strings in lowercase `N` form:

```text
RootOccurrence =
    NameUuid(rootAssetId, "scene/occurrence/root/v1")

ChildOccurrence =
    NameUuid(parentOccurrence,
        "scene/occurrence/prefab/v1/" +
        placementIdLowercaseN + "/" + targetAssetIdLowercaseN)

ExpandedEntityKey =
    NameUuid(occurrence,
        "scene/entity/v1/" + authoredEntityIdLowercaseN)
```

Asset/version/dependency digests are pinned validation/cook inputs but are not namespace operands. Validate the complete derived occurrence and expanded-key sets for collisions. Hierarchy traversal follows authored root/child order with each placement expanded in place; live Entity assignment instead sorts complete expanded keys by unsigned RFC GUID bytes. A top-level activation at cursor `k` reserves its scene-instance assignment at `k + 1`, then assigns expanded entities at `k + 2` onward in that key order. Nested occurrences consume no World identity ordinal. Canceled/rejected activation consumes none; activating the same source again preserves source occurrence addresses but receives new World Entity and scene-instance identities.

The occurrence limit is 1048576 retained occurrences per World, counting each root occurrence; active top-level instances are limited to 65536, expanded live scene entities to 1048576, per-prefab entities to 65536, and prefab depth to 32. Empty placements count toward occurrence and byte admission. Root/child projection, depth, hierarchy and representability validators remain mandatory.

Native references/overrides use a selector `(Scope, PlacementPath, AuthoredEntityId)`, where Scope is exactly `OccurrenceRelative` or `InstanceAbsolute`; zero/unknown rejects. A path contains only downward placement GUIDs, has at most 32 entries, and has no implicit parent traversal, wildcard, recursive search, nearest match or ambient lookup. Empty relative path means the explicit anchor occurrence itself. The anchors are:

| Use | Relative anchor | Absolute rule |
|---|---|---|
| Component/internal reference authored in an asset | That asset's occurrence | Allowed in a SceneAsset; forbidden in a reusable PrefabAsset |
| `PrefabPlacement.Overrides.Target` | Child occurrence introduced by that placement | Forbidden; root SceneAsset override is used for instance-wide targeting |
| Entity-reference value within an override | Selected target entity's containing occurrence | Allowed only when authored by a SceneAsset |
| Native placement binding for a child's external slot | Containing asset occurrence | SceneAsset only |
| Root SceneAsset override | Root occurrence | Allowed |

Authored-ID shorthand is explicitly local scope with an empty path; it never searches descendants. If no local entity exists but multiple descendants contain the ID, reject as ambiguous; if exactly one descendant matches, reject for missing occurrence scope rather than silently selecting it. A prefab needing a parent/sibling outside its subtree declares an external slot and receives its binding from its enclosing placement. The existing GUID-only `SceneInstance.TryGetEntity` is shorthand for a root-authored ID only.

### Nested occurrence witness

Use these stable authoring IDs:

```text
A  = 10000000-0000-4000-8000-000000000001
B  = 20000000-0000-4000-8000-000000000002
C  = 30000000-0000-4000-8000-000000000003
P  = 40000000-0000-4000-8000-000000000001   A places B
Q  = 40000000-0000-4000-8000-000000000002   A places B
R  = 50000000-0000-4000-8000-000000000001   B places C
S  = 50000000-0000-4000-8000-000000000002   B places C
EA = 60000000-0000-4000-8000-000000000001
EB = 60000000-0000-4000-8000-000000000002
EC = 60000000-0000-4000-8000-000000000003
```

Each B contains R and S. The complete repeated EC addresses derive as:

| Address | Occurrence GUID | Expanded entity key |
|---|---|---|
| `[P,R]/EC` | `fca9c64e-a2a2-8201-aada-37d941768fc4` | `847c8442-1579-84eb-acc3-d24fdbf89418` |
| `[P,S]/EC` | `4ba5f912-5537-8573-b703-ab0402b232ef` | `5753c5aa-e518-88bc-b023-0b1dcf929369` |
| `[Q,R]/EC` | `26b5de4d-171e-8228-ac94-1bc32647334d` | `889e120d-f490-8f99-9856-782b741ab007` |
| `[Q,S]/EC` | `9ba6445e-19d7-86ec-9ee5-acbe6e87ba38` | `95181077-4e48-8d15-b475-703bb60fc1e9` |

An internal B reference using `OccurrenceRelative([S], EC)` resolves to `[P,S]/EC` in the P occurrence and `[Q,S]/EC` in the Q occurrence. An override on A's placement P with relative target `[S]/EC` selects only `[P,S]/EC`; a root override using `InstanceAbsolute([P,S], EC)` selects the same occurrence. Bare EC in B is rejected as ambiguous. With EA and both EB entities included, assignment order is `[P,S]/EC`, `[P,R]/EC`, `[Q,R]/EC`, `[Q,S]/EC`, `[P]/EB`, `[Q]/EB`, `[]/EA`; first activation uses instance ordinal 1 and entity ordinals 2–8, and second activation uses instance ordinal 9 and entity ordinals 10–16.

Property paths are typed sequences of `FieldTag(nonzero permanent UInt32 tag)` and `FixedArrayIndex(checked UInt32 index)`, at most 64 segments. Source override ordering is lexicographic by scope, RFC-ordered placement path (shorter prefix first), authored entity GUID, component schema GUID, positive schema major, then property segments `(kind, numeric value)`. The expanded effective key is occurrence GUID, authored entity GUID, component schema GUID, schema major and property path. Duplicate effective keys, including distinct selectors that resolve to one target, reject within a layer; ancestor/descendant writes in one layer also reject. Apply component definitions, then inner placement overrides outward so outer layers win, then root-scene overrides last. A placement override target remains inside that placement's introduced subtree.

These semantics require the occurrence-qualified native scene/prefab payload as major 2. Descriptor identities, field tags, wire kinds/strides and independent bytes remain owned by chapter 10 and must be reconciled/approved there; this behavioral contract does not assign provisional tags or fixtures.

`LocalTransform` geometry uses chapter [06](06-owned-geometry-and-numerics-interchange.md)'s `TerraFX.Numerics` types. Its initialized pose uses explicit `Quaternion.Identity`/`Vector3.One`; raw default values remain zero. Chapter [06](06-owned-geometry-and-numerics-interchange.md)'s robust `Normalize` does not waive the following narrower authoring norm/scale admission.

`LocalTransform` has `Position: Vector3`, `Rotation: Quaternion`, and `Scale: Vector3` fields. Position and scale must be finite. Quaternion components and the computed `lengthSquared` must be finite, and `lengthSquared` must exceed `1e-12`; the engine normalizes the quaternion on assignment. An overflowed or nonfinite norm is an explicit validation failure, not a zero quaternion produced by division by infinity. The pose default is zero position, identity rotation, and unit scale (`Position = Vector3.Zero`, `Rotation = Quaternion.Identity`, `Scale = Vector3.One`). Scale components have magnitude in `[0.0001, 1000]`; negative scale is legal for rendering with parity handling, but not necessarily for physics. Cached `WorldTransform`, previous committed pose, and dirty version are transient engine-owned data, not serialized overrides.

Roots store a separate `SpatialPosition3`; their `LocalTransform.Position` is zero, avoiding two competing translations. Child translations are parent-local `Vector3` values. Hierarchy resolution retains a spatial translation and linear transform; it forms `world = local * parentWorld` only inside one admitted frame. Dirty propagation is iterative/topological, parent before child. Derived matrices may include parent-induced shear; rendering uses the full matrix/normal inverse transpose, while physics requires its restricted transform. Nonfinite or out-of-frame composition faults/refuses under [07](07-spatial-coordinates-and-indexing.md), never becomes identity.

Reparent modes are `KeepLocal`/`KeepWorld`. `SceneTransaction.Validate()` is a preview; queued edits retain typed intent and exact World/binding, scene-instance and entity generations, not precomputed transforms. At owner-boundary application, recompute each intent sequentially against the current canonical state after preceding FIFO commits and earlier edits in the same transaction. `KeepWorld` captures the child’s current canonical spatial location at application time, obtains the new bounded parent-relative displacement, then computes the relative linear transform and admitted SRT. In one common frame this is `oldWorld * inverse(newParentWorld)`. Recomposition residual must be <= `1e-5 * max(1, maxAbs(original))`; noninvertible/unrepresentable shear or an inadmissible displacement rejects the whole command. Moving to/from a root transfers translation between its spatial position and child-local pose atomically. Preservation is within that declared recomposition/representation budget, not a guarantee that a newly rounded child-local translation reproduces identical spatial bits. Compare positions through admitted nearby displacement, never by flattening cell indices into the residual matrix. Self-parent/cycle/cross-world/depth violations reject at application, with no partial mutation.

`HierarchyDestroyMode.DetachChildrenKeepWorld` and `HierarchyDestroyMode.DestroySubtree` are the only admitted destruction modes. Immediate `World.DestroyEntity`, both deferred `CommandWriter.Destroy` target forms, and scene unload require an explicit mode argument. The default single-entity policy is `DetachChildrenKeepWorld`, but callers pass that named value explicitly; there is no omitted argument, optional parameter, mode-less overload or ambient selection.

`DetachChildrenKeepWorld` destroys only the selected entity and detaches its direct children in their current stable child order. Validate every resulting child root pose under the existing spatial, SRT and recomposition rules; refuse the complete transaction if any child is unrepresentable. `DestroySubtree` destroys the selected entity's current subtree in descendants-first stable child order. Contact-end preparation and resource cleanup occur once per actually destroyed live entity. Parent links do not imply ownership of arbitrary referenced assets or entities. Temporary creation cancellation follows chapter [12](12-entities-components-and-queries.md).

#### M03 5.1 Namespaces and grafting

**RootPoses is a complete per-expanded-root final pose table, not a hidden delta.** Each Target is OccurrenceRelative from the placement's introduced child occurrence and names exactly one of that prefab's final expanded roots. It covers all roots once, including the empty table for an empty expansion. After completing that target subtree's nested grafts/inner overrides, copy this placement's canonical Local over each root, then apply this placement's own Overrides; outer grafts/overrides and root Scene layer follow. Root-level placements require explicit RootPosition and zero Local.Position; child placements forbid RootPosition and remove the template's root-position component. Retain other components. Read/Write never fills missing poses or multiplies/decomposes an implicit transform. This explicit outward replacement supports multiple roots without wrappers, hidden shear or ambiguous SRT signs.

Apply component definitions, deepest placement overrides outward, then root Scene overrides last. Only afterward resolve full references/external slots and validate hierarchy/components. Native cook/load never runs assignment normalization. Chapter16's public gameplay assignment still normalizes an admitted input quaternion; explicit native bindings copy the already-canonical, validated wire bits instead of invoking that setter again. Restore likewise retains those bits under chapter27. Amend this boundary explicitly rather than changing ordinary gameplay assignment.

#### M03 5.2 Override and reference keys

Selector Scope is OccurrenceRelative=1/InstanceAbsolute=2; zero rejects. Paths are downward PlacementIds, length <=32; no parent, wildcard, recursive/nearest search or ambient lookup. Empty relative path names the explicit anchor itself. The anchors are the already reviewed table above; RootPoses.Target uses the placement's introduced child occurrence, like Overrides.Target.

Source override order is `(Scope, PlacementPath RFC tuple, AuthoredEntityId RFC, component Guid/major/minor/scope, PropertyPath pairs)`. Component minor is zero and schema Scope=Content, so the extra constant keys do not change chapter 16's order. The effective uniqueness key is `(resolved occurrence Guid, authored EntityId, component tuple, property pairs)`, not the operation. Distinct selectors resolving to that same key reject within a layer; ancestor/descendant writes in one layer reject. Different components can legitimately use the same numeric path. Outer layers intentionally win.

Set=0 requires Value; Omit=1 forbids Value/ReferenceValue and targets only an optional field. Paths contain 1..64 explicit FieldTag/FixedArrayIndex segments, all declared PrefabEditable, with every index checked; Set replaces only a fixed scalar/geometry leaf, never a whole R/FA/RA. For an Entity leaf, Set additionally requires ReferenceValue; an ordinary Guid forbids it. Internal ReferenceValue.Value Guid equals the selector's AuthoredEntityId; external Value Guid equals ExternalSlotId. These are symbolic tokens resolved by this declared binding, not live identities. No missing component/path, required null/omission, default repair or silent ignored override.

Reference source order uses the same composite source selector/component/path key. Cover every explicitly present declared Entity leaf exactly once before override layers, including array leaves; absent optional leaves have no binding. Reference-target Kind Internal=1 requires Entity/forbids ExternalSlotId; ExternalSlot=2 has the inverse presence. ExternalSlot names the containing asset's explicit slot and creates no asset-ownership edge. A reusable prefab reaches a parent/sibling only through such a slot. Placement bindings cover every required child slot once; optional absent/null is admitted only under its descriptor; forwarding to a containing slot is explicit.

Each base Entity leaf's symbolic Guid equals its Internal target selector's AuthoredEntityId or ExternalSlotId token, just as an override Value does. Set atomically replaces both the symbolic leaf and its effective reference binding; Omit removes both. The overridden base binding is not applied afterward and cannot undo an outer override. Resolve only the final binding against the complete map/current shadow membership. An admitted optional-null external slot produces an absent nullable Entity leaf only when that leaf is optional; a required leaf rejects. It never fabricates Guid.Empty or silently changes an unrelated opaque Guid.

Required external slots have Required=true/AllowNull=false and exactly one nonnull binding. Optional slots may be omitted; explicitly null requires AllowNull. RequiredComponents is the exact sorted active Component/EntityTag set the target must possess. Duplicate/extra/unknown slots, default/stale/foreign entities and inappropriate null reject. Root Scene preparation takes a defensively copied typed slot-ID -> nullable actual Entity set, captures exact target World/binding generations, and revalidates against sequential current shadow membership at application. It never performs ambient GUID or latest-version resolution.

## 2. Prefabs and streaming

Prefab overrides identify an occurrence-scoped entity selector + component schema `Guid` + typed property path + typed value. Invalid/missing paths and unresolved/ambiguous selectors are import/migration errors, not silently ignored. Expansion remaps internal entity references through the complete occurrence map and requires explicit external asset-instance bindings; cloned ephemeral body/entity handles are never copied. Cycles, total entity/occurrence counts and cumulative byte budgets are checked before allocating a live scene.

Scene load is async preparation plus queued owner-thread atomic activation. Required assets/physics primitive definitions are ready and budgets reserved first; preparation captures the exact target World/binding generation and cancellation before application changes no world. Activation defensively copies its external-binding input, resolves the complete occurrence/entity map, validates every supplied target against the sequential current shadow membership, reserves the scene-instance and entity assignments, then commits without partial publication. Required external slots have exactly one nonnull binding; optional absence/null follows its descriptor. Duplicate, extra, nonexistent, default-handle, stale, foreign or inappropriate-null bindings reject. No ambient GUID lookup, latest-version substitution or cross-World binding is allowed. Rejected/canceled activation consumes no World identity assignment. After activation, cancellation cannot pretend the scene never existed. Unload is an explicit queued entity-destruction transaction and resource lease release; renderer/audio may retain versions until their completion protocols.

`SceneEntityAddress` is an immutable root-relative placement path plus authored entity ID for public address lookup. `SceneEntityProvenance` is immutable engine-produced data containing scene-instance ID, occurrence/path, source asset ID/version, authored ID, expanded key and qualified World identity. `SceneInstance.TryGetProvenance(Entity)` succeeds only for a live entity in that exact instance and World binding. Reparenting a live entity changes its transform hierarchy, not its source occurrence or World identity.

All loaders for one exact World binding use a single Scenes-owned registry, not per-loader maps or a process dictionary keyed only by World GUID. `WorldRegistrationBuilder.RegisterSceneSupport` enlists one closed registry factory before registration freezes; a SceneLoader cannot register it late. Entities owns only a lower internal participant/retirement interface; only Scenes constructor/restore actors obtain its typed registry, with no public service locator. Registry-owned source-version pins/provenance outlive the originating loader. Replacement constructs and fills a new candidate registry, restoring saved instance IDs/mappings before publication; old loaders/instances are revoked rather than implicitly rebound, and a new loader resolves the replacement registry.

`SceneLoadOptions` has an explicit parameterless constructor and the fields/defaults in [30](30-public-api-review-surface.md#5-scenes-cameras-and-animation). `AssetLoadOptions` is nonnull and immutable. `MaximumExpandedEntities`, `MaximumPrefabEntities`, `MaximumExpandedOccurrences`, `MaximumPrefabDepth` and `MaximumHierarchyDepth` may lower but never exceed the ceilings above: expanded entities `[1,1048576]`, prefab entities `[1,65536]`, retained occurrences `[1,1048576]`, prefab depth `[1,32]`, hierarchy depth `[1,256]`. Options validate/freeze before preparation and combine with the World's remaining identity, scene-instance, slot and byte capacities; no budget grants extra capacity or partial activation. Preparation takes independent asset/version pins, and abandonment/disposal reclaims reservations only after actual consumers stop. Usage errors are synchronous; admitted I/O/cook failures fault the task and expected activation refusal retains its scene-specific receipt.

## 3. Physics and animation authority

Dynamic body root position/rotation is owned by physics; body application programming interfaces (APIs) `Teleport`/`SetVelocity` apply at `Physics` admission, not field edits. Direct competing writes detected at stage 3 fault the tick. Dynamic roots cannot have a transform parent; visuals/bones/attachments may be children. Kinematic targets are staged by gameplay/animation; static changes use explicit physics update/rebuild. Collider scaling/shear rules are chapters [22](22-custom-physics-world-and-solver.md), [23](23-custom-physics-shapes-queries-and-ccd.md)'s authority and validated on registration/reparent.

`Animation` poses update bone-local transforms at stage 2; root motion produces a typed desired-motion record consumed by an application movement system. That system enqueues supported kinematic targets or dynamic forces/impulses; animation itself does not supply a character-controller solver. Root motion cannot move a dynamic body by bypassing collisions. Render interpolation does not feed back into simulation/hierarchy queries.

## 4. Cameras and coordinate conversion

Chapter [06](06-owned-geometry-and-numerics-interchange.md)'s owned left-handed (LH)/reversed projection and `LookAt`/`LookTo` factories supply camera matrices; plain `AsTerraFXMatrix4x4` does not change a base class library (BCL) source matrix's basis/depth. Camera extraction validates once, not per-vertex. Public camera/picking values use `TerraFX.Numerics`.

Camera fields are `ProjectionKind`, `VerticalFieldOfView` radians (default `float.Pi / 3`), `OrthographicHeight` (default physical 10 meters), `Near` (0.1 meters), `Far` (1000 meters or explicit `Infinite` for perspective), nullable `float` `AspectRatioOverride` (default `null`), normalized `Viewport` (default full), clear flags/color, layer mask and `Order`. Physical defaults are converted once to the frozen distance unit. Nonpositive/singular camera scale is invalid; extraction uses spatial position and rigid rotation, not inherited nonuniform scale.

Null aspect derives width/height from the active physical-pixel viewport; override is finite/positive and fixes only the projection's aspect, not the output rectangle. A matching viewport/explicit letterbox policy supplies undistorted pixels when a fixed source aspect differs from the window. Orthographic width = height * aspect. Chapter [11](11-assets-import-streaming-and-packages.md) imports perspective `aspectRatio` when present, otherwise leaves `null`, and imports orthographic aspect = xmag/ymag. Imported distance/extents scale with asset units, not dimensionless aspect/FOV. Validate derived values before publishing a camera; overflow/underflow into an invalid dimension refuses import rather than clamping.

Perspective projection and clip conventions are defined in [Chapter 03](03-shared-conventions-and-clocks.md). Orthographic height and aspect must be positive, and finite `Far` must exceed `Near`. An identity camera's right/up/forward are +X, +Y, and +Z; transform `UnitX`, `UnitY`, and `UnitZ` by its normalized rotation to obtain an oriented frame. The camera-target helper uses left-handed construction and refuses a coincident target or parallel up vector instead of inventing an orientation. View remains the inverse of the rigid camera-world transform. Unrotated camera-space Z > 0 is in front; there is no implicit 180-degree default camera turn.

`TryWorldToScreen` takes a `SpatialPosition3` and an immutable `CameraSnapshot`, returning a copied `ScreenProjection` with coordinates/depth/`IsInFront`/`IsInsideViewport`. False means only perspective `clip.W = 0`; invalid arguments, incompatible profiles, stale snapshots, or positions outside the snapshot's admitted calculation frame throw/refuse before projection, not another false condition. Otherwise `IsInFront` means `viewZ > 0` independently of near/far inclusion. `ScreenToRay` returns `SpatialRay3`, validates viewport/physical pixel/dots per inch (DPI)/inverse, and unprojects near depth 1/far 0 (a finite positive depth for infinite-far). The identity perspective center ray originates at the spatial camera and points +Z; an orthographic ray starts at camera plus `(0, 0, Near)` and points +Z. Editor picking does not assume identical physics/render silhouettes.

Render interpolation evaluates previous/current spatial positions in the same admitted frame before lerp and shortest-arc quaternion slerp, with alpha clamped to `[0, 1]`. Scale interpolates only without a parity crossing. Spawn/teleport/lost history or inadmissible history conversion uses the current pose with an explicit discontinuity. A frame change alone is not a teleport or an automatic history break.

## 5. Rebase transaction

`World` is the sole canonical owner of its enabled dimensional frames and frame-control history. Its standalone public route is the owner-idle `CreateNextFrame3/2` plus `SetFrame`; `EngineHost.ChangeFrameAsync` is the ordinary-thread queued adapter for the exact hosted World binding. Candidate inspection copies the exact owner/profile/settings and checked next dimensional revision, but grants no mutation authority and consumes no cursor, control, revision or marker. Disabled 2D refuses explicitly. Public Core frame construction and equal WorldGuid/frame bits do not confer World authority. The complete public signatures, receipt and queue channels are in [30](30-public-api-review-surface.md#4-hosting-worlds-and-jobs).

### Frozen M03 participant set

Amend the existing registration route; do not create a second World service. Before World construction, `WorldRegistrationBuilder.RegisterSceneSupport` captures one immutable opaque `SceneSupportRegistration` produced by `SceneSupport.CreateRegistration`; it owns the exact per-World scene/hierarchy and native-camera factories. `RegisterCpuExtractionSupport` captures the separate opaque `CpuExtractionSupportRegistration` produced by `Renderer.CreateCpuExtractionSupportRegistration`; it owns the actual headless-capable CPU extraction adapters and declares its Scenes prerequisites. `TerraFX.Entities` references neither higher namespace. Duplicate/conflicting/missing prerequisites reject Build. Renderer service availability in a Host does not silently register support into an existing World. No late enlistment, second scene registry, shadow renderer participant or same-GUID successor retarget is allowed.

The fixed private actor order is SceneHierarchyFrameAdapter (key 0), CameraFrameAdapter (key 1), CpuExtractionFrameAdapter2 (key 2), and CpuExtractionFrameAdapter3 (key 3). The first two represent the exact scene registry/hierarchy and native camera/ancestor source data; the latter two represent actual dimensional CPU extraction sources, previous/current conversion inputs and materialized World-relative caches. The 2D actor requires enabled Frame2 and keys 0/1; the 3D actor requires keys 0/1. The 3D actor includes applicable static M03 mesh/light/palette inputs, but not particles, animated palettes, UI/native passes or GPU completion. A selected actor with no entries returns a stamped typed empty state; it cannot skip participation. Support is required before the corresponding scene/camera/extraction use.

Preparation has no caller-selected camera or render target. It rebuilds only target-independent source/basis/history state and existing materialized entries. Persistent distant spatial positions need not all fit one frame-relative float representation; extent and precision checks apply to representations actually materialized or required by the selected actors. Nonmaterialized entries stay canonical/nonmaterialized. A valid current cache/history entry cannot be dropped, reset or lazily repaired to make a frame change succeed. A later `Renderer.Extract` independently supplies its target extent/camera IDs and applies the existing owner, marker, camera, draw/light/bone and diagnostic guards against the installed generation.

### One stamped cohort and coherent reads

Entities owns one private `FrameCohortCoordinator` per World. A boundary record contains both current dimensional frames and their complete persistence wrappers, one checked cohort-read generation, immutable participant-state roots and canonical control/cursor/marker facts. Every check/preparation result/reservation/retirement is stamped with exact World object/construction binding and operational owner generation, copied WorldGuid, requested dimension, unchanged other-dimensional frame, settings/profile, old/proposed dimensional revisions, source/read/participant-set generations, frozen actor keys/definitions, exact actor instances and source/configuration generations, and the owning operation/permit. Final install validates the whole vector, never only a participant count or schema GUID. The recorded-control path additionally carries its exact private one-use permit and signed sequence.

All frame-dependent scene, camera and CPU extraction readers obtain one lower-issued `FrameReadLease` over one boundary/cohort record. Acquisition books actual-use ownership before payload dereference and then revalidates publication/generation; if publication won, the reader releases the prospective interest and retries, while an earlier pinned reader is joined by old-owner retirement. A reader never combines separate current-frame getters with stale actor state. Unchanged-dimensional roots receive independent retained ownership in the new aggregate before the old one retires. Structural/camera-source writes advance or invalidate the relevant source/cohort generation before derived data can be read. Frame operations exclude those writers, active tick/query/jobs and borrowed jobs.

### Prepare, abort, install and retire

The lower private participant protocol is `CreateInstance`, read-only bounded `Check`, reserved synchronous CPU `Prepare`, reverse-order `Abort`, and detached-owner `Retire`. There is no participant `Install` callback. Check can inspect exact source/configuration facts and report bounded extent/precision/demand; it cannot allocate replacement caches, acquire new asset pins or mutate source. The complete simultaneous old/current + prepared/new + scratch + retained-read/pin + diagnostic/receipt/cleanup/retirement peak is reserved from existing World/owned-state and World/persistence admission before replacement allocation or Prepare. Higher-owned prepared payloads are immutable opaque values accompanied by lower-held explicit ownership.

| State | Required transition |
|---|---|
| Entry / admission | Direct `SetFrame` owns an exact idle World operation. Host admission revalidates the exact host/target binding and authority, selects cancellation or refusal, checks retained control history and checked owner-request/canonical-revision issuance, then queue and admission-byte capacity. Accepted install atomically records the actual request cursor/count, queue entry and marker invalidation. It does not reserve the eventual control slot. |
| Preflight | At the idle owner boundary, copy one source cohort/roster/configuration vector; validate all metadata before calling actors; reserve bounded source-use/diagnostic/scan scratch before source leases or Check. Check actors in frozen order. Validate all required extents before precision, then full replacement/coexistence capacity. |
| Preparing / prepared | After complete peak reservation, invoke applicable Prepare ports in dependency order, outside gates. They cannot escape work, tick, publish, acquire arbitrary World write access or install. Every allocation/pin enters the provisional lower ownership record. Prepared state is a complete correctly stamped cohort plus a prebuilt control/receipt/boundary record and old-owner retirement node; no partial state is visible. |
| Abort | On expected refusal/revocation/revalidation failure, end actual uses and attempt every independent prepared cleanup in reverse dependency order, even after one fails. Only confirmed releases refund. Successful abort permits `Rejected`; the old boundary stays installed. Still-used resources remain live and charged; stopped-but-unreleased resources remain charged in cleanup/quarantine. Unexpected preparation/abort failure throws for direct `SetFrame` or faults the original Host Task after actual uses end with `WorldFrameTransactionException`; it is never converted to a successful refusal. |
| Install / commit | Under the lower installation gate, repeat the ordered binding/authority/revision/roster/source/capacity guards using the exact stamped immutable Check facts; do not call actors under the gate. Merge actual queue counters into the preallocated unpublished record. Transfer prepared ownership, append exactly one frame control and finalize/seal one complete record; its release-store is the only visibility point. There is no allocation, callback, continuation or fallible check after visibility inside the gate. |
| Retire | Detach the old cohort owner into its preallocated retirement node and deny it new readers. Publish `Applied` outside gates after application uses unwind. Join only old-owner actual uses, then clean/release each confirmed ownership; do not wait for the new cohort, setter, new World or unrelated domain. `receipt.Retirement` succeeds only when these obligations finish, or faults with `WorldFrameRetirementException` while the cleanup ledger/quarantine remains charged. Applied and its committed facts never roll back or become Rejected. |

Abort/retirement cleanup distinguishes unattempted, confirmed, still-used and stopped-but-unreleased ownership; a callback being invoked is not proof of release. Retries are serialized by the lower owner and never repeat confirmed destructive releases. Independent immutable old outputs retain their own credits and original frame/relative coordinates until their actual last use; they are not joined as old-owner operation uses. Dropping the receipt does not erase a retained retirement failure.

### Entry, admission and application ordering

This is the single precedence contract for direct `D = World.SetFrame`, inspection `G = CreateNextFrame`, ordinary-thread `H = EngineHost.ChangeFrameAsync`, and private recorded-control application `E`. Diagnostic names below are operational facts, not additions to C0 or a new public validation-rule set. Within actor-dependent categories, the lowest frozen key then stable selected-entry order chooses the primary.

| Phase | Check order and result |
|---|---|
| Entry 0-1 | H validates nonnull World, then disposed/revoked/stopped receiver state. No admission or retention. |
| Entry 2 | D/G require exact World owner thread and idle state. H instead validates exact hosted World object/binding without a caller-owner check; wrong host is `ArgumentException(world)`, a known revoked former target is `WorldFrameTargetRevoked`. Never select a same-GUID successor. |
| Entry 3-4 | D/H reject forbidden public recorded-continuation control before cancellation. D/G/H validate enabled dimension and immutable candidate/origin/extents/owner/profile/settings; disabled 2D and malformed/foreign frames fail synchronously. H reads its sealed admission header, not owner-only World getters; candidate revision staleness is deferred to application. |
| Entry 5 | After valid usage checks, a pre-canceled H token returns canceled with no work. G performs checked selected-revision + 1 and returns only a copied candidate; it never mutates World state or consumes a cursor. |
| Host admission | Under the admission gate, revalidate host/exact target/authority and observe cancellation before selecting a terminal refusal or acceptance. Check retained control-history space first; then checked owner-request/count and canonical-mutation-revision issuance; then pending queue capacity; then admission/result/cleanup bytes. History/exhaustion/byte refusals use their declared `Rejected` receipt. A full queue faults the Task with `WorldOwnerQueueFullException`/`Diagnostic.Code == WorldOwnerQueueFull`, exact target/dimension/pending count/limit and signed current cursors; it is not a synchronous queue error or receipt, creates no request sequence and changes no marker. A selected refusal is terminal despite later cancellation. Accepted admission installs exact target ownership/request cursor/count/queue and invalidates the marker atomically; its original Task is not cancellable. |
| Application 0-3 | Revalidate the exact captured target World/owner generation; authority and exact unused recorded permit; immutable operand/profile integrity; then require requested revision = current + 1 with checked signed arithmetic. Expected target/authority/revision refusal precedes any participant, extent, precision or later capacity callback. |
| Application 4-4a | Revalidate frozen registration, complete participant/instance/source/configuration vector and coherent source/read generation before actor use. Expected participant/source change refuses. Then reserve bounded source-use/diagnostic/scan scratch before leases/Check; refusal is `WorldFramePreflightCapacityExceeded`. |
| Application 5-6 | Check all required representation extents first (`WorldFrameExtentRejected`), then precision/nearby conversion/history (`WorldFramePrecisionRejected`). No cache dropping, history reset, clamping or large-float recovery. |
| Application 7-8 | Check control-history slot, then signed `long` control sequence, canonical mutation revision, cohort generation and prebuilt-control capacity; then reserve complete preparation/retirement/coexistence/scratch/credit peak. Refusals retain accepted Host cursors/marker invalidation, append no control and successfully abort before returning `Rejected`. Direct operations check before their own canonical control write. |
| Prepare / install | Expected reservation refusal aborts then returns `Rejected`. Exceptions, wrong stamps or escaping work fault rather than reorder diagnosis. Install repeats the same applicable checks against current state, uses stamped immutable extent/precision facts without actor callbacks, merges actual queue counters, and performs the one complete record install. No install callback/allocation occurs under the gate. |
| Commit / retirement | `Applied` is irrevocable and records one complete dimensional frame, revision, control sequence and application NextTick with no diagnostics. No hidden Step, Extract, save, tick publication or GPU/audio completion occurs. The independent `Retirement` task reports only old-owner cleanup. A separate `WaitAsync` cancellation changes no operation or ownership. |

Host capacity is checked without reservation, preserving direct overtaking and existing FIFO order among queued requests. A candidate made stale by a direct operation or earlier queued control is explicitly `Rejected(WorldFrameRevisionStale)`; it is never silently refreshed. Queue-full is distinct from a request accepted and later rejected: a refused queue attempt consumes no cursor/marker and leaves its candidate reusable, while accepted work retains its actual cursor even if history or revision capacity disappears before application. Token cancellation wins only if observed at the specified pre-admission selection point; after a refusal has been selected it cannot turn its terminal fault/receipt into cancellation.

Required combined-failure witnesses include: full history plus stale candidate yields history-full before admission; stale revision plus participant/source/extent defects yields stale with no actor call; participant invalidation precedes extent/precision; extent precedes precision, which precedes replacement capacity; accepted Host work overtaken by direct `SetFrame` rejects stale; direct `SetTimeScale` consuming the last slot makes accepted frame work reject history-full without rewinding its request cursor; queue admission during Prepare survives install without false source staleness; pre-swap target replacement never retargets; cleanup failure after expected refusal faults instead of returning `Rejected`; and old cleanup failure faults Retirement without undoing Applied or invalidating independently retained output.

Persist initial/current dimensional frames and existing frame-control facts through [27](27-state-serialization-replay-and-recovery.md). Restore prepares one coherent cohort and publishes it with the candidate; it does not call public `SetFrame`, append a control, tick or publish a hidden snapshot. Keep canonical root/body positions, velocities, forces, relative anchors, entity identities and spatial-index membership unchanged. Foreign results retain their original frame/revision and convert only through an admitted nearby operation or refuse as stale. Physics has its own frame/rebase owner; this M03 cohort does not implicitly rebase Physics, audio, GPU or native-host state.
