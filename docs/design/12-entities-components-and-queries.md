# Entities, components, and queries

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Storage and registration

`World` owns entity slots, archetypes, managed attachments and deferred command buffers. `Entity` is `(OwnerId:uint, Index:uint, Generation:uint)`; default invalid. Slot zero is reserved; first live generation 1. `Destroy` increments generation before reuse; generation `uint.MaxValue` destruction retires the slot permanently. Owner IDs use chapter [03](03-shared-conventions-and-clocks.md)'s process-wide Core allocator. `World..ctor(WorldConstructionPlan)` is its sole Runtime caller; the sealed engine-private plan freezes validated registration/profile/options/capacities and the admitted identity, exact domain/root/reservation and ownership grants before exactly one ID is issued. The plan also carries one Core-issued `WorldDiagnosticsCapability`, binding the World to either its independently owned standalone diagnostics service or the borrowed host service without an Entities-to-Hosting dependency. A failure after issuance cleans up and surfaces the failure but burns the ID. Exhaustion fails before live allocation; disposal and replacement never refund an ID. Standalone, hosted and restored factories converge on this constructor; restored candidates consume source/transformation identity already admitted by the plan and never select a fresh lineage.

Components are registered `T : unmanaged`; registration supplies stable schema `Guid`, field schema, semantic validators and storage flags. Type IDs are process-local accelerators, not persisted identity. Portable components prohibit pointers, `IntPtr`, native handles and private runtime object identifiers; transient handles are explicitly transient/nonserializable. A portable `Entity`/`Entity?` leaf is permitted only when every leaf has a closed typed mapping to a declared stable-GUID field, with explicit presence, getter, candidate-only setter, bounded extent and contextual live-target validator. An ordinary `Guid` is never inferred to be an Entity reference. Unmanaged resource arrays prohibit `Entity` and private-handle leaves; an explicitly declared stable-GUID reference may be contextually validated without producing a runtime handle or membership authority. Managed strings/resources/scripts live in assets or owner-thread attachment tables, never boxed archetype columns. `RegisterTag` declares a zero-data filter; tags have no mutable span.

An immutable Entities-owned `WorldRegistration` is built before World allocation from explicit component, tag, system, and access/factory registrations. Its `CompiledContentSchemaRegistry` is Core build-time descriptor metadata, not executable codec registration or package data. Each data component has a typed column factory, field codec/default/validator registrations and any required authoritative-state contract; tags have stable schema identity/version and no CLR marker type or column. Registration freezes before World creation; no post-creation `RegisterComponent`, `RegisterTag`, or `RegisterSystem` path exists. World validates the compiled schema-registration closure, duplicate identities, exact descriptor-to-typed-registration correspondence, portable component restrictions, system access/dependency ordering, and capacities before calling the Core issuer or allocating live storage. Hosting checks its additional World/AssetStore compatibility before it delegates to World construction; SceneLoader checks asset/schema compatibility during preparation before live reservations.

Tags and data components share one unique schema-identity set. `MaximumComponentTypes` counts each explicitly registered component or tag schema identity once; it excludes unregistered catalogue descriptors/imports, systems, resources, attachments, and the implicit Entity column. Duplicate or cross-category identity conflicts reject before Core identity issuance, allocation, or registration mutation. `HasTag(Entity, Guid)` returns false only for an absent registered tag on a live same-owner entity; unknown schemas/stale/foreign entities throw. Idle `AddTag`/`RemoveTag` and matching live/temporary-entity CommandWriter overloads perform ordinary archetype structural transitions. Add-existing/remove-missing are errors; deferred edits participate in the same whole-batch preflight and atomic commit as data components. Query required/excluded schema sets can name tags, but Read/Write/TryGet cannot fabricate a zero-data span. Saved tag identity/version follows its registered schema, not a process-local type index.

Registered geometry field kinds bind to chapter [06](06-owned-geometry-and-numerics-interchange.md)'s `TerraFX.Numerics` values and `EngineGeometryBinary32Rows2`: vector2/vector3/vector4/quaternion/matrix3x2/matrix4x4. Schema generation traverses named components/rows, not private backing fields or base class library (BCL) type-name guesses. Readonly geometry is replaced as a complete value inside a mutable component; never mutate a borrowed property copy or bypass validation by reflection. Public application programming interface (API)-major/nominal type changes require module rebuild and schema/profile admission, despite unchanged component byte counts.

An archetype key is the sorted union of its component and tag schema GUIDs; component/tag identities cannot collide, so the key needs no category discriminator. Storage contains one managed T[] payload column per data component plus Entity[]; there is no tag payload column or span. Tags contribute zero payload bytes, including during prepared layout construction, installation, row growth, archetype migration, pooling/reuse, and failed-preparation cleanup. The logical target payload is 32768 bytes, with capacity `min(256,floor(32768 / (12 + sum(componentSize))))`; only data component sizes contribute. Capacity must be >= 1; oversized component/archetype is rejected before mutation. Arrays/headers/alignment/metadata add real memory beyond this target; do not advertise 32 KiB actual object footprint. Pools clear departed rows containing handles/sensitive application data before reuse.

Default admitted limits: 1048576 live entities, 4096 archetypes, 65536 deferred commands per barrier, and 256 explicitly registered component/tag schema identities under `MaximumComponentTypes`. Catalogue descriptor count does not consume this World registration limit. All limits are configurable before World creation, included in profile, and allocation-checked; failure is `EntityCapacityExceeded`/`ArchetypeCapacityExceeded`/`CommandCapacityExceeded`. `Entity` slot table is sparse index -> archetype/chunk/row/generation; chunk ordinal is monotonic nonnegative `long` and exhaustion refuses allocation. Ordinary capacity/row/type indices use `int`; the frozen unsigned handle tuple remains a separate identity representation, not the type of every arithmetic index.

### Stable World and Entity identity

`WorldGuid` is the nonempty persistent identity of the logical World/document. After validating and freezing construction inputs and capacities, the World-owned construction path resolves exactly one value before identity issuance and publication. A supplied `WorldOptions.WorldGuid` is validated and retained; `null` selects one `Guid.NewGuid()` UUIDv4 result for that construction attempt. `Guid.Empty` is invalid, not omission, and the resolved value is never written back into caller options. The Entities-owned registry shared by admitted standalone and hosted World factories owns active/reserved GUID admission. Resolve and reserve before Core `OwnerId` issuance; an active/reserved collision rejects without silently choosing another GUID. A same-GUID candidate is permitted only against its exact replacement target binding, with reservation transferred atomically at swap. Ordinary replacement/branching retains the source checkpoint GUID; an independent fork uses its explicitly selected fresh target-record GUID. The GUID is never inferred from `OwnerId`, regenerated per save, or used as operational authority.

#### Process-wide WorldGuid registry

The Entities-owned `WorldGuidRegistryAccounting1` is the single process operational index for admitted standalone Worlds and later-enrolled hosted factories under the selected loaded Core identity. It tracks active/reserved WorldGuid keys and exact binding generations; it is not the domain-local lineage registrar, a persistence record, or an authorization lookup service. A key remains retained through every associated owner, preparation, independent-use, retirement, and quarantine role until actual release. Immutable snapshots, copied identities, remaps and GUID equality alone are not active bindings.

Core's non-resetting participant-Type seal accepts only the actual CLR `Type` identity of `TerraFX.Entities.WorldGuidRegistry`. `WorldGuidRegistry.GetSelected()` calls `WorldAdmissionParticipant.Claim(typeof(WorldGuidRegistry))` before any backing allocation. Both Core and Runtime use only zero-initialized static value/reference state before the claim; neither has an allocating static initializer, `Lazy`, or preclaim profile/control/directory/index/slab allocation. A matching type name is not sufficient, and a second Runtime registry Type fails before backing allocation.

Runtime synchronizes one bootstrap state machine: `Uninitialized -> Initializing -> Ready | Failed`. Only the caller that wins `Uninitialized -> Initializing` reserves the full 1,060,672-byte cold charge and initializes. It retains each successful allocation before the next fallible step, performs allocations outside bootstrap/admission gates, and publishes one instance only after the control, fixed index, directories and invariants are complete. Concurrent same-Type callers wait outside gates without an engine-owned waiter list, Task or second cold reservation; successful callers receive the same instance. Recursive access by the initializer is an invariant failure, not a self-wait. `Failed` is terminal for that selected execution domain: all partial backing and the full cold charge, including unspent amounts, remain owned for the domain lifetime. There is no retry, reset, alternate instance, reachability refund, session/World initialization, or OwnerId issuance. A fixed failure record (stage, category and numeric facts) fits the existing 4,096-byte control; the initializer rethrows its original exception, while waiters/later callers receive a contextual `InvalidOperationException`. The registry does not retain arbitrary exception graphs or stack traces. A post-Ready slab allocation failure is not singleton failure: its exact G ticket remains until that attempt ends; any returned slab installs at its reserved ordinal and remains charged at high water, while an unspent grant is released only after the attempt proves no slab was returned.

The fixed process limits and complete layout are owned by [chapter 04](04-capacity-and-workload-profiles.md#m03-a-process-wide-worldguid-registry-accounting); no caller supplies demand counts or raises them. Fresh construction reserves its admitted process/domain roles before lineage/session work and Core issuance. Replacement reserves both the exact old binding and prospective destination before source inspection; a changed destination is unavailable until the old/new transition is atomically published. At full K, an unknown destination may be refused even if source inspection would later establish same-GUID replacement. Two plans are independently charged and are not guaranteed; after one swaps, competing claims are invalidated but continue to consume their cells until actual cleanup. Lock order is process registry, exact domain membership, then binding/publication. Allocation, GUID generation, callbacks, codecs, worker joins, Task delivery and physical cleanup occur outside those gates.

Domain-interest names used below are distinct credits: `C_o` is candidate/current World complete-history ownership; `S_o` and `T_o` are retained source and transformed-target data ownership; `S_p`, `T_p` and `D_p` are preparation source, target and domain consumers; `S_c`, `T_c` and `D_c` are accepted-commit source, target and domain consumers; `H` is the default-domain handoff operation; and `W_u` and `D_u` are independent-use World-history and domain-operation interests. Coincident GUIDs, roots or owners do not alias these cells. A transfer moves one named credit; it does not duplicate it.

Fresh construction prepays two domain interests; replacement prepays nine for an external domain and ten for the default domain (including H); independent use prepays two. Each named interest is a distinct domain cell even when roots/GUIDs coincide. The binding-owner, coordinator and commit U credits remain associated with their O/P roles; H adds no process U or duplicate close-owner credit. Fresh/independent-use operations permit no independently escaping children; replacement preparation permits exactly one prepaid accepted commit; commit/handoff permit none. Additional independent work requires its own closed admission.

All carriers default invalid, contain no positive generation or authorized role until issued, and copying does not duplicate ownership. `WorldGuidGrant` has a registry-fixed route role and no caller demand argument; `WorldGuidSlabGrant` names the exact G ticket/category/ordinal/generation and is consumed only by registry backing allocation. `WorldPreparedReplacement` is issued by exact-target Entities preparation and retained opaquely by Hosting. Captures, transfers, ticket use and ending are single-use checked transitions against the owning control. `IWorldGuidRetentionOwner` is memberless and is implemented only by `WorldConstructionPlanControl`, `WorldLifetimeControl`, `WorldReplacementOperation` and `WorldGuidUseControl`; marker implementation grants no acquisition, mutation, close or quarantine authority. Data-only `WorldRetainedHistoryControl` and nested `WorldPlaybackControl` do not gain process-binding authority. Only `WorldGuidUseControl` may quarantine its own U/domain interests; only `WorldLifetimeControl` with its exact `WorldGuidRetirementPermit` may retire/quarantine the corresponding unpublished or revoked O generation. An independent U may delay retirement of a revoked binding but cannot change an active binding. No generic GUID-based quarantine or reattachment exists.

`ReplayLineageId` identifies an admitted compatible checkpoint/replay history; `IdentityBranchId` identifies the future issuance branch; each assignment retains its creation lineage/branch. Fresh `World.Create` and hosted `EngineContext.CreateWorld` constructions start a new history. After input/capacity validation, WorldGuid reservation and execution-session acquisition, the Entities-owned path uses `WorldOptions.InitialReplayLineageId` when supplied, or selects exactly one independent `Guid.NewGuid()` UUIDv4 when it is null. A supplied value must be nonempty and is retained exactly; it is not restricted to UUIDv4 or the Entity/scene-instance UUIDv8 exclusion. A present `Guid.Empty` rejects before reservation or Core OwnerId issuance. Generated invalid values are invariant failures and generation exceptions preserve their cause; there is no redraw, WorldGuid fallback, default value or continuation fallback. The resolved value is not written back into caller options and is fixed before factories can observe the World.

The initial branch remains `NameUuid(WorldGuid, "world/identity-branch/root/v1")`, while initial issuance uses `WorldGuid`. The initial branch directory row carries the selected creation lineage; the history begins with no assignments, and the first committed assignment has ordinal 1. Root registration consumes no Entity or scene-instance assignment ordinal. Recreating a disposed World with the same WorldGuid selects a new lineage and does not import prior history; branch and bare automatic GUID values may repeat, while qualified creation identity remains history-qualified. A matching WorldGuid or ReplayLineageId is never continuation proof or cross-binding authority.

Restored candidates never perform fresh-lineage generation. They install only the source/transformation lineage and complete history admitted by chapter [27](27-state-serialization-replay-and-recovery.md): continuation and compatible Branch retain source lineage; an admitted lineage-changing migration or IndependentFork uses its explicit nonempty `NewReplayLineageId`. No constructor temporarily generates a lineage and overwrites it during Restore. Stored and explicitly supplied nonempty lineages may be non-v4 or equal WorldGuid; the UUIDv4 requirement applies only to engine-generated null-input fresh lineages.

### Domain-local lineage participation

Each `WorldAdmissionDomain` owns one Entities lineage registrar and the complete-history membership boundary used for start-new admission. Root standalone Worlds without a supplied domain receive an engine-owned default domain; caller/host domains may be shared explicitly. Lineage membership is domain-local and is never inferred across domains, hosts, Assets, unopened files, remaps or frozen metadata. The process-wide active/reserved WorldGuid admission rule remains separate and unchanged. Replacement/load preparation and candidate construction use the exact target World/domain and cannot retarget by GUID equality.

The registrar and its admission carriers are engine-private types in `TerraFX.Entities`; none is a public fabrication or GUID-only permission:

| Carrier | Owned meaning |
|---|---|
| `WorldHistoryRegistrar` | One per domain; owns the root directory, per-root GUID vectors, shared full-GUID index, credit/reservation directories and the membership gate. |
| `ValidatedWorldIdentityHistory` | Issued only by the complete Entities validator; carries WorldGuid, current lineage/branch, namespace, cursor and validated history. |
| `WorldHistoryRegistrationPermit` | Prospective root/byte/credit grant bound to the exact domain, operation and root slot/generation. |
| `WorldHistoryInterest` | Independently owned credit in an exact registered root generation; transfer, consumer and cleanup roles preserve the same credit. |
| `WorldNewLineageReservation` | At most one new value per target root; recognizes only its exact domain/reservation/root generations. |
| `WorldDomainOperationInterest` | Admission interest with finite child/growth allowance, acquired before admitted work escapes wrapper ownership. |
| `WorldDomainRetirementOwner` / `WorldDomainRetentionAnchor` | Entities-owned retirement actor and pre-owned intrusive domain node retaining actual grants, consumers, retiring storage and quarantine without public-wrapper reachability. |
| `IWorldHistoryRetentionOwner` | Memberless marker implemented only by approved engine-owned controls retaining the actual history/data/consumer/cleanup state. |
| `WorldDefaultDomainOwner` / `WorldDefaultDomainHandoff` | Current default-domain close credit and single-use provisional replacement ticket, bound to the exact domain and owner/candidate bindings and generations. |

The closed state-changing protocol is `PrepareRetainedRegistration`, `PrepareStartNewRegistration`, `CommitRegistration`, `RetainHistory`, `TransferHistory`, `PublishStartNew`, `EndConsumerAfterActualUse`, `EndOwnerAfterActualHistoryRelease`, `QuarantineUnreleasedHistory` and `AbandonPreparedRegistration`. Preparation prospectively reserves complete root/key/edge/index/vector growth, interest and failure/cleanup controls before allocation. Gated commit revalidates exact generations and installs all membership/reservation changes or none; transfer moves an existing credit without minting another or changing domains. End operations are nonblocking and occur only after actual consumer use or owned-history release. Refusal returns no usable carrier; failures retain existing charges in cleanup/quarantine rather than dropping a key. Allocation, UUID generation, codecs, callbacks, worker joins and physical cleanup remain outside the membership gate.

Valid copies of an issued carrier alias the same owning control, role and single-use authority. A valid copy may participate in the first authorized transition; copying creates no additional reservation, interest, grant or ownership credit. Capture, transfer, publication, abandonment and ending remain checked against the shared control and exact generations, so competing or sequential aliases cannot perform two successful instances of the same single-use transition or refund a credit twice. After consumption, transfer or terminal closure, all old aliases observe the resulting authority state. Copied metadata, unissued/default authority, foreign or stale generations, unauthorized retargeting and duplicate use provide no authority. Repeated idempotent public disposal may return normally, but does not constitute another ownership-ending transition.

The registrar indexes the sorted unique union of only these validated identity-history fields: `state/identity-history` tag 2 `ReplayLineageId`; every `state/identity-branch` tag 6, tag 3 `CreationLineageId`; and each branch's recursively retained `state/fork-source` tag 8, tag 3 `SourceCreationLineageId`, following tag 7 `Prior` to absence. Checked header/control/source duplicates must equal their exact history row and do not add memberships. WorldGuid, BranchId, Entity/scene IDs, arbitrary GUID-valued fields, digests and remap getters are not lineage keys. Full 16-byte RFC GUID equality is authoritative; hashes only accelerate lookup. The Entities validator issues a `ValidatedWorldIdentityHistory` only after complete descriptors, equality, ancestry, assignments and structural bounds are validated.

Start-new admission claims one genuinely new current lineage for one exact target root in its exact domain. Preparation reserves prospective capacity and ownership but establishes neither semantic membership nor pending exclusion. After complete validation and prepared storage, gated `CommitRegistration` installs the exact target root's complete membership and its new-current-lineage reservation atomically, or installs neither. This transaction is the start-new admission linearization point. A retained registration linearizes at its gated complete-membership installation. Prospective retained grants, vectors and accounting/index capacity never win membership priority.

Admission applies two distinct conflict predicates. First, a start-new request refuses if its requested new current lineage occurs anywhere in another root's committed validated membership, including that other root's retained creation or fork-source ancestry. This freshness predicate examines the requested new current lineage, not every retained lineage in the incoming history. Second, every complete membership installation—retained or start-new—refuses if any key in its full validated union intersects another root's pending new-lineage reservation. This includes nonactive branch creation lineages and recursively retained fork-source ancestry. A reservation excludes its one reserved value, not its owning root's entire history.

Subject to complete validation, source-relative freshness and capacity, a migration or fork may therefore install a genuinely new current lineage while sharing retained creation/fork-source lineages with committed roots. Such retained overlap alone is not a conflict, including when an overlapping root has a pending reservation for a different value absent from the incoming union. These domain predicates do not replace chapter 27's source-relative transformation/freshness checks.

Refusal installs no partial membership or reservation, returns no usable admitted carrier and does not wait, truncate provenance, redraw a lineage or reinterpret restore intent. Only the owning operation's exact domain, operation, root and reservation authority recognizes its own admission during revalidation. Target-data/candidate uses retain or transfer the exact admitted target root and grants; belonging to the same operation or having equal GUIDs does not exempt another root. Candidate, data-owner and consumer interests remain separately charged.

Pending exclusion persists until publication or irrevocable abandonment. `PublishStartNew` ends exclusion only in the same allocation/callback-free visibility transaction that publishes the fresh binding or replacement and performs the applicable history, WorldGuid and ownership transfers. It must not run earlier as a separate release. A retained installation ordered before that transaction refuses; one ordered afterward may coexist under ordinary admission rules. Shared bits certify no historical compatibility.

`AbandonPreparedRegistration` is an irrevocable terminal transition serialized against capture and publication. Before removing exclusion, it permanently disables every publication-capable route for the exact operation/root/reservation generations, including any captured route owned by that terminal operation. Abandon-first cannot later publish; publish-first cannot subsequently become abandoned. Published cleanup uses ordinary retirement.

Acquisition closure or wrapper disposal alone is not abandonment of a captured operation. Only the actual owning actor's terminal prepublication refusal, failure or abandonment performs that transition. Logical exclusion removal does not end actual membership, reservation-control occupancy, storage, consumers, pins or cleanup/quarantine ownership; each survives to its own actual-release condition. Already committed unreleased history remains known membership. Failed prospective cleanup retains its ownership charges without becoming committed membership or gaining priority.

Fresh-factory lineage conflicts report contextual `InvalidOperationException` with operation, lineage and domain context. Persistence uses chapter 27's applicable existing `Rejected` channels. Compatible retained admission requires no new reservation; a Branch transformation that starts a lineage, a lineage-changing migration, and IndependentFork consume the exact reservation installed with their admitted target history. No cross-domain or permanent lineage tombstone is introduced.

Only complete engine-owned histories and their actual admitted consumers are roots: active/candidate/retiring/quarantined Worlds; immutable canonical snapshots; bounded decoded source and transformed target; and plans/operations retaining those complete histories. Each independent root or operation consumer owns a charged interest before work escapes. Scalar IDs, copied getters, options, receipts, unloaded remaps, unopened files and disposed passive wrappers do not retain membership or permit later acquisition. Immutable per-root key vectors remain valid through actual consumers; the shared index is accessed only under the domain membership gate, never through borrowed/stale slot references.

Preparation reserves root/key/edge/interest/reservation cells, complete index/vector growth, sort scratch and cleanup/quarantine controls before allocation. Commit revalidates exact domain/operation/root generations and capacity under the gate, then installs membership/index/reservation changes atomically or none. Allocation, UUID generation, codecs, callbacks, worker joins and physical cleanup occur outside that gate. Wrapper disposal closes its own acquisition route but cannot refund a consumer still in actual use. Membership retires only after all actual histories, pins, consumers and cleanup/quarantine release; observer cancellation, GC, wrapper reachability and copied metadata are not release evidence. Failed cleanup transfers the existing charged interest into pre-owned quarantine rather than dropping membership. Domain retirement and its ownership rules are specified in [04](04-capacity-and-workload-profiles.md), [27](27-state-serialization-replay-and-recovery.md), and [29](29-project-setup-build-and-deployment.md).

World construction freezes and validates identity inputs, resolves/reserves WorldGuid and the exact domain, obtains the ready execution session, then resolves and registers fresh lineage or consumes an already validated restore plan. The complete construction plan is revalidated before the sole private World constructor issues one Core OwnerId. No owner is issued before successful identity admission; an issued but failed candidate burns its owner. Restored target identity and lineage are fixed before candidate factories/Restore, and successful replacement transfers domain/history ownership atomically with binding publication. Old-World retirement releases only its interests and cannot close or await a surviving replacement's domain. Chapter [30](30-public-api-review-surface.md) owns the public construction surface; [29](29-project-setup-build-and-deployment.md) owns the exact issuer and participant actors.

The private Entities execution domain owns one synchronized `ExecutionSessionId` gate with `Uninitialized`, `Ready(sessionId)` and `Failed(exception)` states. Every domain/World admission obtains the session before Core owner issuance or World publication. Under the gate, the first initializer generates one nonempty `Guid.NewGuid()` UUIDv4 and publishes `Ready`; that publication is the sole successful initialization linearization point. Initialization failure publishes and retains the exception as `Failed`; later admissions surface it without generating another value, returning a default, or retrying. No owner is issued and no World is published by a failed initialization. A later World-construction failure does not reset a successfully published session. The session survives disposal of the last World, host stop/restart, replacement and fork; it is not caller-supplied and is excluded from canonical persistence and hashes.

Automatic Entity and top-level scene-instance IDs use chapter [10](10-binary-data-and-authoring-formats.md)'s versioned name UUID recipe:

```text
Entity       = NameUuid(issuanceNamespace, "world/entity/v1/" + ordinal)
SceneInstance = NameUuid(issuanceNamespace, "world/scene-instance/v1/" + ordinal)
```

`ordinal` is sixteen lowercase hexadecimal digits. One checked cursor advances for every committed Entity or top-level scene-instance assignment, including explicit IDs. Explicit World identity requests require a nonempty GUID outside the exact RFC-variant UUIDv8 domain reserved for engine issuance. The restriction does not apply to authored IDs, asset/schema IDs, occurrence keys or lineage metadata. The complete assignment history rejects a duplicate GUID even when its prior row is retired. Canceled tokens and failed transactions/activations consume no ordinal; successful explicit assignment consumes the current ordinal. No reset, recycling, truncation or random retry is permitted.

The UUIDv8 exclusion applies when the World assigns an Entity identity or top-level scene-instance identity, not when an `EntityDescription` candidate is constructed. A present `PersistentId` candidate must be nonempty, but a nonempty UUIDv8 candidate remains constructible and is refused only at the World assignment boundary. Idle `World.CreateEntity` refuses it before canonical mutation or ordinal consumption. A deferred writer Create records the refusal through chapter [13](13-jobs-and-frame-pipeline.md)'s first-fault channel before any command key/sequence, payload preparation, staging reservation or token issuance. Eligible nonreserved duplicate identities remain append-admissible and are attributed atomically during preflight: a retained-history collision belongs to its requesting operation; a collision among surviving Creates belongs to the later Create in playback order. `ExplicitIdentityCollision` preserves its actual preflight cause and alone does not require a `ParamName`; other preflight reasons retain their existing exception contracts.

The cumulative assignment limit is 33554432, retained branches 1024, Entity slots including permanently retired slots 2097152, authoritative Entity-reference positions 4194304, active top-level scene instances 65536, and retained scene occurrences 1048576 including each root occurrence. All limits remain subordinate to the joint byte admissions in [04](04-capacity-and-workload-profiles.md). A slot/assignment limit refuses new creation before mutation but never prevents a valid retirement.

The resident identity ledger is append-only and paged by 4096 assignments. Its exact 24-byte record contains a 16-byte RFC-order stable GUID, a four-byte little-endian live locator, and a four-byte little-endian metadata word; ordinal is the one-based row position. Metadata bits 0–9 are the creation-branch directory index, bits 10–11 the kind (`1` Entity, `2` scene instance), bits 12–13 the origin (`1` automatic, `2` explicit, `3` fork-imported), bit 14 live, and bits 15–31 zero. A live Entity locator is its slot, a live scene-instance locator its registry slot, and a retired locator is zero. Retirement clears only live/locator state; it retains the exact GUID index entry and provenance and needs no new ledger row.

An insertion-only B+ tree indexes the full 16-byte GUID to four-byte ledger ordinals; comparisons dereference and compare all RFC bytes. Pages are 4096 bytes with a 32-byte header, up to 1016 four-byte leaf ordinals or 508 eight-byte internal entries, with nonroot minimum occupancies of 508 leaf entries and 254 internal children. The maximum 33554432-assignment tree is at most 66315 pages and has height three; up to 272 MiB of the shared-state transition reservation may fund copy-on-write preflight pages. Preflight validates the complete batch and prepares page, reverse-slot, retirement, cleanup and event capacity; commit installs prepared storage without allocation or callbacks. Failure discards prepared ownership and leaves the current root, cursor, ledger and structural state unchanged.

`WorldEntityIdentity` is a qualified value key `(WorldGuid, CreationLineageId, CreationBranchId, EntityId)`, not proof of membership or authority. Lookup is performed only in the exact current World/binding. The bare stable-GUID lookup is an intentional query of that selected current World; replacement remapping instead uses the pinned source checkpoint's live set and never falls back to equal GUID bits from a discarded future.

Within a chunk append new rows; remove by copying last row into removed row and updating its slot lookup. `Structural` playback's stable order makes these moves reproducible. Component default is all fields' default values, then supplied values/validators; padding is never serialization/hash data.

### M03 frozen component storage and typed codec bindings

The public component producer path begins with an exact selected schema tuple in the Core `CompiledContentSchemaRegistry`. `ComponentSchema<T>.FromRegistry` copies its component role, active tuple, fields, defaults, storage and restore declarations; direct construction must pass the same compiled-registration join. `ComponentLayout` is separate from canonical field encoding: `LogicalBytes` is exactly `Unsafe.SizeOf<T>()`, including padding, and lies in `[1, 32756]`. LayoutId is nonempty and qualified by the exact schema GUID/major/minor/scope; equal stride or LayoutId never proves matching semantic accessors. Canonical codecs visit declared fields and never emit padding contents, addresses, owners or accelerators.

`RegisterComponent` captures `factory.Binding` exactly once before any provider callback, column allocation or World owner issuance. The sealed binding freezes its copied descriptor and its actual default, closed field-access, restore and Read/Validate/Count/Write roots for one `T`/immutable symbolic `TAuthor` family. `WorldRegistration.Build` closes the entire catalogue/registration/participant graph. Mutable factory getters are never consulted again; shared providers/configuration are immutable and reusable, while mutable columns and operation state are fresh World-owned storage/bindings. Generated and handwritten providers use the same public producer path and qualification requirements.

The declared storage inventory names each source path, kind, offset, extent, bounded inline count/stride, semantic purpose and explicit padding. Leaves and padding partition `[0, LogicalBytes)` without overlap or gaps. Each canonical field binding names its selected Core path/rule/default and all storage paths, then provides closed typed runtime and author accessors. Scalar, optional, Entity/optional-Entity, explicitly declared stable-GUID-reference, fixed-array and bounded aggregate producers are distinct; optional values have separate presence/value operations and absent values are never synthesized. Ordinary Guid remains opaque unless its selected descriptor explicitly gives it a reference role. An Entity binding reads/writes live handles only through the exact engine-issued complete-map binding; a Guid scalar cannot substitute for it.

The inventory and path checks validate declarations, not arbitrary CLR storage or callback truth. Runtime admission checks tuple/role/field/default/rule/storage/restore correspondence, legal ranges, leaf/padding coverage, closed typed-port compatibility and duplicate/path closure before callbacks. It cannot discover hidden fields, prove offsets/accessor semantics, or certify immutable object graphs. The selected source and emitted artifact therefore require an independent source-layout audit and nonfriend public execution of the actual default, getter/presence/reference, restore and codec paths. Same-size wrong-field bindings and an opaque Guid equal to a live Entity ID are required distinguishing failures; mutually swapped encoder/decoder implementations do not pass merely by round-tripping. NativeAOT root closure and selected-artifact evidence are distinct from metadata admission.

`IComponentStateCodec<T,TAuthor>.Read` receives an engine-issued scoped `ComponentReadBinding<TAuthor>`. Its public `Complete`/`Reject` producers are callable by external handwritten codecs, but cannot be constructed by callers. One live callback can issue exactly one result for its exact source/schema/operation/thread. Complete requires a nonnull complete immutable author root and exact consumption of the source extent. Reject requires a defined failure kind, bounded source offset, optional structurally valid field path and nonempty bounded message, or preserves an existing Core EBIN rejection and its exact structural facts. A read result is either a nonnull `Read` root with exact consumption and empty diagnostics, or `Rejected` with no usable root and nonempty diagnostics; status-aware `TryGetAuthorValue` exposes nullability without a success-null state. A null/foreign/duplicate result, bad consumption or callback exception is a protocol/execution failure, not a malformed-input fallback. The author root cannot retain borrowed bytes, binding authority, mutable caller storage, a live World or an unaccounted owner.

Default construction, write-scope validation, capture, symbolic reference restore and actual codec paths use that same frozen typed dispatch; no alternative reflection-derived field map is allowed. Reset and Derived transient policies execute only their declared default/rebuild roots. Required serialized bytes are never repaired from author defaults. Saved factory/schema/storage identity mismatch rejects in source/target preflight before candidate issuance when those facts are available; a semantic callback failure after issuance aborts candidate ownership, burns the issued owner and leaves the prior World unpublished.

`ComponentDerivedDependency` is an exact active Content Component tuple paired with its exact registered unmanaged type. Its list is initialized, copied, null-free, and duplicate-free; only registered Persistent components are valid dependencies. Tags, Auxiliary/Foundation records, transient components, inactive or historical tuples, foreign descriptors, and unregistered or mismatched types reject. `None` and `Reset` factories require an initialized-empty list; a Derived factory may also declare an initialized-empty list when it reads no component dependency. Complete projected membership must satisfy every declared dependency before create/add/remove commit and candidate restoration. Removing a required Persistent component while its dependent Derived component remains rejects the whole structural batch before installation.

Candidate restoration first establishes the complete receiving Entity map, then restores every Persistent component value and all of its declared mapped references across the candidate before invoking any component Derived rebuild. Only after that global barrier may rebuilds read their dependencies. `WorldStateRestoreBinding.ReadSameEntity<TDependency>` is valid only for the exact live component-Derived callback, receiving entity, declared dependency/type, registered component, completed Persistent restoration, thread, phase, and callback lifetime. It returns a copied value and grants no other-entity read, query, write, reference, or borrowed storage. System and attachment Restore do not inherit this capability from the shared binding. Wrong-kind active use is sticky misuse; expired use throws only. Revoke the binding in `finally`.

M03-A implementation closure is every real callable root and mutable storage dependency required by its explicitly selected frozen registration. A implements the selected default/access/validation/Read/Count/Write and applicable Restore/derived-rebuild providers; stateful-system, resource and authoritative-attachment factories/storage/access/codecs; fresh nonaliasing World state; mutation invalidation; scope-close and complete-map reference validation; disposal, failure cleanup and retained/quarantined lifetime. These roots are real and compiled/AOT reachable even where their first legal execution is a later operation. A qualifies every applicable non-persistence path through an actual World operation; it does not manufacture callback bindings. Record implementation owner, legal execution prerequisite and execution-observation owner separately. B owns persistence I/O/capture, source and candidate orchestration, State2 candidate restoration, replacement and continuation/playback observations. A-required implementation is never deferred merely because its persistence-dependent observation is B-owned.

The selected CApp1 stateful consumers include `system-counter`, `resource-counter` and `attachment-counter`: system-owned state is not fabricated as Resource access; resource Values count equals registered PartitionCount; authoritative attachment ownership is transferred or edited only through its declared engine-owned scope. Their complete provider roots, fresh storage, mutation/reference rules and lifetime are A implementation work when selected. Public decode/restore and candidate execution remains with its genuine B operation.

## 2. Public operations

Owner-thread immediate `Create`/`Destroy`/`Add`/`Remove`/`Set` are permitted only when no tick/query/job is active. Data and tag Add/Remove operations have typed idle and deferred forms, with explicit-value or declared-default initialization; attachment set/get/removal is owner-thread-only and outside chunk jobs. During a tick, structural changes go through `CommandWriter`; component field writes within admitted query leases are nonstructural. `Has<T>` and `TryGet<T>` check entity owner/generation first; a live entity lacking T is ordinary absence, a stale/cross-world entity is an error, not false.

Every grant of canonical write access first advances the checked canonical mutation revision and invalidates the current committed marker, even if the caller ultimately makes no value change. This includes idle `Set`, mutable component spans, structural transactions, authoritative attachment/system-state edits, PRNG/control/timeline changes, asset activation and replay-relevant frame edits. Caller-retained mutable attachments cannot be authoritative unless their registration provides engine-owned edit scopes or immutable snapshots with a complete persistence/mutation contract; ordinary unregistered attachments are explicitly transient.

The bounded owner-control queue is Entities-owned and admits up to 128 pending structural/control requests. `World.PumpControlBoundary()` drains one bounded accepted batch while idle, with no tick or clock advancement, including while paused/headless. Each participant reserves and preflights its entire operation against current canonical state, then commits without allocation or callbacks; accepted requests execute FIFO and publish receipts only after their visibility point. Pre-cancellation prevents admission; cancellation before commit completes only after reservations/consumers retire; cancellation after commit does not revoke the committed receipt. Frame-change requests have their own pre-admission-only cancellation contract: once accepted, the original operation task cannot be canceled; callers cancel only a separate `WaitAsync` observation. For non-Try `EngineHost.ChangeFrameAsync`, a valid request refused solely because the pending queue is full returns a contextual faulted task, not a receipt or synchronous queue-full exception, and changes no cursor, marker, or candidate state. Other frame-control history/exhaustion/capacity outcomes retain their declared receipt channels. Other queued operations retain their own cancellation/refusal contracts. World replacement/stale owner or entity generations reject before mutation.

Queries declare required/excluded tags/types and read/write access. `World.ForEachChunk<TAction>` and `WorldSystemContext.ForEachChunk<TAction>` take `scoped ref TAction`, with `TAction : struct, IAction<EntityChunkView>, allows ref struct`. `Invoke(scoped EntityChunkView chunk)` receives the borrowed view; generated typed adapters retain this concrete callable type through constrained dispatch. The engine neither copies, boxes nor captures callable state, and state updates remain caller-visible on normal return or exception. Component-column factories and every used generic query/codec instantiation are generated or explicitly registered for AOT; no runtime reflection creates unknown columns or closes generic methods. Source-generated adapters expose `scoped` typed chunk spans plus entity read-only span. A query may not add/remove/create/destroy, recursively perform structural work, await, retain spans/refs, return storage-backed views or call arbitrary engine-native services. Copies of values/handles are legal. All declared accesses are checked against the current system's admission set.

Callback segmentation follows [13](13-jobs-and-frame-pipeline.md#1-ownership-and-worker-admission). When `EntityQueryDescription.Range` is present, each selected populated global plan partition whose archetype matches the query produces exactly one callback, in plan order, and its `EntityChunkView` exposes exactly that partition's physical-row slice. When Range is absent, each matching nonempty physical chunk produces exactly one callback over all populated rows. A present full-domain Range remains partitioned; selected partitions are never coalesced or subdivided at query dispatch, and unselected rows are never exposed. `Entities` and every admitted component span use the same interval and local indices. Filters act on archetype membership, not individual rows. Validate the complete query, requested range and applicable access before resolving a zero-callback selection.

`WorldSystemContext.ForEachResourcePartition<T,TAction>` traverses the registered resource partition domain on the executing thread with the same uncopied `scoped ref TAction` contract; caller-owned ordinary/ref-struct action state remains observable on normal return and exception. Before callbacks, validate the exact live invocation/thread, registered resource identity/type/family, parallel eligibility, actual `PartitionCount`, nonempty valid range, bounds, declared-range subset and access mode. Resource indices are `[0, PartitionCount)`, not component work-plan partitions or worker IDs. Read access permits copied `Read`, not `Write`; Write permits both and invalidates the canonical marker before the first callback. No mutable backing, reference or span escapes. Each view is revoked in `finally`; scope close validates affected values through captured typed dispatch, including exceptional exits. Whole-resource validation occurs at a joined boundary, not concurrently with disjoint writers. Default, revoked, wrong-thread, wrong-mode and wrong-phase view use throws; known active-invocation misuse records its sticky fault before throwing, while expired-control misuse cannot fault a successor or another World. `PartitionIndex` is lifetime-checked. Qualification observes actual zero-inclusive visits and caller-local state, not SystemState or persistence capture.

Every declared live Entity-reference leaf is validated when its component write scope closes. Structural preflight validates projected component and native references against the final sequential shadow membership. The engine validates all authoritative component/resource/system references again after stage-7 playback against the complete new membership and after Extract's permitted writes before immutable publication. A system whose target was destroyed by Structural must explicitly clear/rebind it; silent nulling is invalid. A post-playback reference failure withholds publication and tick advancement under [13](13-jobs-and-frame-pipeline.md), but does not claim rollback of the committed structural batch.

Stable query traversal: archetype key lexicographic GUID order, chunk ordinal, physical row. This is not persistent gameplay entity order; algorithms requiring entity-ID order sort a bounded copied index list explicitly. Version counters catch stale query caches, but a counter is not protection from concurrent mutation. `World` waits for all leased queries/jobs before structural work.

Managed attachments use the typed `SetAttachment<T>`, `TryGetAttachment<T>` and `RemoveAttachment<T>` overloads in [30](30-public-api-review-surface.md). The overload without an Entity addresses World scope; the Entity overload addresses Entity scope and validates the live same-World handle before table access. Entity scope records the owning Entity's stable persistent ID, copied before membership revocation; that owner is distinct from any Target reference inside the payload. Operations are owner-thread-only while the World is idle, nonfaulted and outside active ticks, queries and jobs. Invalid default, stale or foreign Entity handles throw; they are not ordinary absence.

`AttachmentOwnership` has only `CallerOwned=1` and `Transferred=2`; zero and every other value throw `ArgumentOutOfRangeException(nameof(ownership))`. Null payloads throw `ArgumentNullException(nameof(value))`; null is not removal. TryGet returns false/null and Remove returns false only for absence on a valid target. Admission, validation, authority and cleanup failures throw, never return false.

Ownership is selected by frozen `(scope,T)` registration. Transferred installation requires the exact registered authoritative binding; a missing registration throws `InvalidOperationException`. CallerOwned installation is allowed only when that scope/T has no authoritative registration; a conflict throws `ArgumentException(nameof(ownership))`. Neither request silently changes ownership or falls back to a transient installation. CallerOwned values remain explicitly transient: the engine does not release or dispose them, their mutable state is neither canonical nor saved, and removal/destruction only detaches the table reference. Transferred values use immutable approved value graphs and their registered State2 provider; mutable authoritative edit scopes are a separately reviewable future surface, not part of this contract.

The installed table key is `(target scope/owner, frozen attachment registration)` for authoritative values and `(target scope/owner,T)` for unregistered transient values. There is one authoritative value per key. Ownership transfer linearizes at the allocation/callback-free storage commit. Before commit, failure preserves old storage and caller ownership; after commit, replacement/removal remains committed despite cleanup failure. Every transferred installation has a distinct checked positive installation ID/control, even when replacement uses the same immutable object. Shared immutable payload objects do not share installation authority or release obligations.

Release runs exactly once for each detached transferred installation after storage commit and outside locks. It releases that installation's obligations without disposing or destructively mutating a shared immutable payload; there is no implicit `IDisposable` call or automatic retry. A complete bounded release report is `WorldAttachmentReleaseException`; a report-finalization failure uses the separately prepared `WorldAttachmentReleaseReportFinalizationException`. Both preserve committed storage and continue safe cleanup exactly once. Retained authoritative values remain readable after removal or World disposal but grant no lease or mutation authority; copied Entity handles may subsequently be stale.

Every engine invocation of an attachment field reader or provider runs under an engine-owned, same-World nonreentrant boundary tied to the exact World lifetime and containing operation. The boundary is established before application code and remains active through unwind; no lock is held across the callback. While active, no independent public operation may mutate attachments or canonical state, grant write access, apply structural/control work, pump an owner boundary, start Step/replacement/disposal, or prepare/admit capture, extraction, queries or other callback/live-storage authority against that World. This includes indirect and task-returning frontends and cannot be bypassed by a fresh binding, wrapper, queue or async path. Already-admitted private engine dispatch for the containing operation remains permitted.

Read-only `TryGetAttachment` remains subject to owner-thread, idle/nonfaulted/lifetime and Entity-validity checks and invokes no application code. During precommit installation validation it observes the currently installed value, not the proposal; during legal idle postcommit Release it observes committed replacement/removal. It cannot expose detached storage or revive a destroyed Entity. Existing phase/lifetime checks still forbid idle lookup during Step or disposal.

## 3. Deferred transactions

Each command has key `(stageOrdinal,systemOrdinal,partitionOrdinal,localSequence)`. `Stage`/system ordinals are stable registered integers; partitions derive from ordered chunk/range IDs, not worker thread IDs. Worker completion race is irrelevant. Local sequence is monotonic per writer. Buffer overflow fails the producer; no truncation.

`Create` returns a temporary `EntityToken` bound to world, writer, barrier epoch and local ID. A token can be used only by that writer in its subsequent commands; cross-writer references require an already-live entity or next-barrier receipt. After successful playback a `CommandReceipt` maps token -> `Entity` or `Canceled`. Tokens never masquerade as live entities.

In these rules, “writer” means the engine-issued logical writer-prefix domain for the exact World/binding and tick/barrier, as defined in chapter [13](13-jobs-and-frame-pipeline.md); it does not mean CLR receiver-object identity. Repeated queries selecting the same applicable prefix share its sequence and earlier-Create records. Different query partitions and outside-query calls retain their distinct prescribed prefixes. Copying a receiver reference grants no additional authority, and matching numeric prefix/key values alone does not establish the issued domain. `EntityToken.IsValid` reports intrinsic issued representation only, not current authority, membership or projected liveness. Default is invalid; an issued token may remain intrinsically valid after cancellation or playback. Invalid token arguments to a live writer and use of an expired writer receiver follow chapter 13's separate fault-routing rules.

Every deferred `Destroy` supplies `HierarchyDestroyMode`; the live-entity and same-writer-token forms preserve that exact value from capture through structural projection and playback. Each original destruction owns an anchor at its command position and reaches exact-prefix expansion before candidate-map freeze. `DestroySubtree` expands descendants-first in stable child order before that anchor; generated descendants keep the original request anchor and mode, are not recursively expanded, and add no application command, sequence, receipt or identity assignment. `DetachChildrenKeepWorld` destroys only the target and validates each direct child's resulting root pose under chapter [16](16-scenes-transforms-and-cameras.md)'s spatial/SRT rules. Temporary-token destruction retains its selected mode and anchor in the admitted trace while creation/component edits cancel; it fabricates no destroyed identity. A surviving reference to a canceled token still rejects the complete batch.

Tokens are not Entity references and cannot be written into an Entity-typed component field by generic `Set<T>`. Any token-relative typed reference must use its declared command form and is resolved only against the complete projected shadow set before identity assignment.

`Destroy` of the same writer's uncommitted token cancels its creation and component edits. Remaining commands referencing a canceled token fail validation; no invented `null` parent/target. Two destroys of a live entity in one ordered batch are an error on the second; do not silently coalesce. `Add`-existing/remove-missing are errors; `Set`-existing is last ordered write wins. All identities/types/hierarchy/native integration changes are validated against a sequential shadow model.

Token issuance/World/prefix/barrier validation at append does not establish projected entity liveness. If a same-prefix temporary `Create` is canceled by an earlier successfully admitted `Destroy`, later commands may not use that token; such an append is refused under chapter 13's live-writer argument-fault rule. A reference admitted before a later cancellation or destruction is checked against the complete sequential shadow and final receiving map and rejects the complete structural batch if still invalid. No reference is silently nulled or discarded. A refused append consumes no sequence. An admitted append consumes its ordinary sequence even if later structural preflight rejects the batch; retain its admitted trace/key. Cancellation, discarded edits, receipts, structural storage and identity assignment retain their existing atomic preflight rules.

An engine-produced successful `CommandReceipt.DestroyedEntityIdentities` is an initialized immutable copy of the already-issued qualified identities actually destroyed by that receipt's deferred writer/barrier commands, in their receipt-local subsequence of effective structural destruction order. Descendants belong to the original request's receipt. Empty means no live identity was destroyed; cancellation does not fabricate an entry. A failed operation has no successful receipt or empty success-shaped substitute. The vector contains no live handles, storage views, World reference or asset pins and grants no membership or mutation authority. Prepare and account the complete vector before installation; it is observation data, not another command stream or checkpoint input. A caller may retain it as ordinary immutable application-owned managed data; that retention does not pin mutable World storage. It proves reported structural order, not physical cleanup-dispatch order or a global ordering across receipts.

Each successful Step groups commands into one `CommandReceipt` per nonempty admitted logical writer-prefix/barrier, ordered by stage, exact signed registered `SystemOrder`, then `WriterPartition`. Repeated calls selecting the same prefix share its receipt; an all-canceled prefix still has a receipt. Unused writers, refused appends and generated descendants create none. Every admitted Create token belongs to exactly one group, including when that Create is later canceled.

The C30 `CommittedWorldPublication.GetCommandReceipt` lookup accepts a Create token from any group/barrier in that publication, including a canceled Create, and returns the exact owning object in its `CommandReceipts` array. A token from another group in the same publication resolves to that other group. Default/unissued, foreign-binding, another-publication, or non-Create tokens throw `ArgumentException(nameof(token))`. `CommandReceipt.TryResolve` accepts only a Create token belonging to that exact group: it returns true and the originally assigned Entity for a surviving Create, or false and exactly default Entity for a canceled Create. A token from another group/barrier, even in the same publication, is invalid for `TryResolve`. Neither lookup consults current World membership; their historical answers remain stable after destruction, slot reuse, later Steps and disposal. A lookup argument exception is not recorded as a sticky fault against an ambient invocation, and an out value on a throwing call is not an observation.

Preflight the entire batch, reserve all columns/slots/physics registrations/asset leases, then commit without new allocations or user callbacks. Failure releases reservations and changes no structural storage; report command key, entity/token and reason. Physical integrations enlist in this transaction; no entity published with a missing required body/asset attachment. Receipts become observable only after complete commit.

Arbitrary component writes performed earlier in a tick are not automatically journaled. A failing system/barrier faults the world; no tick index increment, event/render/audio publication or capture from that world is permitted. The stage-9 committed marker records the exact canonical mutation revision. Capture/extraction requires a nonfaulted idle world whose current revision matches an existing committed or restored marker; a new World is not capture-eligible until its first successful tick. Restore installs a coherent marker after validation/cache rebuilding without an extra tick. Recover by restoring a committed checkpoint into a new world. Do not claim whole-world rollback because structural preflight is atomic.

## 4. Lifecycle and persistence

`Entity` destruction first revokes membership/handles, removes hierarchy membership and queues physics destruction/contact-end effects, detaches resources, then releases rows. Destruction does not recursively destroy children by accident; chapter [16](16-scenes-transforms-and-cameras.md) owns explicit hierarchy modes. User callbacks see committed storage and copied event payloads only. `World` disposal joins jobs, closes writers, removes native integrations, cleans attachments and returns pools in that order.

Replacement restore constructs an invisible candidate with one fresh Core-issued process owner ID; saved stable GUIDs and applicable slot/generation metadata do not confer old runtime ownership. Candidate validation failure before issuance leaves the allocator untouched; failure after issuance retires candidate resources but burns that ID and leaves the active World unchanged. Owner IDs remain absent from canonical persistence bytes. Prefab/save references use stable scene entity GUIDs remapped to new `Entity` handles during atomic instantiation/load. `Standard` saves may repack storage; `StrictLocal` snapshots preserve chapter [27](27-state-serialization-replay-and-recovery.md)'s traversal/allocator metadata because query partition/reduction order is observable. `Process`-local type IDs and owner IDs are never persisted identities. Registering different types with the same schema GUID is a startup error; changing fields requires a new schema version/migration. Hashes serialize named fields in schema order with canonical representation, never raw `unmanaged` memory.

Acceptance obligations: value/ref-struct callable dispatch and negative span-escape consumers; caller-visible state and fault cleanup without boxing/delegate capture; generated closed column/query registrations; default/stale/cross-world/retired IDs; tag/no-column behavior; capacity 1 and oversize; swap-remove index repair; query access/escape/structural rejection; identical playback across worker counts; temporary cancellation/reference refusal; all-or-nothing reservation failure; attachment cleanup; saved reference remapping. `Cross`-system expected outcomes appear in [34](34-engine-acceptance-cases.md).
