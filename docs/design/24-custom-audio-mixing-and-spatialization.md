# Custom audio mixing and spatialization

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

The engine owns decoding/import validation, voice state, buses, mixing, spatialization, sample-rate conversion, streaming, and WASAPI/PipeWire output adapters. [08](08-binary32-kernels-and-predicates.md) owns the binary32 headroom/filter/cursor profile; this is not an external audio-engine specification.

The independent `TerraFX.Audio` library/package depends on Core/Assets, never Runtime; entity/scene/host composition belongs to Runtime's `TerraFX.Integration` namespace. Consolidating that adapter does not change mixer clocks, owner contexts or endpoint admission.

## 1. Clock, format, and fixed defaults

The mixer clock is independent of host frames, simulation ticks, and the output device's native sample rate. Its epoch starts at sample-frame index 0 and advances only when the mixer produces output frames for a running endpoint. A frame is one instant containing one value per channel; a stereo frame contains two scalar channel samples. Public scheduled positions, buffer lengths, and latency measurements are in **frames**, never ambiguously in scalar samples.

| Contract | Version-one default |
|---|---|
| Internal sample rate | Exactly 48,000 frames/second; not silently changed to match an endpoint |
| Internal layout | Interleaved stereo IEEE-754 `float32`, linear amplitude |
| Maximum voices | 256 active voices per mixer |
| Maximum streaming voices | 32, independently included in the 256-voice limit |
| Maximum buses | 64, rooted at one `Master` bus |
| Maximum mix block | 256 frames (5.333... ms at 48 kHz); backend requests larger than this are processed as bounded consecutive blocks |
| Maximum native buffer | 8,192 frames per negotiated endpoint buffer/callback; larger native buffers are refused before processing |
| Reliable command queue | 1,024 accepted-but-unacknowledged commands |
| Endpoint recovery | Retry the selected endpoint with 250-ms initial, doubling to a 5-second maximum; never switch endpoint/backend silently |
| Default stop fade | 64 frames |
| Steal fade | 64 frames |
| Maximum voice/bus/master gain | 4.0 linear per node |
| Default master/bus/voice gain | 1.0 linear |
| Default pitch | 1.0 playback-rate ratio |
| Default 2D pan/balance | 0.0, center |

All public floats must be finite/in range. Imported NaN/infinity or amplitudes outside `[-16, +16]` reject. Voice samples, bus accumulations, gains, coefficients and filter states are binary32. Each bus/master has frozen `MaximumGain` in `[0, 4]`, default 4; current/ramp gains cannot exceed it. Every contiguous voice-input-bus-to-ancestor ceiling product, including the input bus itself, must be <= 65536; downstream attenuation cannot conceal unsafe upstream intermediates. [08](08-binary32-kernels-and-predicates.md) defines the resulting finite headroom including rounding and graph-history replacement. After Master/crossfade processing only, clamp output to `[-1, +1]`; clipping/meters remain observable. No intermediate clipping or required FP64 substitutes for this admission.

An audio operation that targets a sample frame uses `long AudioFrameIndex`. The next frame to be mixed is observable. An untimed accepted command targets the first not-yet-mixed frame when the real-time consumer admits it; it is not rounded to a later full-block boundary. At submission, explicit scheduled frames earlier than the observed next frame are rejected as `InPast`; frames farther than ten minutes ahead are rejected as `OutOfRange`. If a scheduled target becomes earlier than the consumer's next frame before admission, the receipt is rejected as `MissedDeadline` and the operation is never retroactively applied. Arithmetic is checked; sample-index exhaustion faults the mixer instead of wrapping. A simulation pause does not pause audio or the output sample clock. When the endpoint is suspended/lost, the audio sample clock freezes and resumes at the same index after successful endpoint reconstruction; it does not silently consume voices into inaudible time.

## 2. Owned API and asset/import contract

`AudioOutputMode` is `NotRequested`, `Native`, or `Offline`; `AudioEndpointBackend` is `Wasapi` or `PipeWire`. `AudioEndpointOptions(backend, endpointId)` names that backend and an opaque string endpoint ID, with null selecting its current default. It never selects another backend/endpoint after loss. `AudioMixerOptions(outputMode, endpoint)` requires endpoint options exactly for Native and forbids them otherwise. Native validates platform/capabilities before opening; Offline creates no device and NotRequested does not mix.

`AudioMixer.CreateAsync(options, cancellationToken)` returns an independently owned mixer only after configuration/native startup is complete, or faults with actual initialization context. Owner/control setup keeps COM/device work on its proper thread; awaiting the task confers no affinity. Offline `RenderFrames` drives the same admitted mixer without a native callback and has serialized single-consumer admission, not caller-thread affinity. Host convenience creation delegates to this contract; destroying a host does not silently invalidate an independently owned mixer.

Public entry points are `AudioMixer`, `AudioAssetStore`, `AudioBusHandle`, `AudioClipHandle`, `AudioVoiceHandle`, `AudioDeviceSnapshot`, and immutable `AudioCommandResult`/`AudioEvent` records. A mixer owns its output adapter; host convenience creation transfers the independently owned mixer to its caller; callers do not receive an `IAudioClient`, `pw_stream * `, endpoint buffer pointer, or a callback into entity-component-system (ECS). Every handle has nonzero `OwnerId`, `Index`, and `Generation`; all-zero is invalid. Clip/bus/voice handles from another mixer or stale generations fail explicitly.

The task-returning convenience methods are PlayAsync, StopAsync, StopAllAsync, SetBusGainAsync, SetBusCutoffAsync and ReplaceBusGraphAsync. Play/Stop below also name command kinds, not synchronous facade members. Final cancellation tokens on ordinary async methods default to default; required options/requests remain explicit. Usage/mode/ownership errors throw synchronously, pre-cancellation of a request with a cancellation token returns a canceled task before admission, queue saturation faults non-Try tasks, and accepted commands retain the application/voice/native-completion boundaries below.

TryGetBusHandle takes a nonempty bus Guid and returns a nonnullable value handle: true supplies a valid same-mixer bus, false means only an unknown bus identity and sets the output to invalid default. Disposed owners or invalid identities throw; no NotNullWhen annotation or nullable-handle dereference is needed.

DeviceSnapshot is a cheap read of the latest control-published immutable AudioDeviceSnapshot, not a fresh histogram allocation or event drain. Control publishes at most once per 100 ms observation interval while running, and after control processing of an endpoint-state transition; a stalled control owner may leave the last observation stale. No getter waits for the consumer/control thread, promises an atomic live query, or allocates/locks in engine code. Histogram buckets and counters are copied at publication and never recycled beneath retained readers; snapshots remain readable after mixer disposal. Use command completion/VoiceEnded for exact lifecycle observations, not snapshot freshness.

`AudioMixerOptions` fixes `SampleRate = 48000`, `OutputChannels = 2`, `MaxVoices = 256`, `MaxStreamingVoices = 32`, `MaxBuses = 64`, `MaxBlockFrames = 256`, `CommandCapacity = 1024`, `StopFadeFrames = 64`, and `StealFadeFrames = 64` by default. `CommandCapacity` and its outstanding-credit limit are fixed at 1,024 in version one; the ingress ring, schedule calendar, and acknowledgement ring are allocated to that bound before playback and cannot be configured smaller/larger. `EndpointRecovery` defaults to retrying the same selected endpoint after 250 ms, doubling to a five-second maximum; no fallback endpoint/backend is selected. Other capacity overrides are validated before allocations and frozen at creation; internal rate/layout are not configurable in version one. Endpoint rate/layout/format are negotiated independently and always appear in `AudioDeviceSnapshot`.

The importer owns file parsing and codec integration:

 * Required source formats are pulse-code modulation (PCM) WAVE (`RIFF/WAVE`, integer PCM 8/16/24/32-bit or IEEE float32) and Ogg Vorbis. Imported mono/stereo assets decode to immutable finite float32 PCM or to an owned streaming decoder. Supported source rates are in the closed interval `[8,000, 192,000]` Hz. Only one or two source channels are accepted; other channel counts/layouts fail with `UnsupportedChannelLayout` rather than being silently downmixed.
 * PCM WAVE 8-bit samples are unsigned and map as `(sample-128)/128`; signed integer PCM n-bit maps as `sample/2^(n-1)`; IEEE float32 is preserved after finite/range validation. Resident decoded float32 data is capped at 256 MiB per clip; longer content must use streaming. Streaming duration is at most 24 hours per asset, checked from codec metadata and decoded frame count. Reject oversized assets before registering or allocating their full decoded size.
 * RIFF parsing honors the declared container extent, checked chunk sizes/alignment, arbitrary `fmt`/`data` chunk order, and `WAVE_FORMAT_EXTENSIBLE` only when its valid bits/channel mask describe mono or stereo. Truncated, contradictory, unsupported compressed WAV, invalid channel masks, and oversized assets fail before registration. The importer rejects malformed/truncated Ogg/Vorbis streams; it does not reinterpret corrupt data as silence or successful EOF.
 * Ogg Vorbis uses a pinned decoder/version and a reviewed permissive license or an engine-owned implementation. The implementation records codec provenance/version/license in the asset build manifest/SBOM; GPL-only or otherwise incompatible codec code is not an implicit runtime dependency. Import-time decoding is outside the real-time path.
 * Decoded assets own their backing storage until all voices and streams release their leases. A caller may release its clip handle after a successful Play acceptance; the engine retains the asset/stream until the voice and any fade tail end. Asset reload creates a new immutable version; it never mutates sample memory being read by a voice.
 * Resident clips are imported into 48-kHz mono/stereo float32. For N source frames at source rate R, the converted frame count is `ceil(N * 48000 / R)` using checked integer arithmetic; output frame j uses the exact integer quotient/remainder of `j * R / 48000`, interpolating adjacent frames and clamping the final neighbor to the last input frame. Resident and source-rate streaming voices retain a nonnegative `long` whole-frame cursor plus a 64-bit fractional numerator. Configuration converts `sourceRate * pitch / 48000` once to the nearest-even integer/fractional step under [08](08-binary32-kernels-and-predicates.md); processing never accumulates a growing float frame number. At end-of-clip the final source sample is held only for interpolation, then the voice ends; looping wraps the interpolation neighbor to frame zero and preserves phase. A fractional conversion rounding to one samples the next frame at fraction zero without changing canonical cursor state. This bounded linear resampler is the version-one quality/performance contract; no claim of band-limited resampling is made.
 * Each stream has a 16,384-source-frame ring and a 4,096-frame low-water mark by default; the real-time consumer never waits for I/O or a decoder. Ordinary import/refill/control orchestration uses bounded `Channel<T>` queues and `Task` workers outside the audio path. The refill channel holds at most 32 queued requests, uses wait/backpressure rather than drop mode, and has at most one in-flight decode request per stream. A stream underrun emits `AudioStreamUnderrun`, outputs zero for unavailable voice frames, and freezes that voice's source cursor for those frames so it does not jump over unheard content. Refill/decoder corruption/end-of-stream are distinct events. A corrupt stream terminates that voice with a failure result.

No native codec/digital signal processing (DSP) callback may run in the output process callback. Codec selection is part of asset import, and the audio engine owns validated decoded buffers/stream state.

## 3. Voice, command, and lifetime semantics

`PlayAsync(AudioPlayRequest)` accepts an immutable request: clip handle, 2D/3D mode, target bus, gain, pitch, priority, loop flag, optional `ScheduledFrame`, and (for 2D) pan. Gain is finite `[0,4]`; pitch is finite `[0.25,4]`; pan is finite `[-1,1]`; priority is byte `[0,255]`, default 128. Default loop is false. Play, `Stop`/`StopAll`, bus gain/cutoff changes, and validated bus graph changes all carry the same optional `ScheduledFrame`; absence means untimed. Each request copies its scalar data and owned graph/version references and takes its own asset lease before acceptance. The caller cannot mutate a request object or reclaim source bytes to alter a queued command.

Play/`Stop`/bus changes are reliable, independently owned audio commands:

1. Any number of ordinary producer threads may submit. A short producer-side lock serializes the validated command, assigns a monotonic `AcceptanceSequence(exhaustion throws/faults admission, never wraps)`, and writes one preallocated SPSC ring; the real-time consumer never takes that lock. A shared 1024-credit pool covers ingress/calendar/acknowledgements until control reclamation. `TrySubmit(AudioCommand, out Task<AudioCommandResult>? completion)` uses `NotNullWhen(true)`: true atomically accepts/owns the command and supplies its completion; false means only `QueueFull`, leaves completion `null` and has no side effect. Invalid arguments/foreign ownership/disposed mixer throw before admission. Callers retry or surface false; no Play/`Stop` is silently dropped, overwritten or merged.
2. Before mixing, the consumer drains admitted ring entries into a fixed-capacity 1,024-entry binary min-heap calendar allocated by `AudioMixer` construction. No `PriorityQueue` or storage grows on the real-time path. Heap order is `(TargetFrame, AcceptanceSequence)`. An untimed command gets `TargetFrame = nextFrameToMix` at consumer admission. A scheduled command whose target is now earlier than `nextFrameToMix` is completed as `Rejected(MissedDeadline)`; it is not retroplayed. The heap cannot exceed capacity because every ring/calendar/ack entry retains one of the shared 1,024 credits.
3. A render block is at most 256 frames. The consumer applies due commands at their exact target frame, mixing up to (but not including) an interior target, applying all commands at that frame by acceptance sequence, then mixing the remainder. Thus target `F + 17` splits a block starting at `F` after exactly 17 output frames. A future Play at `F + 1000` cannot head-of-line block an untimed `Stop` admitted at the current frame or another earlier-target command.
4. The output consumer writes a fixed-size completion record to a second preallocated SPSC ring. At most 1,024 commands can be outstanding, so the completion ring cannot overflow if credit reclamation is correct. A non-real-time control thread drains completions and completes `Task<AudioCommandResult>` receipts there with asynchronous continuations; no task continuation or user callback executes on the audio consumer.
5. Accepted means the request/asset are owned. `AudioCommandResult` is a dedicated immutable receipt with Status enum Applied/`Rejected`/`Canceled`, acceptance sequence, target frame, command kind and applicable reason/voice/completion-kind metadata, not a generic result or C# union. Nonempty applied Play supplies the valid new voice handle; empty Play has `CompletionKind` `EmptyClipCompleted` and no voice/slot. `Rejected` represents expected application-time voice/binding/deadline conditions; terminal `Canceled` acknowledges accepted-command shutdown. Unexpected mixer/invariant failure faults the `Task` on the control thread after safe lease reclamation, never throws through the processing callback. Applied `Stop` means fade scheduled, not last sample played; separate `VoiceEnded` carries terminal reason/frame.
6. If the command queue is full, critical `Stop` is not magically accepted or given a hidden priority lane. `TrySubmit` returns false/`null` completion for `QueueFull`; non-Try Play/`Stop`/`StopAll` fault their `Task` with contextual `InvalidOperationException` on admission overflow. Callers anticipating saturation use `TrySubmit` and remain responsible for retrying. No stop is accepted then silently lost, overwritten or reordered to make room.

`AudioVoiceHandle` is a named `OwnerId`/`Index`/`Generation` value, with generation increment on reuse/retirement before wrap. It survives endpoint replacement because mixer identity is separate. Foreign/default/stale handles supplied at synchronous admission throw the established ownership error; a handle valid at acceptance but ended/stolen before scheduled application receives the domain `Rejected(StaleHandle/NotFound)` receipt and changes no other voice.

At 256 active voices, stealing is deterministic: among voices with priority strictly less than the incoming request, select lowest priority, then oldest start sequence, then lowest slot index. If no eligible victim exists, reject as `VoiceLimitReached`; equal priority does not steal. A steal immediately installs the new voice and moves the old source/lease/state into a preallocated 64-frame tail. If all 32 tail slots are occupied, reject the new Play as `VoiceLimitReached`; do not truncate a voice without a fade. The old handle becomes stale at the steal boundary and receives a `Stolen` end event when its tail is complete. Tail exhaustion, voice exhaustion, and queue exhaustion have distinct counters/results.

Natural/faded/stolen endings enqueue one retirement record per voice/tail into a preallocated 512-slot SPSC backing ring. Semantic credits remain 256 voices plus 32 tails, at most 288 pending records; spare backing slots do not add voices. Retiring slots cannot be reused until control drains records/releases leases/returns credits. No disposal/pool return/user continuation occurs on the processing path. Each slot contributes at most one record, proving capacity. Without a free voice an eligible victim may be stolen only if a tail is available; otherwise Play rejects explicitly. Empty completion uses its existing command credit.

The control thread delivers reliable `VoiceEnded` results outside native callbacks. Each voice's completion observation is independently available even if diagnostic/event subscribers are slow; bounded telemetry may coalesce/drop only with counters and cannot erase that completion. Disposal quiesces processing, drains acknowledgements/retirements and completes remaining voices/tickets with explicit terminal reason before releasing storage.

`StopAsync(handle, fadeFrames, scheduledFrame)` defaults 64 fade frames and no schedule; an untimed zero-frame stop applies at admission. Nonzero fade is linear from current amplitude to zero over exactly that many frames starting at target. `SetBusGainAsync(bus, gain, scheduledFrame)` ramps over 64 frames; validated graph/cutoff changes likewise apply atomically at target. Synchronously invalid/stale `Stop` throws; accepted-then-ended produces the explicit `NotFound`/`StaleHandle` rejection above, never a second successful stop. A scheduled fade/stop is not confused with its applied acknowledgement.

## 4. Mixer graph, DSP, channels, and spatialization

The bus graph is a rooted acyclic tree with one Master, at most 64 buses, one parent per nonroot and one destination per voice. Control validates cycles, capacities and every contiguous upward gain-ceiling segment before atomic scheduled publication; `GainPathBudgetExceeded` refuses an over-budget route. Stable pairwise binary32 summation precedes gain/optional low-pass at each bus. No feedback sends, arbitrary DSP callbacks or per-voice graph allocations exist. Structural reparent/replacement resets graph filter histories, emits `AudioGraphStateReset`, and crossfades the last old pre-clamp stereo output into the new graph for 64 frames under [08](08-binary32-kernels-and-predicates.md). Cursors do not reset; unchanged-tree gain/cutoff ramps retain histories.

Version-one DSP blocks are Gain, EqualPowerPan and OnePoleLowPass. Cutoff is finite in `[20, 20000]` Hz. Compute binary32 `s = float.Sin(float.Pi * cutoff / 48000)` and `a = 1 / (1 + 2 * s * s + 2 * s * float.Sqrt(1 + s * s))`, avoiding small-angle cancellation. Qualify `a` in `[0, 0.999]`; each channel uses `y[n] = (1 - a) * x[n] + a * y[n - 1]`. This is the one-pole -3 dB cutoff. Gain/coefficient ramps span 64 frames. HRTF, ambisonics, convolution/reverb, Doppler, occlusion, user DSP, capture, MIDI and exclusive output remain excluded.

Channel mapping is fixed:

 * A mono 2D source has `L = s * cos(theta)`, `R = s * sin(theta)`, `theta = (pan + 1) * pi / 4`, then voice gain. Center yields equal-power `sqrt(1 / 2)` gains. A stereo 2D source preserves left/right at center. Its pan is balance: positive pan attenuates left by `cos(pan * pi / 2)` and leaves right unchanged; negative pan attenuates right by `cos(-pan * pi / 2)` and leaves left unchanged.
 * 3D requires mono; stereo requested as3D rejects explicitly. Emitter/listener poses use [03](03-shared-conventions-and-clocks.md)'s left-handed (LH) axes and the frozen distance units, with identity right/up/forward = +X/+Y/+Z. Pose/basis must be finite. Derive an oriented frame by rotating `UnitX`/`UnitY`/`UnitZ` with the listener quaternion; supplied basis must be orthonormal within 1e-3 and match its orientation, including numerical `cross(right, up)` = forward, or extraction rejects. Emitters use the latest snapshot for their audio world. A positive +Z source is ahead of the identity listener, not behind. Pan remains `dot(direction, right)`, so +X is right-channel biased in either backend; no endpoint adapter applies another Z reflection.
 * 3D panning computes normalized direction from listener to emitter, `pan = clamp(dot(direction, listenerRight), -1, + 1)`, and the same equal-power stereo law as mono 2D. At zero distance pan is zero. No elevation/HRTF filtering is claimed.
 * 3D inverse-distance attenuation has finite `r > 0`, `m > r` and `q >= 0`: zero for `d >= m`, one for `d <= r`, otherwise `r / (r + q * (d - r))`. Physical defaults are `r = 1` meter, `m = 100` meters and dimensionless `q = 1`, converted once to the selected unit. Spatial integer-cell bounds reject only provably distant sources; nearby displacement uses [07](07-spatial-coordinates-and-indexing.md)'s seam-aware float arithmetic and scaled finite norm. Validate dimensional/intermediate representability and admitted range before snapshot publication; no global-double subtraction is required.
 * Internal output is stereo. For a negotiated mono endpoint, adapter output is `(L + R) * 0.5`. For multichannel output, front-left receives L, front-right receives R, and all other channels (including center/LFE/surround/top) are zero. Channel order/mask is taken from the negotiated endpoint; unknown layouts fail negotiation instead of guessing. There is no implicit stereo-to-multichannel spatial decoder.

The importer records the original source sample rate; resident clips are represented to voices as 48-kHz data and streaming sources retain their decoded source rate. Pitch scales source-frame advance. Empty clips are valid, complete immediately at their scheduled frame, and do not consume an active voice. Nonempty loops require at least one frame. All sample offsets/counts use frame units and checked arithmetic.

## 5. Real-time boundary, scheduling, underrun, and endpoint loss

Managed .NET is not a hard-real-time runtime. The engine promises bounded engine work and no application-controlled blocking on the audio process path; it does not promise that the garbage collection (GC), operating system (OS) scheduler, compositor, driver, or endpoint can never pause.

Before opening an endpoint, create/preallocate voices, bus state, mix/conversion scratch, SPSC rings, stream rings, completion slots, and callback state; warm every process-path code path; retain/root native callback entry points and buffers for the entire endpoint lifetime. Persistent sample/ring memory is not reclaimed until the callback has quiesced and the device epoch has advanced. Steady-state output processing performs no managed allocation, lock acquisition, blocking wait, file/network I/O, `Task`/Channel operation, user delegate, LINQ, or decoder call. No application callback is invoked from WASAPI/`PipeWire` processing. Do not call `GC.Collect` on the audio thread. The host may configure and report its documented GC latency mode outside playback but must not claim it eliminates pauses or mutate a process-global mode without an explicit host policy.

 * **WASAPI:** A dedicated audio/control thread initializes Component Object Model (COM) as MTA before enumerating/opening endpoints and releases those COM objects before `CoUninitialize`. Open the default or explicitly selected endpoint in shared mode. Query `IAudioClient::GetMixFormat`; initialize `AUDCLNT_SHAREMODE_SHARED` with `AUDCLNT_STREAMFLAGS_EVENTCALLBACK`, set the event handle, query actual buffer size, and wait for the event on a dedicated audio thread registered with Windows Multimedia Class Scheduler Service where available. On each wake, use current padding/buffer frames and `IAudioRenderClient::GetBuffer/ReleaseBuffer`; do not assume a fixed 10-ms buffer or mix-sample count. Convert/resample the engine's 48-kHz stereo stream to the exact negotiated mix rate, format, and channel mask with persistent phase/state. Event/endpoint invalidation is reported with the HRESULT and device epoch.
 * **`PipeWire`:** Connect directly to the `PipeWire` server with an output/PLAYBACK `pw_stream`, advertise supported raw formats, set audio media type/category/role properties, request `PW_STREAM_FLAG_AUTOCONNECT | PW_STREAM_FLAG_MAP_BUFFERS | PW_STREAM_FLAG_RT_PROCESS`, and accept only the negotiated sample rate, format, channel positions, stride, and available buffer extent. Negotiate buffer sizes no larger than 8,192 frames. `param_changed`/buffer renegotiation happens on the non-real-time control loop and publishes immutable converter configuration before the process callback uses it. The process callback dequeues/fills/queues the supplied buffer; it never assumes tutorial/default rate, channel count, or frame count. If `PipeWire` is unavailable, the capability is unavailable; do not silently route through `PulseAudio` or ALSA.
 * Both adapters accept negotiated float32 or signed PCM16/24/32 with recognized channel layout. `Unsupported` format/layout is a start/reconfigure failure. Reject a negotiated buffer larger than 8,192 frames rather than allocating or processing an unbounded request. Integer conversion clamps first and rounds to nearest-even, using the signed negative scale `2^(bits-1)` and positive scale `2^(bits-1)-1`, then saturates to the representable range. Rate conversion is linear interpolation with phase retained across native buffers; no per-buffer reset/drift is permitted.
 * A native output buffer not supplied on time is an observable underrun with endpoint frames/time and a counter. The engine writes silence only when the backend contract requires a valid buffer to be released; it also raises `AudioUnderrun` and never reports those frames as audible successful playback. A lost/disconnected endpoint stops submission, quiesces callbacks, increments `AudioDeviceEpoch` once when the old endpoint lifetime is invalidated, and reports the native cause. The sample clock freezes while no endpoint is running. Accepted commands/assets remain owned and pending; new commands may use remaining queue credits while suspended but do not receive an `Applied` receipt until the endpoint resumes. Each failed retry is observable. The next successfully opened endpoint uses the already-incremented epoch; it does not `double`-increment for the same invalidation. Preserved voices resume at the frozen clock. If shutdown wins, accepted commands receive terminal `Canceled` receipts.
 * `PipeWire`'s process callback is native/real-time initiated; no exception may unwind through its application binary interface (ABI). The interop boundary catches a process-path fault, latches a preallocated fault record, stops normal mixing, fills only the remaining valid output extent with silence when safe, and notifies the control loop to fault/stop the stream. It never swallows the error as healthy playback. WASAPI thread exceptions follow the same explicit engine-fault result.

`AudioDeviceEpoch` is 0 before an endpoint opens and 1 for the first successfully opened endpoint. `AudioDeviceSnapshot` reports the requested/actual endpoint, backend, device epoch, endpoint rate/channels/format, output period/buffer frames, estimated queued latency in seconds as `converterPendingFrames / 48000 + endpointPaddingFrames / endpointRate + reportedEndpointPeriodSeconds`. The converter-frame count is divided by the 48,000-frames-per-second mixer rate; endpoint padding is divided by the negotiated endpoint rate in frames per second; the reported endpoint period is already in seconds. The snapshot also reports a process-duration histogram, clipping, stream underruns, and the last diagnostic. Hardware/DAC latency unavailable from the OS is separately `Unknown`; it is not added as an invented measurement. A 48-kHz internal clock does not imply a 48-kHz endpoint. Device loss does not invalidate voice handles; destroying the mixer does.

## 6. Transform extraction and cross-system ownership

Public positions use dimensional spatial values; velocities/bases use [06](06-owned-geometry-and-numerics-interchange.md)'s owned geometry. Interchange does not normalize a listener frame, reflect +Z or supply units. Admission stays on the control/extraction boundary; processing uses preadmitted sample/scalar storage without allocating wrappers.

After final structural commit, the host extracts a bounded immutable `AudioWorldSnapshot`: listener basis and current emitter poses/velocities per audio world, tagged with world/profile/frame revision and host sequence. It contains no ECS references, delegates, or mutable components. The mixer never calls back into ECS, transforms, physics, or a scene.

An `AudioWorldHandle` has mixer owner/index/generation, distinct from ECS identity. Reliable creation/destruction receipts govern lifetime; defaults are 32 worlds, 4096 emitters/world and 32768 across admitted snapshots. Snapshot fields are audio-world handle, checked sequence, frozen `SpatialSettings`, profile/frame descriptor/revision, one spatial listener pose, and unique nonempty emitter GUID/spatial-position/velocity records sorted by canonical GUID. Integration owns mappings; standalone callers supply the same records without ECS.

A 3D play request additionally names audio world, domain binding (`Tracked` emitter ID or `FixedPose` canonical `SpatialPosition3`), required snapshot sequence and attenuation. Consume the latest admitted snapshot before due commands. Missing world/listener/emitter or unmet sequence rejects, not zero fallback/wait. Tracked removal ends with `EmitterRemoved` and default fade; world disposal ends its voices. Fixed poses retain canonical chunks/offsets and never move with a cache-frame rebase. Copied resolved snapshot indices prevent processing-path dictionary/ECS access.

Explicit `Offline` mode creates no native endpoint and exposes synchronous `RenderFrames(int frameCount, Span<float> interleavedStereo)` with exact checked destination extent. Any ordinary caller thread may invoke it; one exclusive consumer admission serializes calls. Concurrent/reentrant calls throw contextual `InvalidOperationException` before output or sample-clock mutation. Disposal closes new render admissions and joins an already admitted call before releasing state or pins. Command producers remain independent and may submit concurrently; no native consumer exists in this mode. It drives the same mixer/calendar/resampler in chunks <= 256, advances the sample clock by the rendered count, and returns owned caller output only after processing completes. The caller provides at most 65536 frames per call; no concurrent native consumer is allowed. `NotRequested` mode does not mix, advance or claim audible success. Playback/control command admission in that mode throws contextual `InvalidOperationException` before retaining commands; `TrySubmit` does not invent another false reason or enqueue work that can never complete. Offline arrays are reference output, not proof of hardware latency; `Headless` can opt into Offline without opening devices.

Spatial snapshots are latest-value data: a preallocated three-slot mailbox may replace an older unconsumed snapshot; sequence/replacement counts are observable. This triple buffering is a concurrency protocol, not FP64 storage. Reliable commands/leases never share its lossy replacement policy. Asset/stream ownership persists through terminal voice/tail completion and control reclamation.
