# Animation, skeletal poses, and deformation

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Assets and sampling

Pose vectors/quaternions/matrices are the `TerraFX.Numerics` values defined in [Chapter 06](06-owned-geometry-and-numerics-interchange.md); palettes use the explicit row packers in [Chapter 18](18-shaders-and-material-pipeline.md). Raw cubic quaternion derivatives must remain raw during `AsSystemQuaternion`/`AsTerraFXQuaternion` and the reflection defined in [Chapter 11](11-assets-import-streaming-and-packages.md); only existing key/sample admission normalizes them. No-motion poses use explicit identity, not `default(Quaternion)`. Private interpolation kernels may use base class library (BCL) values without exposing another public pose family.

Clip record: `Guid`/version, duration `TimeSpan` > 0, tracks keyed node/bone `Guid`, sorted unique key times in the closed interval `[0, duration]`, interpolation `Step`/Linear/Cubic, events with stable ID/time/payload schema, root-motion track and loop mode. Sprite clips use atlas frame IDs and duration/key times. Skeleton maximum 256 bones/mesh, parent indices topological/acyclic, depth <= 256, bind-local scale-rotation-translation (SRT) and inverse-bind matrices; four joint weights/vertex.

Clips/skeletons already use the canonical left-handed (LH) coordinate profile at runtime. Chapter [11](11-assets-import-streaming-and-packages.md) converts right-handed (RH) source translations/quaternions/matrices and cubic derivatives together; do not negate Z again during sampling/skinning/extraction. Its linear quaternion map commutes with component Hermite interpolation and normalization, provided derivative tangents are not normalized. Converted bind/current palettes, root deltas and actor transforms must satisfy the same row-vector composition below.

`Animation` state is per entity: clip/version, local timeline, speed is finite in the closed interval `[-4, +4]` (default 1), loop count, previous sampled time, transition/layer weights and event cursor. Simulation controls it at stage 2; presentation can interpolate sampled poses but cannot advance canonical clip state. Time deltas retain fractional remainder; long seeks use modulo/quotient not repeated frame iteration. [Chapter 34](34-engine-acceptance-cases.md)'s EN056 requires accepting both endpoints and rejecting the nearest finite representable speed values outside them without changing animation state.

`Step` returns previous key including exact boundary; Linear position/scale lerp and quaternion shortest-arc `slerp(normalize)`; Cubic glTF Hermite uses time-scaled tangents, quaternion component interpolation then normalize. `Near`-zero quaternion/invalid tangent result rejects asset or faults sample, no identity fallback.

At exact loop end, Loop maps pose to start but events at duration fire for preceding loop and events at 0 fire for new loop once; interval conventions `(previous,current]`, start 0 events fire on explicit Play. Reverse sampling uses reversed half-open interval and reverse event order; event carries direction/loop. Seek defaults pose-only/no events, explicit `EmitCrossedEvents` bounded 4096 per operation; excess refuses entire seek rather than truncation. Nonloop clamps final pose and emits Completed once.

#### M03 7.2 Clips and static skin

Track key is `(TargetDomain, TargetId RFC, channelRank)`: SceneEntity0/SkeletonJoint1; Position0/Rotation1/Scale2/SpriteFrame3. Sprite tracks use domain0/rank3. SceneEntity TargetId is the unique **ExpandedEntityKey** from the explicitly selected Scene version, not a bare authored ID that could match several nested occurrences. Scene is present iff any domain-0 track exists and selects native/scene 2.0; every such key must exist in its independently expanded source map. Skeleton is present iff a joint track or RootMotion exists. Sorted and unique; two channel variants on one target are not duplicates. Do not sort by track-wrapper GUID. A clip cannot implicitly activate its scene or guess a runtime binding.

Interpolation Step0/Linear1/Cubic2. Position/Scale use vector3 keys; Rotation quaternion keys. Cubic requires both finite derivative tangents, Step/Linear forbid both; tangents are per-second raw values and quaternion tangents are not normalized. Key times strictly ascend within [0,DurationTicks]. Events sort by time/ID and IDs are globally unique. Loop Clamp0/Loop1. Scene targets are symbolic until playback binding; loading data does not instantiate a player.

Position/Scale/Rotation channels are 0/1/2 exactly. Position vectors have engine-distance meaning and engine-distance-per-second tangents; Scale vectors are dimensionless with the same nonzero absolute [0.0001,1000] canonical admission as LocalTransform and dimensionless-per-second tangents. Shared vector-key metadata has Unit=None; the owning clip/track schema version supplies this channel discriminator, not a guessed field-unit rule. Rotation key Q uses the canonical norm predicate, derivative V4 only finite. Domain 1 requires the exact selected Skeleton and a registered joint ID; domain 0 is the selected scene's symbolic expanded key, never a process handle or World-assigned ID. RootMotion present requires Skeleton, an exact matching RootMotionJoint in that skeleton, and the root/scale predicates below. Sprite-key frame IDs resolve against their exact Atlas version. These are load/binding predicates, not playback execution.

Joints retain declared topological order, unique IDs, each parent=-1 or preceding index; depth<=256. Bind-model/inverse-bind agreement is <=1e-5 against identity under the owning numerical profile. Root-motion binding names a parentless root with unit bind scale; root scale keys are one and cubic scale tangents zero when extraction is declared. BoundsQualification=0 means authored/unqualified; no between-key/all-animation-bounds certification at M03. Unknown bounds are not an empty draw.

PoseMode=0 is explicit static BindPose for M03 mesh components. Skin matrices are inverseBind*bindModel, copied/validated with skeleton pins and <=2048 palette-entry extraction limit; no AnimationPlayer or hidden animation tick. Live animation/palette state requires M05's approved extension, not pretending a bind pose is sampled animation.

## 2. Blend and state transitions

Layer record includes bone mask, normalized weight in the closed interval `[0, 1]`, override/additive mode, reference pose and optional event policy. Up to 4 active clips/layer and 8 layers/entity. Override blends positions/scales weighted linearly and quaternions via stable ordered shortest-arc pairwise interpolation; weights normalize only when positive total, otherwise bind pose (explicit configured no-active state).

Additive delta position = sample-reference; row-matrix rotation delta = `inverse(Rreference) * Rsample`, represented by `Quaternion.Compose(Quaternion.Invert(reference), sample)`. Blend that delta from identity by layer weight, then `Compose(accumulatedRotation, weightedDelta)`. `Scale` ratio only for positive reference scales; apply weighted delta in fixed layer order. Negative/zero-scale additive clips unsupported on import; don't divide by zero. Bone mask 0 leaves previous layer unchanged.

Transition fields source/target, duration (default 0.2 s), condition/action schema, interrupt policy (`RestartFromCurrentBlend` default), event selection (Both with `clipID` to deduplicate gameplay intentionally). Transition weights linear default; repeated conditions choose explicit priority then stable `transitionID`. No implicit string-to-code expression interpreter.

## 3. Root motion and skinning

Root-motion import explicitly names one parentless skeleton root with unit bind/sample scale; an animated ancestor or scaled root is unsupported, not automatically guessed. With `Extract` enabled, replace that root's sampled translation/rotation with its bind translation/rotation in the visual pose. All motion sampling uses the original track before this replacement.

Let `M(t)` be the sampled rigid row-vector root transform. A chronological segment from `a` to `b` produces `D = M(b) * inverse(M(a))`. The desired actor transform is `D * actorWorld`, not `actorWorld * D`; the actor's root-motion binding requires unit scale. At a loop boundary, accumulate the segment to `duration`, any full loops `M(duration) * inverse(M(0))`, and the segment from zero, in chronological application order. Do not count the wrap from `duration` to zero as physical backward movement. Reverse uses the reversed segments/inverse loop transform. `Complete` loops use checked quotient and exponentiation by squaring; events still obey their separate 4096-record limit. Nonfinite accumulated motion faults sampling.

`RootMotionRequest` is a copied tick-local record containing entity/tick/clip-version, actor-local Translation:`Vector3`, `Rotation`:`Quaternion` and extraction policy. Its translation/rotation are the rigid decomposition of D. During transitions on base layer (index 0), blend each source clip's delta using the same stable clip order/normalized weights and shortest-arc quaternion rule as override poses; higher override/additive layers do not contribute root motion. If total contributing weight is zero, produce an identity desired delta.

An application system after animation at stage 2 consumes this record, maps it to supported kinematic targets or dynamic forces/impulses, and declares that resource access. The core does not promise a capsule, step-climbing, navigation or character-controller service. Pose Sync computes `MotionFeedback` with the old/new body-origin pose and actual delta; feedback is available at stage 6 and externally only after stage 9. When blocked, visual animation continues unless an authored next-tick speed policy changes it. `Animation` never calls user code inside the solver or teleports a dynamic body through geometry. Chapter [32](32-end-to-end-integration-scenarios.md) supplies a complete circle/sphere movement witness.

For row vectors, the bone skin matrix is `inverseBind * currentBoneModel`; the final position is `sum(weight * position * skinMatrix) * instanceWorld`. Bind pose yields identity skin matrices within `1e-5`. The normal algorithm separately blends per-bone inverse-transpose-transformed normals, then applies the instance inverse transpose and normalizes; this conventional approximation is not the exact geometric normal of the blended deformation. Invert every admitted bone's linear matrix on the central processing unit (CPU); a singular/nonfinite palette fails extraction. If the blended normal has `lengthSquared < 1e-12`, use the highest-weight valid bone normal (ties go to the lowest joint index), report `DegenerateSkinnedNormal` through a GPU diagnostic count, and never emit NaN. Normalize authored weights when `sum > 0`; zero sum is an error. Joint indices must be in range, and the maximum of four weights is explicit. Import rejects a higher influence count unless an explicit recorded approximation policy retains the largest four, renormalizes, and warns.

First renderer uploads per-frame CPU-evaluated bone palettes into structured buffers; vertex shader performs four-weight linear blend skinning. A CPU skinning path may support optional picking, but it is not maintained as a second implementation for test comparison; tests use selected bind-pose, weighted-bone and degenerate-normal expectations. No graphics processing unit (GPU) compute skinning feature is promised. Animated bounds use offline conservative track sampling plus user-declared margin, validated with adversarial key/tangent cases; uncertain bounds are conservatively drawn with diagnostic.

A bounded compute diagnostic pass reads admitted skinned vertex formats/palettes, counts near-zero blended normals, and asynchronously reads the counter after its fence. Raster vertex shader uses the documented dominant-bone normal without storage writes; diagnostics are tagged frame/draw IDs. This does not enable arbitrary vertex atomics or promise compute-produced vertex geometry. Diagnostics are observable after GPU completion, not synchronous render-thread readback stalls.

Sprite frame animation changes immutable draw frame/tint/size at extraction; collider changes require explicit gameplay/physics command, not automatic image silhouette recomputation. Crossfade of sprites renders both weighted instances, order stable, never a half-valid atlas frame.

## 4. Acceptance

Require bind-pose identity, two-bone weighted sample, negative-dot quaternion path, exact loop/reverse/seek events, cubic tangent/time scaling, transition interruption, masks/additive reference, blocked root motion, hierarchy/rebase, palette version retention, maxbones/influences and invalid/import failure. `Animation` state is serialized/replay-hashed by schema; GPU palette bytes are derived and not independently saved.
