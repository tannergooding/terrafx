# UI, Unicode text, and editor

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. UI model and layout

Retained user interface (UI) tree owned by host thread, distinct from entity-component-system (ECS). `UiElement` ID/generation, parent/order, visibility Visible/Hidden/Collapsed, enabled flag, hit-test flag, layout, style, focus/tab index, accessibility label/role/value, event handlers. Tree maximum 131072 nodes/depth 256; changes invalidate affected measure/arrange subtrees, deferred while routing an event.

UiTreeOptions has an explicit parameterless constructor with MaximumElements = 131072, MaximumDepth = 256 and MaximumLayoutPasses = 4. Positive overrides may lower but not exceed those ceilings, validate before allocation and freeze at tree creation. UiTree captures its caller/host owner, validates the supplied input recipient, and owns its nodes/private layout state; Dispose closes admission, cancels capture/composition and releases tree-owned pins without invalidating independently retained snapshots. Caller-visible errors use [02](02-dotnet-api-memory-and-ownership.md)'s conventional channels.

BuildSnapshot requires a complete current layout and returns an independently owned disposable UiSnapshot with positive LayoutRevision and nonnegative DrawCount/HitRegionCount. Private immutable ordered draw/hit-test data and exact font/texture version pins belong to that snapshot; no public mutable vertex array or atlas pointer is exposed. Renderer/UI integration takes independent operation credits before admitting snapshot consumption and retains its GPU versions until actual completion, so caller disposal cannot revoke accepted draws. Snapshot metadata remains readable after disposal; new consumption is refused. Layout revision advances only on a completed published layout, never silently wraps, and input/rendering share that revision. Snapshot construction is a method because it performs bounded copying/pinning, not a cheap property.

Layout lengths Auto/Pixels/Percent; logical device-independent pixels (device-independent pixel (DIP)), convert through window scale then physical rounded edges. Containers Row/Column/Grid/Overlay, padding/margin/min/max, alignment `Start`/Center/End/Stretch; Grid fixed/auto/fraction tracks. Measure children under available constraint, determine desired size; arrange actual bounded rectangles, distribute positive remaining fraction space by weight. Percent under indefinite parent measures Auto with a diagnostic; layout dependency cycles fail rather than infinite recalc.

Dirty layout maximum 4 measure/arrange passes per pump; remaining dirtiness yields `LayoutNotConverged` diagnostic and refuses new hit-test snapshot, keeps previous complete layout explicitly. No frame-long loop. Pixel rounding applies cumulative boundaries to prevent seams; clipping nested rectangles intersection, scrolling transforms input/render consistently.

`Core` widgets: label, image/nine-slice, button, checkbox, scalar/text field, slider, list/tree with virtualization, scroll view, menu, tab, dock panel, modal and tooltip. Widget states Normal/Hover/Pressed/Disabled/Focused are explicit style keys. Pointer capture is one owner per pointer; destroyed/hidden/disabled/canceled owner receives `CaptureLost` before removal, never stuck drag.

### Layout details

Hidden participates in layout but neither draws nor receives hit tests; Collapsed contributes zero size/margins and is skipped. Padding consumes the container's available extent; child margins consume space but do not expand the child's hit rectangle. Clamp measured/arranged dimensions to finite min/max before alignment; contradictory min > max is invalid. Percent means a fraction of the finite parent's inner available dimension. Negative percentages, dimensions, padding and spacing are invalid; negative margins are excluded in 0.1.

Row/Column have no implicit wrapping or shrink-to-fit. Measure Auto children at intrinsic size, resolve explicit lengths, then allocate positive remaining main-axis space to explicitly weighted Fill children. If minimum sizes exceed available space, preserve minima and expose `LayoutOverflow`; clip/scroll according to the container policy, never silently scale fonts/controls. Overlay measures the componentwise maximum child extent and arranges each by alignment. Grid first reserves fixed tracks, then measures nonspanning Auto tracks; span deficits distribute equally over Auto tracks, then by weight over fraction tracks, in stable child order. Fixed tracks never grow implicitly. Distribute remaining positive space among fraction tracks after these minima; an indefinite fraction track measures as Auto with the same diagnostic as an indefinite percent. Record both desired size and constrained arranged size so overflow is not falsely called convergence.

Lists/trees use fixed row height (default 20 DIP) in 0.1; variable-height virtualization is unsupported. Flatten expanded tree items in stable authored preorder. Realized row indices occupy the half-open integer interval `[max(0, floor(scrollOffset / rowHeight) - 2), min(count, ceil((scrollOffset + viewportHeight) / rowHeight) + 2))`, inclusive at the computed lower index and exclusive at the computed upper index, with two overscan rows on each side. Recycled rows rebind stable item IDs and reset transient pointer/focus state; selection survives by item ID, not visual slot. Scrolling clamps to `[0, max(0, contentExtent-viewportExtent)]`. Tagged wheel detents move 40 DIP per detent by default; surface-axis pixel values use their declared native/DIP conversion, not a fabricated detent scale.

### Widget activation and rendering

Button pointer-down captures its primary pointer; an up inside the same enabled widget activates once, up outside/capture loss cancels. Enter activates the focused button on nonrepeat key-down; Space arms on down and activates on up while focus remains. Checkbox uses the same activation and toggles once. Slider/scalar controls validate finite min < max and positive finite step. Interactive value is `clamp(min + RoundToEven((clamp(raw, min, max) - min) / step) * step, min, max)`, using checked finite derived arithmetic; a max endpoint need not be a whole step. Pointer drags and arrows emit `PreviewChanged`, one successful gesture emits `ValueCommitted`, Escape/capture loss restores the gesture's initial value with `Canceled`. Undo records commits, not every preview sample. UI navigation repeat uses host monotonic time (default 500 ms delay/50 ms interval), separately from chapter [14](14-custom-input-actions-and-text.md)'s gameplay repeat policy.

Menus, tabs and trees expose explicit selected/expanded stable IDs; arrows move by authored order, Enter activates, Escape closes the active popup without activating its previous target. Modal creation remembers prior focus; close restores it only if still live/enabled, otherwise chooses the next eligible tab-order target. Tooltips appear after 500 ms stationary hover (default movement threshold 4 DIP) and disappear on capture, activation, focus loss or target invalidation. Event handlers run on the owner after native dispatch, outside storage/native locks; faults are surfaced to the host, not swallowed.

Dock layout is an acyclic split/tab tree keyed by stable panel globally unique identifiers (GUIDs). Center drop inserts into the target tab group at a validated index; edge drop replaces that leaf with a horizontal/vertical split (initial ratio 0.5). Sash ratios clamp to `[0.1, 0.9]` and respect panel minimum sizes; unavailable space reports overflow. A drag previews a candidate tree, commits atomically on valid drop, and restores the old tree on Escape/capture loss. Persist this pure-data editor layout separately from runtime world state; callbacks/ephemeral widget IDs are never saved.

Nine-slice data includes source pixel borders and destination DIP borders. Preserve corners; scale edges along one axis and center along both. If destination is smaller than opposing border sums, scale those destination borders proportionally and use a zero-sized center; negative rectangles are never emitted. UI primitives preserve tree draw order, accumulated opacity, intersected clips and snapshot font/texture leases; batch only adjacent compatible primitives. Layout snapshots, rendered geometry and hit tests use the same metrics revision.

UI layout stays top-left/Y-down, independent of world handedness. Its pixel-to-clip transform and generated glyph/nine-slice triangles must produce chapter [21](21-2d-and-3d-rendering.md)'s canonical clockwise projected fronts, not reuse a physics polygon's CCW boundary order. Native front-face/viewport policy is shared with scene rendering; no UI-only Vulkan Y or handedness patch. Gizmo forward is +Z at identity and positive rotations use chapter [03](03-shared-conventions-and-clocks.md)'s base class library (BCL)/axial signs.

## 2. Input, text, and focus

Route pointer hit-testing from frontmost by draw order, then capture -> target -> bubble; the event marks `Handled` and is consumed by gameplay before [Chapter 14](14-custom-input-actions-and-text.md) maps remaining actions. Keyboard navigation uses `Tab`/`ShiftTab`, ordered by tab index and then tree order; modal focus is trapped, and Escape follows modal policy. Game actions do not receive consumed typing/drag input; physical held state remains tracked for correct release/rearm.

Text uses Unicode-scalar strings backed by UTF-16, never key-code-to-`char` conversion. Platform composition/preedit/commit events from [Chapter 14](14-custom-input-actions-and-text.md) feed `TextField`. Cursor/selection operate on grapheme clusters, not `char` indices; use BCL `StringInfo` for grapheme boundaries and HarfBuzz for shaped clusters, bidi, and script positioning. Use ICU bidi analysis (not an improvised right-to-left string reverse), HarfBuzz shaping, and FreeType rasterization through reviewed native bindings. Choose fallback fonts from a declared chain; a missing glyph emits a visible replacement with a diagnostic containing the font/codepoint, not silent omission.

Text layout uses authored language/direction (font 20 DIP default), font metrics/line height, wrapping at Unicode line break opportunities from ICU, tabs declared width 4spaces, selection rectangles and caret mapped through shaping clusters. Input method editor (IME) composition is visually distinct and not committed to game/save until `Commit`. Clipboard paste uses chapter [15](15-platform-host-and-devices.md)'s native text service, validates length (max 1 MiB UTF8 equivalent)/graphemes, not arbitrary execution; absent/denied capability disables the command with visible `ClipboardUnavailable`, not empty-string success. Password text is not telemetry. Color-font rasterization is excluded in 0.1; emoji/grapheme shaping still works with admitted monochrome fallback or visible missing-glyph diagnostic.

Glyph atlas R8 coverage pages 2048, maximum 16 pages/default; least recently used (LRU) evicts only glyphs not pinned by current render snapshots/fences. Linear coverage/premultiplied blending; subpixel LCD rendering not core because transforms/color/surface assumptions differ. Font license/bytes/rasterizer/settings in asset manifest. Text correctness tests include combining marks, surrogate pairs, emoji sequences, Arabic mixed with Latin/numbers, CJK wrapping and IME cancellation.

## 3. Editor contract

`EditorSession` opens an edit `World` and asset project. Dock panels: hierarchy, scene2D/3D viewport, inspector, asset browser/import jobs, animation timeline, physics debug, material/shader error, audio bus, input map, console/profiler and diagnostics. Selection stable scene GUIDs; viewport gizmos translate/rotate/scale with axis/plane constraints and configurable snap, verify scene/physics restrictions before edit.

Property schema and typed constructors/accessors come from generated or explicitly typed component/asset registration: name/type/unit/range/default/required/serialization/ownership/conditional visibility. The NativeAOT editor does not discover arbitrary CLR members or compile access expressions at runtime. Inspector edits typed values, no reflective field poking that bypasses validators. Invalid changes stay in local draft with error; canonical scene unchanged. Multi-edit validates all targets before commit.

Geometry fields use chapter [06](06-owned-geometry-and-numerics-interchange.md)'s `readonly` `TerraFX.Numerics` values. Inspector edits reconstruct copied components/rows through registered constructors and existing validators; there are no mutable Mij fields/private-field reflection writes. Raw defaults do not initialize a valid rotation/pose. Property/schema generation registers all six geometry kinds and the geometry profile, while UI/pointer dimensions keep existing DIP/pixel conventions.

### Authoring presentation and conversion

Authoring conventions describe a quantity in its declared space; they do not replace the runtime contracts in [03](03-shared-conventions-and-clocks.md) and [07](07-spatial-coordinates-and-indexing.md). There is no global handedness, clockwise-positive, or Y-direction preference. Changing a graphics backend cannot change an inspector's meaning or a document's coordinates.

Registered property metadata identifies the quantity, canonical unit, applicable spatial/profile or window-metrics context, display units and conversion, and any angular zero/reference/direction. A unit label alone does not authorize conversion. Conversion descriptors freeze factors, evaluation/rounding budgets and overflow behavior; exact display round trips are not assumed. Positions, displacements, directions, dimensionless components, UI sizes and image texel counts remain distinct; a raw `Vector2`/`Vector3` cannot establish their meaning. Generated or explicit typed accessors/converters share the same editor and source-adapter rules under [26](26-csharp-systems-plugins-and-hot-reload.md), without runtime reflection or a new public universal unit/coordinate framework. Missing or incompatible conversion context reports a validation error before mutation.

| Authoring quantity / view | Required presentation and mapping |
|---|---|
| 2D scene position or translation | Show the declared world/parent XY frame with X right and Y up; label that frame and the selected distance unit. Pointer picking uses the camera/viewport conversion in [16](16-scenes-transforms-and-cameras.md), not a generic Y sign change. |
| 3D scene position or translation | Distinguish root spatial positions from parent-local translations. Present cell/local or admitted frame-relative coordinates under [07](07-spatial-coordinates-and-indexing.md); never flatten a large world into one float vector to display or edit it. |
| World length | Default display is meters, interpreted through frozen `MetersPerUnitExponent` and exact `10^e`; registered alternatives such as centimeters or feet use exact decimal/rational definitions before destination rounding. A display-unit change is not a world/profile conversion. |
| UI or image canvas | Use top-left/X-right/Y-down. UI dimensions use DIPs; image dimensions use declared texels. Physical pixels, DIPs and world lengths are not interchangeable; conversions require their actual scale/context. |
| Ordinary scalar angle | Default display is degrees, with the property's declared axes, zero and positive direction. Runtime angle arguments remain radians. Scalar-angle wrapping is allowed only by that field's own semantic contract. |
| Map or navigation bearing | Use the explicit reference and direction below, not ordinary Cartesian angle semantics or the current camera's forward direction. |

Range, step and snapping rules belong to the canonical quantity. Unit-aware bindings validate edited definitions and canonical results before commit, without a second display-rounding grid. Definition-preserving angular bindings use the source-space snap procedure below; ordinary fields keep their registered canonical snapping. Dimensional conversion includes the powers in velocity, force, inertia or density; multiplying every scalar/vector by a length factor is invalid. Conversion overflow, an inadmissible target value or an unsupported unit is a visible field error, not clamping, zero, identity or a successful partial edit.

#### Definition-preserving source edits

An actual scalar/Euler/bearing edit retains its binary32 value and selected Degrees/Turns/Radians definition through validation, snapping and preview rather than immediately replacing it with rounded turns/radians. Default authored units are degrees. Axis/reference/direction/order still come from registered property metadata, not Angle itself. A scalar angle produces its canonical float radians once at the target boundary; Euler definitions evaluate the Angle rotation factories and compose X then Y then Z once; bearing directions evaluate their declared source-unit zero/sign mapping before trig. Runtime quaternion fields, camera radians and physics angular velocity do not change representation.

The registered angular snap step is a positive finite definition in a declared unit. Transform exact degree/turn ratios into the input's definition space and select the nearest integral multiple with ties-to-even before final binary32 source rounding. Radian/degree mixed snapping uses the qualified bounded conversion budget and cannot claim an exact irrational grid. Validate source, snapped source and final canonical values/ranges together; wrapping is only the property's explicit policy. One edit transaction atomically stores the committed source definition and canonical target. Source quantization/arithmetic still occurs; definition preservation is not lossless floating-point conversion.

Persist the source-only AuthoringAngleDefinition1 envelope from [10](10-binary-data-and-authoring-formats.md#definition-preserving-authoring-angles) for real angular edits. The stable property binding and canonical digest tie definitions to the target they produced. An external target revision invalidates cached definitions; show the derived principal presentation until a real edit establishes a new binding, and never stamp inferred Euler angles as original authored values. Untouched display, save, unit preference or Euler-branch changes preserve both definition and canonical bits. Cooking records converter/recipe identity, validates binding/digest and produces existing canonical runtime fields; it does not serialize this editor envelope into runtime geometry.

#### Spatial unit controls

The raw settings contract is [07](07-spatial-coordinates-and-indexing.md)'s bounded integer exponent, not a runtime enum. The profile-creation/configuration control presents named SI presets: meter at 0 and the current prefixes at exponents `+/-1`, `+/-2`, `+/-3`, `+/-6`, `+/-9`, `+/-12`, `+/-15`, `+/-18`, `+/-21`, `+/-24`, `+/-27` and `+/-30`. Show the unit name/symbol, exact power and "meters per engine unit"; the default selection is meter. Advanced input accepts every integer in `[-30,30]`, with an explicit `10^e m/unit` label for unnamed scales. Validate preset/exponent mapping identically to source adapters, never through a rounded numeric factor or locale-parsed label.

These are editor presets over one canonical exponent, not a second stored unit identity or an enum that cannot express an admitted intermediate exponent. Frozen live settings cannot be changed by selecting a preset: an actual world-unit change previews the explicit conversion/new profile, precision/default refusals and affected content before atomic commit. Ordinary inspector display-unit preferences remain separate and nonmutating. Feet/inches display definitions are exact ratios (`381/1250` and `127/5000` meters), not additional world-scale choices.

#### Rotation controls

The ordinary 2D rotation control shows degrees with zero at `+X` and positive counterclockwise (CCW) toward `+Y` in the declared XY frame. A direction marker makes the sign visible. Dragging a gizmo follows the pointer's physical motion; the display convention does not invert the gesture or alter chapter [03](03-shared-conventions-and-clocks.md)'s axis-specific rotation signs.

For `LocalTransform.Rotation`, the default 3D inspector shows Euler angles: three sequential axis rotations labeled `X`, `Y` and `Z`, in degrees. They use fixed parent-frame axes in X-then-Y-then-Z application order; a root uses the world basis. In row-vector notation, `R = Rx * Ry * Rz`; using chapter [06](06-owned-geometry-and-numerics-interchange.md)'s operations, the orientation is `Quaternion.Compose(Quaternion.Compose(qX, qY), qZ)`. This is not an unspecified pitch/yaw/roll convention or a new runtime representation. Existing gizmo axis-space constraints and pose validators remain authoritative.

Euler presentation is not unique. A newly bound inspector chooses the principal branch with `Y` in `[-90, 90]` degrees and `X`/`Z` in `[-180, 180)`; at gimbal lock, where X and Z are not independently recoverable, choose `X = 0` and solve the remaining Z, with a visible nonunique-rotation indication. The displayed underlying triplet must recompose within [16](16-scenes-transforms-and-cameras.md)'s existing transform-recomposition budget; otherwise report a conversion error instead of fabricated angles. Retain the unrounded user-entered triplet during an active edit, rather than decomposing/rebranching after every preview. A genuine external property revision invalidates that edit through the existing transaction rules.

Only an explicit validated rotation edit replaces the canonical quaternion. Merely binding, displaying, switching units or changing a view preserves the original component bits, including equivalent `q`/`-q` encodings. A quaternion represents orientation, not a revolution count; display branching/wrapping cannot rewrite scalar-angle fields or animation tracks or invent lost authored turns.

#### Bearing fields

A property registered as a bearing displays degrees in `[0, 360)`: zero is north, 90 is east, 180 is south and 270 is west, increasing clockwise (CW) in the declared map plane. The registration supplies that plane/frame and its north/east reference; camera motion does not change the reference. For cardinal maps using the default axes, north is `+Y` and east `+X` in 2D XY, or north `+Z` and east `+X` in 3D XZ. These are map conventions, not a universal geographic-north field in `Core` or a requirement that every application expose a compass.

For the default 2D map, its ordinary Cartesian angle is `90 - bearingDegrees` before conversion to radians. More generally, the direction is `cos(bearingRadians) * north + sin(bearingRadians) * east` in the registered frame; a scalar-angle target also needs its own declared zero/positive-direction mapping. Do not apply bearing wrapping/sign rules to angular velocity, accumulated angles or arbitrary quaternion components.

#### Display and commit isolation

Presentation preferences are separate editor settings, not authoring-field units or runtime profile/schema metadata. Opening an inspector, changing display units/precision, choosing an equivalent Euler branch, inspecting another frame, or panning/resizing a viewport cannot invoke a property setter, dirty the scene/source, create undo history, trigger recooking or alter canonical bytes. Retain the authoritative typed value separately from formatted text; do not parse rounded display text back into an untouched value, including when another property is saved.

Real edits use the existing preview/validate/commit transaction, touching only intended properties and preserving untouched fields. Cancel or rejection restores the original typed values without a display-conversion round trip. Source-adapter conversion and canonical cooking follow [10](10-binary-data-and-authoring-formats.md); changing a serialized unit/reference interpretation requires an explicit schema/profile conversion, not a presentation preference.

### Transactions and play worlds

Undo captures before/after typed changes, affected GUIDs, parent/order, and source bytes needed to reverse asset-source edits; a complete gesture is one transaction, and a divergent edit invalidates redo. Default history 256 transactions/64 MiB; reject an overbudget transaction or explicitly checkpoint/drop the oldest with observable notification. Asynchronous operations become undo entries only at successful activation.

Play creates a distinct world from validated scene snapshot, fresh runtime handles/services; edit-world paused from runtime mutation. Pause/single-step uses simulation clock, audio policy `explicitlyMuteOnPause(default)` with sample fade; native pump/UI continue. `Stop` disposes play-world via ownership protocols, restores edit selections. Data/shader versions can reload at their existing boundaries; changing linked managed modules/accessors requires [26](26-csharp-systems-plugins-and-hot-reload.md)'s explicit rebuild/restart, including saved authoring documents and actual-consumer shutdown. No JIT-only editor mode bypasses this boundary. `ApplyPlayChanges` is explicit previewable diff for serializable authoring properties only, remaps stable GUIDs, excludes physics velocities/tick/transient handles; no automatic live-state writeback.

## 4. Save/share/debug boundaries

`Editor` Save uses chapter [27](27-state-serialization-replay-and-recovery.md)'s transaction, not direct truncating file writes. Export builds chapter [11](11-assets-import-streaming-and-packages.md)'s inert profile and exact validation report/version/content digests; certificates don't allow downloaded code/shaders. Imported content opens in separate scene/document until user activates; no startup hook from asset data.

`Physics`/render/audio debug overlays consume immutable diagnostic data, layer toggles and origin versions; they don't change solve/tick results. Gizmo click input belongs editor context. Render-ID picking is async and tagged snapshot/camera/surface/swapchain epochs; stale result is refused or explicitly mapped by stable GUID, never selects a recycled entity index. `Input`/layout coordinates carry observed window-metrics revision; resize activates a coherent new render viewport/layout version, never mixes an old pick buffer with new scale.

Accessibility exports semantic tree via operating system (OS) adapters where supported; keyboard operation required for every core widget, reduced-motion/high-contrast/scalable font styles, no color-only error states. OS accessibility bridge failures report capability, not false universal accessibility certification.
