# Engine-owned geometry and numerical interchange

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

[03](03-shared-conventions-and-clocks.md) owns space, units and algebra; [02](02-dotnet-api-memory-and-ownership.md) owns framework conventions; [29](29-project-setup-build-and-deployment.md) owns qualified runtime profiles. The left-handed (LH) world and BCL execution foundations remain. [08](08-binary32-kernels-and-predicates.md) replaces required binary64 with bounded binary32/exact-predicate kernels.

## 1. Ownership and scope

The `TerraFX.Core` assembly defines `TerraFX.Numerics.Vector2`, `Vector3`, `Vector4`, `Quaternion`, `Matrix3x2` and `Matrix4x4`. Unqualified geometry names throughout these specs mean that family. All public subsystem geometry uses it: scene/animation poses, cameras, rendering semantic records, physics definitions/query results, audio frames, input axes/pointer positions, user interface (UI) dimensions and registered component fields. `System.Numerics` equivalents appear publicly only in the six explicit interchange pairs below, not duplicate subsystem overloads or an implicit conversion network.

These are ordinary named `readonly` structs implementing `IEquatable<T>`/`IFormattable`, with get-only components/rows, raw component/row constructors, constants and documented operations. Arithmetic/constrained helpers/factories are static methods; the `AsSystem`-prefixed forward conversions, `IsFinite`, row/component getters, formatting and equality are instance members. No positional records, hidden mutable backing owner, implicit unit/basis metadata, public native pointer or instruction set architecture (ISA)-shaped member. Common scalar constructors assign the same supplied `float` to each vector component; `Vector3(Vector2 xy, float z)`, `Vector4(Vector3 xyz, float w)` and `Quaternion(Vector3 vector, float scalar)` preserve the supplied components. Matrices construct from three `Vector2` rows or four `Vector4` rows. Namespace collision with `System.Numerics` is resolved by an explicit using alias/qualification in consumers, not different semantics for the same source identifier.

This is a small geometry API, not a replacement for scalar primitives/type methods, generic math, `Complex`, `BigInteger`, buffers, collections or hardware intrinsics. Reuse BCL/SIMD kernels for ordinary arithmetic, matrix multiplication and interpolation through audited interchange. Specialized private physics predicates remain [22](22-custom-physics-world-and-solver.md), [23](23-custom-physics-shapes-queries-and-ccd.md) and [08](08-binary32-kernels-and-predicates.md)'s responsibility. No public `Vector3<double>`, arbitrary-dimensional matrix framework, or double world origin is introduced; [07](07-spatial-coordinates-and-indexing.md) defines spatial positions.

## 2. Representation and defaults

| Type | Managed bytes / required component offsets | Storage contract |
|---|---|---|
| `Vector2` | 8; `X`: 0, `Y`: 4 | One private `System.Numerics.Vector2` value |
| `Vector3` | 12; `X`: 0, `Y`: 4, `Z`: 8 | One private `System.Numerics.Vector3` value, no hidden fourth lane |
| `Vector4` | 16; `X`: 0, `Y`: 4, `Z`: 8, `W`: 12 | One private `System.Runtime.Intrinsics.Vector128<float>`; lanes 0/1/2/3 are X/Y/Z/W |
| `Quaternion` | 16; `X`: 0, `Y`: 4, `Z`: 8, `W`: 12 | One private `System.Runtime.Intrinsics.Vector128<float>` directly, not a `Vector4` wrapper; lanes 0/1/2/3 are X/Y/Z/W and W is the scalar part |
| `Matrix3x2` | 24; `Row1`: 0, `Row2`: 8, `Row3`: 16 | Three private engine `Vector2` rows; elements `M11`, `M12`, `M21`, `M22`, `M31`, `M32` in that order |
| `Matrix4x4` | 64; `Row1`: 0, `Row2`: 16, `Row3`: 32, `Row4`: 48 | Four private engine `Vector4` rows; elements `M11`..`M14`, `M21`..`M24`, `M31`..`M34`, `M41`..`M44` in that order |

`LayoutKind.Sequential` is the C# struct default; an explicit `StructLayout` attribute is not required merely to obtain it. Sequential layout and this component order/size remain required on admitted x64 profiles, with ordinary default packing rather than an explicit overlay or forced pack/size to hide a mismatch. The table fixes the actual private backing types, not only byte-equivalent alternatives. Get-only component/row properties read that storage by value; they do not add duplicate scalar/row auto-property storage. Matrix rows are the engine `TerraFX.Numerics.Vector2`/`Vector4` values themselves, not BCL rows. This gives the four-component family direct intrinsic storage and composes matrices from the same engine row types without exposing sixteen mutable fields. Public matrix element access uses a get-only zero-based [row, column] indexer; invalid row/column throws `ArgumentOutOfRangeException`. Translation is `Row3` for `Matrix3x2` and `Row4.XYZ` for `Matrix4x4`. Mij in other specs denotes an element, not a mandatory mutable field.

`Vector64<float>` for `Vector2`, and `Vector64<float>` plus one scalar float for `Vector3`, are possible future representation candidates; the current baseline instead requires the corresponding `System.Numerics` backing above. Do not substitute a candidate during implementation, widen `Vector3` to 16 bytes, or infer a universal performance ranking from the choice. Replacing backing requires layout/ABI/runtime-profile review and NM01/NM04/NM15 requalification even when component bytes stay the same. Private `Vector128<float>` storage does not require unguarded ISA-specific instructions or add a public intrinsic-vector conversion API.

> **Informative future-type note:** `Plane` is not part of the currently required six-type public API. If introduced, its backing is one direct private `Vector128<float>`, not an engine/BCL `Vector4`: XYZ lanes carry normal coefficients and W carries D. This records the requested storage rule without adding unreviewed plane methods, schema/wire kinds or an infinite-plane collision shape.

Unmanaged/no-reference storage and exact managed component extent are qualified invariants, not a general native-call application binary interface (ABI), alignment, shader layout or serialization guarantee. Arrays have exactly 8/12/16/16/24/64-byte element strides; a `Vector3` load may not read a fourth `float` outside its extent. No 16-byte alignment is assumed for an arbitrary borrowed value. Layout changes require public ABI/profile review even if properties retain their names.

Raw constructors accept all IEEE 754 binary32 values, including signed zero, infinity, and NaN payloads, without validation, normalization, sign canonicalization, or basis reflection. Each vector's default is zero; `default(Quaternion)` has four zero components; each default matrix is the zero matrix. `Quaternion.Identity = (0, 0, 0, 1)`, matrix identities have diagonal ones, and vectors provide `Zero`, `One`, and the applicable `UnitX`, `UnitY`, `UnitZ`, and `UnitW` constants. A default quaternion or matrix is not a valid rotation or transform. Pose and configuration defaults explicitly use `Quaternion.Identity` for rotation and `Vector3.One` for unit scale; a raw type cannot make `default(T)` or a zero-filled array nonzero.

`IsFinite()` is an instance component-wise classification, not an aggregate `bool`: vectors return their corresponding vector, quaternion returns a `Vector4` in X/Y/Z/W order, and matrices return their corresponding matrix with independently classified row components. Every finite lane, including both zeros and subnormals, produces bits `0xFFFFFFFF`; infinity and every NaN produce bits `0x00000000`. True is an all-bits-set mask, not numeric `1.0f`. Classification preserves the input and says nothing about unit length, invertibility, handedness, ownership or subsystem bounds. Future component-wise classification/comparison APIs use the same shape/mask convention; `Equals`, IEEE equality operators and operation-specific `Try` results remain scalar contracts.

Vectors and matrices expose instance `All()`, `Any()` and `None()` reductions over their complete logical component extent. With no argument, a lane matches only when its entire 32-bit representation is `0xFFFFFFFF`; do not test numeric truthiness, floating NaN equality or merely the sign bit. `All` requires every lane to match, `Any` at least one, and `None` no lanes. Their `float value` overloads instead reduce ordinary component `== value`: opposite zero signs compare equal, NaN never matches, and infinity matches the same sign. These are well-defined for arbitrary raw values, not only masks; `Vector3.One.All()` is false but `Vector3.One.All(1)` is true. A padded intrinsic lane is never included, particularly for 12-byte `Vector3`; matrix reductions cover all six/sixteen components, not an aggregate per-column result. The same rules permit `value.IsFinite().All()` for every required geometry type without losing classification information. Admission still rejects a nonfinite component; it does not accidentally switch to `Any`.

Raw values are not universally invalid because they contain NaN; chapter [03](03-shared-conventions-and-clocks.md)'s finite validation applies at domain/API admission, not raw value construction or interchange. Predicate/reduction signature changes require consumer/generator rebuild, not geometry storage or finite-domain changes.

## 3. Exact by-value interchange

Each type provides an instance forward conversion named `AsSystem` followed by its corresponding type name: for example, `Vector2` has `System.Numerics.Vector2 AsSystemVector2()`. Reverse interchange is the accepted `AsTerraFX` extension family on the corresponding BCL values, declared by `TerraFX.Numerics.SystemNumericsExtensions` in `TerraFX.Core`: `AsTerraFXVector2`, `AsTerraFXVector3`, `AsTerraFXVector4`, `AsTerraFXQuaternion`, `AsTerraFXMatrix3x2` and `AsTerraFXMatrix4x4`. Receivers are passed by value, not `in`/`ref`; ordinary namespace import enables instance-call syntax and fully qualified static invocation remains available. The exact declarations are in [30](30-public-api-review-surface.md#geometry). No reverse factory aliases or conversion operators accompany this family. Operations preserve every component bit in order, including both zero signs, infinity and distinct quiet/signaling NaN payloads. There is no reflection, transpose, normalization, allocation, boxing, validation or migration inside interchange. `AsTerraFXMatrix4x4` on a conventional-depth/right-handed (RH) BCL matrix copies that matrix unchanged; it does not turn it into a valid engine camera.

Use `Unsafe.BitCast` by value where the qualified sizes/layouts match, inside a narrowly scoped method-body `unsafe { ... }` block. Its ordinary C# 15 call-context requirements are point-in-time; source already annotates the implementation operation for Unsafe Evolution's requires-unsafe classification. `TerraFX.Core` inherits the repository's shared `AllowUnsafeBlocks` setting for these reviewed bodies and existing allocators; package consumers do not inherit it. The six forward members and six reverse extensions are not marked unsafe: their implementation establishes the complete size/layout/no-reference invariant, so a safe caller has no unsafety obligation. Baseline sources need no preview syntax/flag. A reviewed component-bit-copy fallback is permitted if a qualified BCL representation changes, but must preserve identical bits and report/requalify the new layout/profile rather than silently reinterpret mismatched storage. Do not use explicit-layout overlays, reference punning, escaping `ref`/`ref` `readonly` views, whole-array casts or public mutable BCL aliases. Synchronous internal span reinterpretation is allowed only after equal-stride/no-reference/extent/lifetime proofs, under chapter [02](02-dotnet-api-memory-and-ownership.md)'s borrowing rules; it is not a public zero-copy alias API.

The engine can therefore own naming, compatibility and LH/reversed-depth factories while using BCL kernels. The mechanism is not a promise that every conversion/call is a zero-instruction operation: calling convention, inlining, tiering, field access, mixed scalar/SIMD usage and just-in-time (JIT)/ahead-of-time (AOT) can still affect generated code. NM15 qualifies actual profiles and patterns. Size equality alone does not prove component layout or optimization.

## 4. Arithmetic, equality and formatting

Vector operators `+`, `-`, unary `-`, componentwise `*` and `/`, and scalar multiplication/division use ordinary binary32 arithmetic. Scalar multiplication is supported in either order. `Dot`, `LengthSquared`, `Length`, `Distance`, `DistanceSquared`, `Lerp`, and `Vector3.Cross` retain BCL component algebra. `Lerp` amount is not implicitly clamped. Arithmetic can overflow or propagate NaN/infinity; no saturating result, diagnostic emission or identity fallback is inserted into elementary math. Consumers requiring finite outputs validate at their domain boundary. `StrictLocal` still records exact BCL/compiler/FMA/runtime settings, not portable arithmetic promises.

`Quaternion` operators `+`, `-`, unary `-`, scalar multiplication, `Dot`, and Hamilton multiplication are raw arithmetic. `Multiply(a, b)` rotates by `b` then `a`; `Compose(first, second) = Multiply(second, first)` expresses application order. `Conjugate` negates XYZ only. Unit-quaternion `Lerp`/`Slerp` use the shortest arc under [20](20-animation-and-deformation.md), without globally canonicalizing positive W. `Vector2`/`Vector3.TransformPoint` and `TransformDirection` retain the BCL affine/linear polynomials and row convention; `Vector3.Rotate` applies its quaternion polynomial. `Vector4.Transform` retains homogeneous W. A surface normal instead requires an explicit inverse-transpose transform and normalization. Rigid rotation requires unit quaternion input; a zero quaternion's raw identity polynomial does not authorize zero as a pose. Subsystems validate once at admission, not per vertex.

`Equals(T)`/`Equals(object)` use component `float.Equals`: equal finite values, both zero signs equal, NaNs equal regardless of payload. Operators `==` and `!=` use component `float` comparison semantics: any NaN component makes `==` false even for the same raw value. `Quaternion` q and -q are unequal values even when they encode the same rotation. `GetHashCode` is consistent with `Equals`, but its implementation/value is not frozen across processes/versions and cannot be used as a persisted ID or strict checksum. There is no tolerance in value equality. Callers compare rotations geometrically through `abs(dot(normalizedA, normalizedB))`, with a declared tolerance, rather than hash/canonicalize a raw value.

`Vector2`, `Vector3` and `Vector4` implement `IComparable<T>` and `IComparisonOperators<T, T, bool>` as a deterministic coordinate ordering; this is not added to quaternions or matrices. First compare exact squared Euclidean magnitude from the origin, without binary32 overflow, underflow or rounded-magnitude ties. Equal magnitudes compare a sign code in descending order: component X is the least-significant bit, then Y, Z and W, and a set bit denotes a nonnegative component (including either zero sign). Thus 2D orthants order `++ > -+ > +- > --`. In 2D, equal-radius values within each orthant follow counterclockwise direction, so `(4, 3) < (3, 4)` in quadrant I. For 3D/4D, first compare leading absolute components in descending row-major order, then apply the same counterclockwise rule to the final component pair (YZ or ZW); this is an axis-dependent lexicographic extension, not a global spherical winding. A NaN-containing vector sorts after every vector without NaN; two NaN-containing vectors use row-major `Single.CompareTo`. Vectors with infinity have infinite magnitude and then use the same sign/direction tie-break. `CompareTo == 0` does not replace `Equals`, and `==` retains IEEE semantics.

All six types implement `string ToString(string? format, IFormatProvider? formatProvider)` for `IFormattable`; parameterless `ToString` uses that operation with `null`/`null`. Vectors delegate to the corresponding BCL vector's existing format/provider overload. BCL `Quaternion`/`Matrix3x2`/`Matrix4x4` do not provide that overload: owned quaternion/matrix formatting instead calls component `Single.ToString(format, formatProvider)`. Null/empty format is the scalar general format, `null` provider uses current culture, custom `NumberFormatInfo` is honored and scalar formatting errors propagate without a fallback.

Owned quaternion text is `(X, Y, Z, W)` with formatted component values; matrix text is `[(row1); (row2); ...]` with each row's components separated by comma-space in column order. Parentheses/brackets, comma-space and semicolon-space are fixed punctuation, independent of decimal/group separators. For `Quaternion(1.25, -2.5, 3, 4)`, F2/invariant gives `(1.25, -2.50, 3.00, 4.00)` and F2/fr-FR gives `(1,25, -2,50, 3,00, 4,00)`. `Matrix3x2` rows (1,2),(3,4),(5,6), F2/invariant gives `[(1.00, 2.00); (3.00, 4.00); (5.00, 6.00)]`; `Matrix4x4` has four four-component rows. Format Q on a finite component throws `FormatException` as `Single.ToString` does; nonfinite symbols/error behavior otherwise follow that scalar formatter. This is an engine diagnostic representation, not a claim of nonexistent BCL formatting APIs or a canonical parse/wire contract. `Parse`/`TryParse` and parsing interfaces remain outside the required family.

All six types and Angle additionally implement `ISpanFormattable` and `IUtf8SpanFormattable`. Their char and byte TryFormat overloads produce exactly their ToString text or its UTF-8 encoding, with identical scalar format/provider and per-type delimiter rules (including the BCL vector delimiter behavior above); numeric format parameters carry `StringSyntax("NumericFormat")`. Null/empty format selects general formatting. False means only insufficient destination, with charsWritten/bytesWritten = 0; destination contents on false are unspecified and must be discarded. Invalid format/provider behavior throws, not false. Only a successful written prefix is meaningful; spare destination bytes are unchanged. Standard invariant/current-culture warmed successful formatting must avoid engine-controlled managed allocation; arbitrary provider behavior and allocating ToString are measured separately. No fixed hidden truncation, precision limit, lossy conversion or culture-independent parsing follows.

The operator interfaces in [30](30-public-api-review-surface.md#geometry) expose only these capabilities: vectors have addition/subtraction/negation, componentwise multiplication/division, float scaling/division, equality and the ordering above; quaternion has addition/subtraction/negation, Hamilton multiplication, float scaling and equality; matrices have matrix multiplication and equality; Angle has same-unit addition/subtraction/negation, float scaling/division, equality and the ordering above. `IEquatable<T>` remains distinct from IEEE operator equality. No `INumber`, `INumberBase` or universal identity/conversion promise is added. In particular, zero degrees is not a valid same-unit additive identity for a radians/turns Angle. Concrete constrained generic use preserves layout/units/exceptions; interfaces alone do not prove inlining, reduced copies or AOT code-size improvements.

## 5. Constrained numerical helpers

The following throwing/Try pairs use conventional [02](02-dotnet-api-memory-and-ownership.md) contracts. Nonfinite inputs to constrained helpers are `ArgumentException`; invalid scalar range/enum/index is `ArgumentOutOfRangeException`. `False` has one expected operation-specific condition and all out values are default/unusable. Throwing counterpart failure is `ArgumentException` with the responsible parameter, never default/identity success. Elementary/raw operations in 4 are not these constrained helpers.

| Required operation | Success / single expected false condition |
|---|---|
| `Vector2`/3/4 and `Quaternion` `Normalize(value)`, `TryNormalize(value, out normalized)` | Finite nonzero value produces finite unit length within 2e-6; false means zero length |
| `Quaternion` `Invert(value)`, `TryInvert(value, out inverse)` | Finite inverse of Hamilton multiplication; false means no finite representable inverse in this numeric profile |
| `Matrix3x2`/`Matrix4x4` `Invert(value)`, `TryInvert(value, out inverse)` | Finite candidate passing both inverse residual checks below; false means no admitted inverse in this numeric profile |
| `Matrix4x4` `TryDecompose(value, out scale, out rotation, out translation)` | Existing finite nonsingular SRT restrictions and recomposition residual in [Chapter 16](16-scenes-transforms-and-cameras.md); false means no representable admitted SRT, including shear/reflection combinations not admitted by that decomposition |
| `Matrix4x4` `CreateLookTo(position, direction, up)`, `TryCreateLookTo(..., out view)` | Finite proper LH frame/view; false means no representable frame from the finite direction/up/position |
| `Matrix4x4` `CreateLookAt(position, target, up)`, `TryCreateLookAt(..., out view)` | Same frame condition using target-position; coincident target/parallel up are false, not invented directions |

`Normalize` supports every finite nonzero binary32 input, including subnormals and `float.MaxValue`, under [08](08-binary32-kernels-and-predicates.md#2-finite-normalization-and-inverses)'s admitted rounding/subnormal profile. Signed-zero components retain their signs. Quaternion inverse uses that section's certified representability filter and bounded exact rational fallback; a failed ordinary candidate is not by itself a nonrepresentable inverse. Neither operation canonicalizes quaternion sign.

Matrix inversion requires a finite qualified candidate passing both inverse products against `I`. Each entry's residual is at most `max(1e-5, 2e-6 * sum(abs(productTerm)))`; `Matrix3x2` is checked in homogeneous 3x3 form. [08](08-binary32-kernels-and-predicates.md#2-finite-normalization-and-inverses) owns the exact bounded dyadic predicate and its fast-path/fallback rules. Inverse failure is observable; inversion is not implicit in ordinary multiplication.

`TryDecompose` uses the qualified BCL candidate, validates chapter [16](16-scenes-transforms-and-cameras.md)'s nonzero admitted scale/quaternion/finite fields, normalizes that nonzero candidate once and applies chapter [16](16-scenes-transforms-and-cameras.md)'s existing recomposition check. Nonrepresentable shear is not silently dropped. Existing scene/physics quaternion length/bounds admission remains stricter than raw `Normalize`, so the helper does not broaden those subsystem ranges.

`LookTo` and `LookAt` establish zero direction and parallel up against the original finite source values, before any normalized component is rounded. Successful output is a finite proper left-handed frame/view with error at most `2e-6`; nonrepresentable translation or frame refuses. No angular epsilon discards exactly nonparallel input or invents an axis. [08](08-binary32-kernels-and-predicates.md#3-proper-camera-frames) owns source predicates, `Scaled32`, basis construction, view rows, and translation rounding. NM12 below specifies the corresponding required boundary observations.

## 6. Factory and composition inventory

`Matrix3x2` requires `CreateTranslation`, `CreateScale`, `CreateRotation(radians)`, `Multiply`, and the `*` operator. `Transpose` is not a 3-by-2 to 3-by-2 operation and is not exposed. `Matrix4x4` requires `CreateTranslation`, `CreateScale`, `CreateRotationX`/Y/Z, `CreateFromQuaternion`, `CreateFromAxisAngle`, `Multiply`, the `*` operator, and `Transpose`, plus the `LookAt`/`LookTo` pairs and reversed factories below. `Quaternion` requires `CreateFromAxisAngle`, `Multiply`, `Compose`, `Conjugate`, `Lerp`/`Slerp`, and the normalization/inverse pairs in section 5. `Rotation`-angle factories require finite radians; affine translation/scale factories otherwise retain the raw component arithmetic in section 4. Axis-angle input uses a finite axis whose exact dyadic length differs from one by at most `2e-6`, and finite radians. Admission compares the exact squared length with the exact squares of `1 - 2e-6` and `1 + 2e-6`; it does not round a length or squared length before deciding. Factories reject axes outside that tolerance rather than silently normalize them. Matrix `CreateFromQuaternion`/Vector `TransformPoint`/`Rotate` polynomial contracts are defined in section 4, with unit input established by the caller's rotation contract.

`CreatePerspectiveFieldOfView(fieldOfView, aspectRatio, nearPlane, farPlane)` always creates the LH reversed-depth matrix with depth in `[0, 1]` defined in [Chapter 03](03-shared-conventions-and-clocks.md). `CreateInfinitePerspectiveFieldOfView(fieldOfView, aspectRatio, nearPlane)` is the explicit infinite variant; do not smuggle infinity through a finite-far argument. `CreateOrthographic(width, height, nearPlane, farPlane)` permits signed finite ordered `Near`/`Far` and positive finite width/height. The projection factories enforce the scalar/derived-matrix/inversion validation defined in [Chapter 03](03-shared-conventions-and-clocks.md) and throw on invalid/nonrepresentable arguments, rather than returning a false camera. There is no default RH/normal-depth overload, configurable global handedness, or implicit viewport-Y flip.

Matrices multiply in row-vector order. Translation occupies `Matrix3x2`'s third row and `Matrix4x4`'s fourth row. A point transformed by `Matrix4x4` through `Vector3.TransformPoint` is affine XYZ evaluation with input W = 1, without projective division. Homogeneous/projective work uses `Vector4.Transform`, then explicitly checks/divides W per [Chapter 16](16-scenes-transforms-and-cameras.md); a `Vector3` convenience call must not discard the perspective pole. `Quaternion` composition, inverse-transpose normals, glTF `H * M * H` conversion, and axial signs remain as specified in [Chapter 03](03-shared-conventions-and-clocks.md) and [Chapter 11](11-assets-import-streaming-and-packages.md). `AsSystemMatrix3x2`/`AsSystemMatrix4x4` merely expose the same row elements to those kernels.

### Definition-preserving angles

`TerraFX.Numerics.Angle` is a Core-owned scalar definition, separate from the six geometry layouts. Its sequential 8-byte backing is one binary32 value at offset 0 and one Int32 `AngleUnit` at offset 4: Degrees = 0, Turns = 1, Radians = 2. Default is zero degrees. Constructor/From helpers preserve supplied value bits, including signed zero/NaN, and reject unknown enum values. They do not convert units, normalize, wrap or imply a rotation axis. This preserves definitions such as 1 degree; it does not recover precision already lost parsing/computing the supplied float.

Addition/subtraction require identical units (otherwise ArgumentException); their result retains that unit and ordinary binary32 arithmetic. Unary negation and float scaling/division also retain the unit, with ordinary IEEE overflow/NaN behavior. There is no implicit conversion or automatic mixed-unit arithmetic. Equals uses identical unit plus float.Equals; operators use identical unit plus float ==. Numerically equivalent differently tagged definitions are unequal; callers explicitly choose a conversion for geometric comparison. Hash is consistent with Equals, not a persisted identity.

ToDegrees/ToTurns/ToRadians are explicit evaluation boundaries. Nonfinite source throws ArgumentException; a converted result that rounds to infinity throws OverflowException. Same-unit conversion returns the original finite bits. Degree/turn conversion evaluates the exact dyadic source times 360 or divided by 360 before one nearest-even binary32 rounding, preserving zero sign; it does not multiply by a pre-rounded 1/360 factor. Radian conversions are irrational, not exact metadata transforms: use a bounded rational pi approximation before final rounding and qualify at most two destination ulps against a higher-precision reference, including underflow and sign. A concrete allowed recipe uses P = hexadecimal `3243F6A8885A308D313198A2E03707344A4093822299F31D0082EFA98EC4E6C89`, where P/2^256 < pi < (P+1)/2^256, and midpoint (2P+1)/2^257. Form the complete source/ratio product in the existing bounded 1024-bit rational workspace; this is not an arbitrary-precision framework or a mandatory FP64 implementation. No universally correctly rounded pi conversion claim follows.

SinCos rejects nonfinite input. For Degrees/Turns, reduce the exact dyadic source modulo 360/1 before any radian rounding; retain a signed remainder of magnitude at most half a turn, choosing the original sign at an exact half/full turn. Exact cardinal results are prescribed: full turns give (signed zero, 1), positive/negative quarter turns give (+1/-1, +0), and half turns give (signed zero, -1). Other values evaluate a bounded radian argument using the recipe above, then the profile-qualified scalar trig kernel; each output's absolute error is at most 2e-6 against the unreduced source definition. Radians use the existing profile-qualified float-radian trig path and retain its signed-zero behavior. Reduction is for evaluation only; it never rewrites Value or loses authored revolutions.

`(float Sin, float Cos) SinCos()` is the single canonical pair-returning form; there is no redundant out-parameter alias. Angle's ToString/IFormattable/TryFormat text is the stored scalar followed by one ASCII space and the exact enum name Degrees, Turns or Radians, such as `90 Degrees`. The format applies only to Value using the scalar rules above; parameterless formatting uses current culture. Formatting never converts, wraps, snaps, evaluates trig or mutates the definition. Default displays zero degrees; negative-zero/nonfinite text follows Single formatting and does not promise recovery of NaN payload bits. Diagnostic text is not the source envelope or a parsing/persistence grammar.

The Angle overloads of Quaternion.CreateFromAxisAngle, Matrix3x2.CreateRotation and Matrix4x4.CreateRotationX/Y/Z/CreateFromAxisAngle use this definition-aware evaluation. Quaternion multiplies the exact source dyadic by 1/2 before reduction/argument rounding, not a raw Angle scalar operation that may already underflow, and never first rounds a radian conversion. Unit-axis validation, LH/row-vector signs and existing pose admission remain. Existing float-radian overloads and canonical float-radian fields/SI radians-per-second physics state retain their contracts. Perspective factories still take canonical float radians; no unrelated factory or angular-velocity type rewrite is implied.

`Angle` implements `IComparable<Angle>` and `IComparisonOperators<Angle, Angle, bool>` using degrees as its default comparison key. Comparison widens the stored binary32 value and evaluates conversions in binary64, so finite extremes remain orderable without overflowing a binary32 intermediate. `Angle.CreateComparer(AngleUnit)` selects a degrees, turns or radians comparison key; each key is derived through degrees so equivalent degree/turn definitions compare equally regardless of comparer. `CompareTo == 0` is a numeric-key result, not definition equality: differently tagged equivalent angles remain unequal under `Equals`. NaN follows `Double.CompareTo` ordering; this does not change IEEE `==`.

[25](25-ui-text-and-editor-tools.md#definition-preserving-source-edits) and [10](10-binary-data-and-authoring-formats.md#definition-preserving-authoring-angles) own source persistence, validation and cooking. Angle is not a seventh geometry wire kind or a reason to dump its CLR bytes. Closed generated source converters know its exact value/unit fields; an application persisting Angle in a runtime component must explicitly register its own schema/codec.

## 7. System integration, wire compatibility and qualification

Geometry representation profile is `EngineGeometryBinary32Rows2`, separate from coordinate profile `LeftHandedYUpForwardZ1` and runtime/ISA/numerical profile. Build/API/plugin/component-layout/save/replay/cook/packer manifests record both. It is not a selectable world flag. Old BCL-typed binaries cannot bind to the new nominal types merely because their sizes match; a required engine API-major change and module rebuild/review are explicit.

Wire fields remain named scalar components/rows, not raw struct dumps or compiler backing-field names. Register vector2/vector3/vector4/quaternion/matrix3x2/matrix4x4 field kinds against the engine types.
