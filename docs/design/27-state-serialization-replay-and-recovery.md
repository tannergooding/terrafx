# Persistent state, replay, and recovery

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Save schema and committed snapshots

Save only from a nonfaulted idle world with a committed/restored marker for its current canonical mutation revision. `SaveAsync` captures synchronously on the World owner before background I/O; dirty/uncommitted state rejects before creating a save transaction or performing file I/O. The capture owns copied bytes and required asset/version pins independently until actual I/O completion. Header engine serialization major/minor, complete selected content-catalogue digest, application schema/version, world stable globally unique identifier (GUID), tick/rate/time-scale segments, frozen spatial settings/positions and frame descriptor/revision, numerical profile, runtime/platform profile, module versions, required asset digests and payload digest. `Entity` components are encoded by schema GUID/version and permanent tagged fields under [10](10-binary-data-and-authoring-formats.md); entity references stable GUIDs remapped on load.

Header/build/replay identity includes coordinate profile `LeftHandedYUpForwardZ1`. Prior right-handed (RH) checkpoints/cooked assets lack this interpretation or carry a different profile: reject before world activation, never silently relabel/replay. An explicit `Standard` migration may reflect registered polar/axial/quaternion/tensor fields according to [03](03-shared-conventions-and-clocks.md), reverse/revalidate shape faces and recook required assets, then rebuild profile-dependent caches under fresh version/profile. Arbitrary `Vector3` fields need schema-declared meaning; unknown direction semantics refuse migration. Such a migration starts a new replay/checkpoint lineage and does not certify `StrictLocal` continuation.

Header/build/replay/schema identity additionally includes `EngineGeometryBinary32Rows2` from [06](06-owned-geometry-and-numerics-interchange.md). Same-left-handed (LH) finite geometry wire components may pass an explicitly registered `Standard` nominal-type migration without arithmetic/renormalization; validate their domain bounds and start a new lineage. Old base class library (BCL)-public binaries require an application programming interface (API)-major change/rebuild, not reinterpretation. Unknown custom fields refuse guessed migration, and `StrictLocal` continuation across the public geometry/kernel profile change is not certified. Coordinate migration above remains a separate operation.

Collision assets additionally pin [10's dimension-specific version-1 validator/statistics ID pair](10-binary-data-and-authoring-formats.md#m03-collision-validation-identity-inventory) with selected spatial profile/settings and canonical `ShapeMeasure` significand/exponent fields under [23](23-custom-physics-shapes-queries-and-ccd.md#12-inert-primitive-validation-and-statistics). Preserve the pair and nullable applicability, not a binary32 area/volume materialization or reconstructed value from `TryGetSingle`. Changed settings or formula identity requires explicit registered migration/re-cook, new validated definitions/statistics, recipe/content digests, asset revision and lineage. `StrictLocal` refuses mismatched bindings; ordinary restore never implicitly revalidates unchanged bits under another setting or upgrades a formula. The stored-pair sphere conversion `0x0000B676` and direct-formula result `0x0000B677` are distinct prescribed outputs, not grounds for rewriting canonical saved statistics.

System/physics/input/action/animation/registered module RNG state included where authoritative. `Physics` includes integer cells, both compensated high/low position parts and exact carry/frame state, poses/velocities/sleep/joints/contact warm-start state/solver settings, pinned residency identity and stable body mapping, not merely rounded visual transforms. Checksum/restore preserve this state; publishing a rounded pose never overwrites it. `Audio` cosmetic output/sample device state/graphics processing unit (GPU) handles/thread IDs/timestamps from UTC omitted; explicitly game-authoritative sound state can be authored component data but never native voice pointers.

`StrictLocal` snapshots additionally preserve all observable execution-order state: archetype schema sets, chunk ordinals and exact row GUID order, next chunk/creation ordinals, slot index/generation/retirement and free-list order, physics body/shape/joint allocator ordering and pending ordered command/event cursors. Reconstruct the same indices/generations/topology under newly allocated process owner IDs; serialized references still use stable GUIDs, never raw cross-owner handles. Pool addresses, padding, type-ID accelerators and native pointers remain excluded. Repacking rows or allocating bodies in GUID order can change floating reductions, command partitions or solver order, so it is allowed only for `Standard` loads which do not promise exact continuation. Application authoritative logic may not derive persistent behavior from the newly assigned `OwnerId`.

Restore already-canonical field bits after validation, without rerunning authoring normalization/quantization that could change quaternion/`float` bits; rebuild derived transforms/caches using the declared profile. `Physics` warm-start caches and interpolation/sleep state are restored, not rebuilt by an extra hidden tick. Include the serialized order/allocator metadata in the `StrictLocal` canonical checksum. Reject incompatible registry/layout/profile rather than silently repacking a strict checkpoint.

Canonical scalar encoding little-endian fixed-width integers, finite IEEE binary32 bits; NaN prohibited, negative zero preserved if allowed by property's semantics. GUID canonical RFC byte order defined, strings UTF8 NFC for identity/schema names only (user text not normalized without consent), arrays in declared order/maps keys ordinal-sorted. Optional presence is explicit: absent, present-empty and present-nonempty remain distinct; required fields remain encoded even when initialized from declared defaults. Canonical world hashes include the selected catalogue/profile, schema-ordered authoritative fields, optional presence, tag membership, ordered controls/clocks, exact asset versions and (for `StrictLocal`) declared layout/order state. Hashes exclude CLR padding, process owner/type IDs and implementation-only dirty counters. No raw struct padding/process hash/dictionary enumeration order.

### World identity, restore intent and remapping

Both `Standard` and `StrictLocal` checkpoints preserve the semantic World GUID, replay lineage, active identity branch, issuance namespace/cursor, complete Entity and top-level scene-instance identity history (including retired assignments), creation provenance and declared live references. `Standard` may reconstruct different slot locators/layout; it does not discard or reset semantic history. `StrictLocal` additionally preserves the exact layout/order state above.

Fresh-history lineage selection belongs to chapter [12](12-entities-components-and-queries.md). Both save modes persist the selected lineage and all declared branch/creation/fork-source provenance as canonical semantic identity; saving, ticking, scheduling, disposal and operational-owner rebinding never regenerate them. Fresh construction with a reused WorldGuid is not recorded continuation, and neither matching WorldGuid nor matching lineage substitutes for the exact source digest, profile, complete history, recording and target-binding checks.

Fresh construction uses `WorldOptions.InitialReplayLineageId` exactly when supplied; null selects one independent UUIDv4 only on the fresh path. Restored candidates never perform that draw. Compatible `Branch` and `RecordedContinuation` retain source lineage; an admitted lineage-changing migration or `IndependentFork` uses its explicitly admitted `NewReplayLineageId`, while preserving existing creation provenance and fork-source ancestry. The engine-generated null-input value alone is constrained to UUIDv4. Stored and explicitly supplied nonempty lineages may be non-v4 or equal WorldGuid; they are not restricted by the UUIDv8 exclusion for Entity/scene-instance IDs. Empty/missing required lineage and inconsistent duplicate fields reject; readers never repair from WorldGuid or a root-name recipe.

The initial identity branch is `NameUuid(WorldGuid, "world/identity-branch/root/v1")`; initial issuance uses `WorldGuid`. A checkpoint's identity history has 1-based consecutive ordinals with no gaps, unique nonempty GUIDs across Entity and scene-instance kinds, and no omitted retired assignments. Automatic records must match their recorded namespace/kind/ordinal recipe; explicit rows are outside the reserved RFC-variant UUIDv8 domain; fork-imported rows must match the declared fork transformation. The live Entity table is exactly the live Entity-history subset; the Scenes registry is exactly the live scene-instance subset with complete occurrence/address mappings. Every declared nonnull reference resolves to the correct live kind in the complete candidate set. Page/column lengths, canonical ordering, branch references, redundant World bindings and (for `StrictLocal`) slot/chunk/row/free-list metadata must agree. Operational owners, page IDs, pointers, binding/invocation generations and publication-session scope are not semantic identity bytes.

Every load selects an explicit `WorldRestoreIntent`: `None = 0`, `RecordedContinuation = 1`, `Branch = 2`, or `IndependentFork = 3`; default/unknown intent rejects. `RecordedContinuation` is permitted only from an admitted `StrictLocal` checkpoint with an engine-prepared continuation bound to its checkpoint digest, exact target binding, compatible runtime/profile, recorded inputs/controls/versions/randomness, ordered structural-creation/command stream and expected canonical committed hashes. Before each tick, admit the complete recorded segment; missing/incompatible input, live mutation, unrecorded owner control, idle canonical edit, version/module change or source exhaustion stops continuation before unauthorized work. Structural preflight compares the ordered creation/command stream before identity assignment; stage-9 compares expected canonical state before publication. A late mismatch faults and withholds publication but does not claim rollback of prior component writes or structural commit. Leaving the recorded interval for unrestricted execution requires an explicit owner-boundary branch transition. `Standard` never enters `RecordedContinuation`, even when one repack happens to preserve order.

`Branch` preserves the selected checkpoint's World GUID, complete identity history and cursor, then appends a bounded branch record and changes the future issuance namespace. Compatible branching retains replay lineage; a schema/profile migration starts a new lineage. `IndependentFork` requires a fresh World GUID and lineage and transforms the complete selected history and every descriptor-declared reference; it does not refund cumulative assignments or erase retired history. A fork transforms every Entity and scene-instance GUID, including retired entries, using the new World GUID and original kind/ordinal recipe; rows become `ForkImported`. It transforms branch GUIDs under `world/fork/branch/v1/{old-branch-guid-as-lowercase-N}`, preserves source provenance, rewrites target-World-bound fields/references to the fork GUID, and validates the complete transformed records before candidate Restore. Ordinary GUID data is not heuristically rewritten; an opaque state with no complete reference descriptor rejects.

`LoadOptions` has no parameterless constructor or `Default` instance. Its constructor rejects `None` and undefined `WorldRestoreIntent` values. Preparation has two validation phases: a synchronous entry front end validates and freezes source-independent inputs before file I/O or operation reservations; after bounded source inspection, source-dependent checks finish before candidate construction, Core owner issuance, system factories/Restore or replacement. Entry validation covers null required objects/paths, empty/whitespace/nonabsolute paths, negative endpoints, intrinsic GUID values, forbidden/conflicting fields, snapshot limits and disposed service/handle misuse. It does not infer compatibility, migration requirements, checkpoint-relative GUID freshness or recording completeness from options alone.

| Intent | Synchronous entry shape | After bounded source inspection |
|---|---|---|
| `RecordedContinuation` | Require a prepared continuation; forbid branch GUID, fork GUID and new lineage | Require `StrictLocal`, exact checkpoint and target-binding match, compatible profile, no migration and a complete admitted interval |
| `Branch` | Require a nonempty branch GUID; forbid continuation and fork GUID; permit `NewReplayLineageId` either absent or present as a nonempty requested GUID | Require a fresh new lineage iff the admitted transformation starts one; otherwise require its absence. Check freshness against decoded checkpoint/provenance |
| `IndependentFork` | Require nonempty fork World GUID and new lineage; forbid continuation and separately supplied branch GUID | Check contextual freshness and validate the complete fork/reference transformation |

At entry, “fresh” for a requested `NewReplayLineageId` means nonempty plus only freshness checks against already-known context. Freshness against the decoded checkpoint, retained provenance and admitted transformation is source-dependent. The Branch lineage-presence decision is likewise source-dependent: otherwise-identical options may be accepted for a compatible source and rejected for a lineage-changing migration, or vice versa. `MaximumSnapshotBytes` admits `[64, 2_147_483_584]` and remains subordinate to actual joint admission.

New-lineage admission uses chapter 12's domain-local known-history scope and synchronized reservations. Entry checks intrinsic option shape and already-known context; source-relative freshness and transformation-dependent `NewReplayLineageId` presence remain post-inspection. A load plan that starts a lineage owns its reservation before becoming `Prepared`; candidate construction consumes that exact admitted identity and reservation, without generating or independently reserving another value. The source and transformed target participate only after complete identity validation and before candidate construction, factories, Restore or owner issuance. Independent plans/consumers hold separately charged operation interests captured atomically before admitted work escapes. Disposing a public wrapper cannot revoke an admitted consumer; disposal-first rejects capture. A contextual lineage conflict returns `Rejected` with nonempty diagnostics; intrinsically empty requested GUIDs retain synchronous argument exceptions. Actual consumers, history storage and cleanup/quarantine retain their charges until release; cancellation, passive metadata and GC are not release evidence.

`WorldLoadPlan` stores the exact sealed Entities-owned `WorldConstructionPlan`, validated target identity/history, source/target interests, reservations, exact target binding/domain and prepared construction/cleanup allowance. It also retains an opaque Entities-owned `WorldPreparedReplacement` capability containing that exact sealed construction control; `WorldPersistence` cannot reconstruct it from GUID getters or fabricate the plan. After public usage and pre-admission cancellation checks, the public Hosting entry `WorldPersistence.CommitLoadAsync(WorldLoadPlan, CancellationToken)` synchronously calls `WorldPreparedReplacement.TryCaptureCommit` before returning or queuing accepted work. That method invokes the common `WorldConstructionPlanControl.TryCaptureCommit` transaction. Under process-registry, exact-domain, then binding gates, it revalidates the target and generations, moves the prepaid process commit grant, independent `S_c/T_c/D_c` interests, finite candidate/cleanup allowance and applicable handoff into the preowned `WorldReplacementOperation`, and changes acquisition from `Open` to `Captured`. It publishes the complete operation or none; no allocation, callback, Task completion or partial bundle escapes the gates. `WorldLoadPlan.Dispose` invokes `WorldPreparedReplacement.CloseAcquisition`: disposal-first captures nothing; capture-first gives the operation independent ownership that survives wrapper disposal. Capture is single-use. Closing the coordinator route does not end its running work or accepted operation; P remains retained while either associated coordinator or commit role remains live.

The admitted operation passes the exact leases and one-use plan to `World.CreateRestoreCandidate`; candidate ownership transfers existing credits without minting a duplicate or releasing membership between owners. Consumers end only after their actual callbacks/inspection/I/O use quiesces; owner cleanup and quarantine remain independently charged until real storage release. Candidate playback does not acquire a fourth late commit interest: after commit source readers/callbacks have actually joined, `WorldReplacementOperation.ExecuteAtOwnerBoundary` invokes its single-use `TransferSourceToPlayback` step and transfers `S_c` plus exact recording/source data/pin leases to candidate-owned `WorldPlaybackControl` before publication. The operation can no longer use or end the transferred credit. Prepublication failure retires playback through the candidate's existing cleanup allowance; successful publication retains it under the candidate's new binding/lifetime. Old-binding revocation and plan, handle or `WorldPersistence` disposal do not revoke installed playback. Playback's final actual cleanup ends `S_c`; the source data owner independently ends `S_o` only after its data/pins release. `T_c` remains through actual target comparison, `D_c` through accepted operation completion/cleanup, and accepted commit uses `CancellationToken.None`.

`PrepareRecordedContinuationAsync` rejects an empty selected interval, an endpoint not after decoded source `NextTick`, incomplete records/hashes, unsupported consumers, incompatible source/profile or source-relative lineage/provenance as `Rejected` with nonempty diagnostics; these are not synchronous argument errors. Null paths throw `ArgumentNullException`; empty, whitespace or nonabsolute paths throw `ArgumentException`; negative `endTickExclusive` throws `ArgumentOutOfRangeException`. Entry-time argument and disposed-wrapper misuse retain synchronous exceptions. This explicitly supersedes any earlier synchronous ownership-exception wording for a target binding that is unavailable, mismatched or revoked: target-binding invalidation during preparation/commit returns stale-target `Rejected` with diagnostics. Unexpected I/O/allocation failures fault the task. Cancellation becomes terminal only after admitted consumers and operation credits unwind.

Capture the exact target binding at its legal owner boundary, inspect bounded source data, complete source-dependent checks, and revalidate the target before returning `Prepared`. At commit, revalidate target freshness before candidate construction/owner issuance and again at the replacement boundary. A stale binding detected before owner issuance consumes no owner. If staleness races after issuance, burn that owner, unwind candidate ownership and leave the active World unchanged. Preparing two plans against one old binding does not authorize both swaps: after the first replacement revokes that binding, the second plan rejects and cannot retarget/replace the successor, even when its GUID is equal.

Load plans distinguish the old operational `TargetWorldGuid`, source checkpoint `SourceWorldGuid` and replacement `TargetRecordWorldGuid`; the plan's `WorldGuid` equals `TargetRecordWorldGuid`. Ordinary branches and identity-retaining migrations use the source World GUID as target-record GUID. Independent fork uses its explicitly selected fresh GUID. All target-bound frame/system/registry bindings and the `WorldStateRestoreBinding` use the target-record GUID; declared source-provenance anchors may retain the source GUID. State2 comparison uses validated transformed target records, not the untransformed source bytes.

For an engine-default `WorldAdmissionDomain`, a prepared replacement owns one exact single-use close-authority handoff ticket but no domain owner credit before publication. The current World remains the sole close owner until the callback-free swap; successful publication transfers the existing owner credit/generation once and revokes the old World authority atomically with binding/history/WorldGuid transfer. Pre-swap failure leaves the old owner unchanged, and candidate cleanup cannot close the target domain. Old-World retirement releases only its own interests and never closes or waits for the surviving domain. Caller/host-owned domains remain external. The current replacement's final disposal closes new admissions, while snapshots, consumers, retiring storage and quarantine continue to retain actual domain credits until release. Chapter 12 and chapter 30 own the exact handoff and actor protocol.

| Replacement boundary | Domain ownership and result |
|---|---|
| Prepared candidate / pre-swap construction | The old binding owns the sole default-domain credit and close authority. Candidate/plan have only exact provisional interests and one handoff ticket; no owner credit or close authority. |
| Final pre-swap validation | Revalidate target binding, domain state/kind, current owner generation, ticket, candidate and all reservations/grants. Old-disposal-first rejects without consuming the ticket. |
| Successful publication | In the same allocation/callback-free visibility transaction as binding revocation, WorldGuid/history/reservation transfer, transfer the one existing domain owner credit to the replacement, install the checked successor generation, revoke old authority and consume the ticket. No close/reopen or ownerless/double-owner interval is visible. |
| Pre-swap refusal, failure or abandonment | Abandon only the ticket and candidate's actual interests/storage; retain or quarantine unreleased data. Old owner credit/generation/authority remain unchanged unless that owner independently disposed. Candidate cleanup cannot close the target domain. |
| Old-World retirement after swap | Release only old World resources/interests. Do not close or wait for the surviving domain, replacement lifetime or unrelated snapshots. |
| Final current replacement disposal | Current owner closes new admissions and surrenders its owner credit; actual snapshots/consumers/retiring storage/quarantine keep their own credits until release. Domain retirement is not a prerequisite for local World retirement. |
| Caller/host-owned domain | No engine-default handoff; external owner remains external and each World releases only its own interests. |

Only one active operational World per `WorldGuid` is admitted in the single-Core execution domain. A same-GUID candidate may reserve against its exact replacement target binding; another active World with that GUID rejects before replacement. Retained snapshots do not count as active Worlds. An engine-produced, independently owned `WorldIdentityRemap` is bound to the verified source checkpoint-payload digest and maps only that checkpoint's live Entity/scene-instance identities. It returns stable identity values, not live `Entity` handles; a later-born discarded-future entity is absent, and equal GUID bits never provide a fallback. Remap ownership is separately reserved and retained until disposal/consumer completion.

Restore preserves the State2 lifecycle and authority: validate source and transformed data; reserve candidate, remap and coexistence ownership; construct the candidate and complete its Entity/instance map; call each system's `Restore` to decode, resolve and rebuild its system-owned caches; revoke every Restore binding in `finally`; perform fresh observational validation and Count/Write; compare canonical output with the validated target records; rebuild only engine-owned caches; then publish a restored marker without a tick. No hidden Execute/tick, lazy repair, or post-validation canonical mutation is allowed. Cancellation/retirement keeps ownership until active consumers unwind, and accepted replacement semantics remain unchanged.

The old target binding authorizes public recording/source admission only. Successful replacement installs candidate-owned playback under the candidate's fresh binding; revoking the old binding prevents later admissions through old handles but does not invalidate installed playback. Admission and wrapper disposal linearize at one synchronized lease boundary: disposal-first prevents acquisition; admission-first gives the operation an independent lease that survives caller disposal. Rejection/failure releases source credits only after actual consumers unwind. Installed playback is World-owned and independent of caller handle or `WorldPersistence` lifetime. `CommitLoadAsync` retains pre-admission-only caller cancellation; once accepted, replacement and consumers use `CancellationToken.None`.

Execution-session initialization failure is terminal for that isolated execution domain. Its retained exception is returned to later admissions without retry/default publication; no owner is issued and no World is published. Witness this permanent failure in an isolated process/domain, not by resetting the production gate.

Schema migrations are deterministic bounded pure-data functions, maximum 16 steps, output validated before activation. Unknown required schema/digest/profile fails with reason; optional explicitly extension data preserved within budget. Load preparation is bound to an exact target World identity/binding generation. `CommitLoadAsync` queues an invisible replacement for the owner boundary, revalidates that binding, and returns a receipt naming the replacement World plus a separately observable retirement task for the old World. The swap revokes old handles and gives the replacement a fresh process owner while retaining the saved stable World GUID. Rejection before swap leaves the old World active. A retirement fault after the swap is reported as retirement/quarantine failure and cannot be represented as “load failed, old World still active.” Restored canonical bits/caches publish a coherent restored marker without a gameplay tick. Independently retained old snapshots/assets remain valid until their consumers finish.

#### M03 8.1 Exact identities and capacity decisions

IdentityHistory is the single authoritative semantic history. Page j starts at ordinal 4096*j+1; GUID/metadata columns have equal count, all pages except the last have 4096 rows, and no retired row is omitted. q=1+sum(page counts), bounded by MaximumIdentityAssignments+1. GUIDs are unique across both kinds. Metadata is exactly directory index bits0..9, kind bits10..11 (Entity1/SceneInstance2), origin bits12..13 (Automatic1/Explicit2/ForkImported3), live bit14 and zero bits15..31. The wire omits resident live locators, B+ tree page IDs/pointers and operational generations. A live Entity or instance joins its exact one-based AssignmentOrdinal and kind/live/GUID; retired rows join neither live table. Creation lineage/branch is the referenced immutable directory row, not the current branch inferred later.

Directory indices are consecutive0..b-1; branch GUIDs unique; ParentBranchId, when present, refers to an earlier directory row. Unforked initial row has Kind Root1, index0, InitialBranch/WorldGuid namespace, CreatedAtNextTick0, FirstAssignmentOrdinal1, no parent/source/fork metadata. A new Branch2 row has namespace=its admitted unique BranchId, parent=previous active branch, creation tick=current n, first ordinal=q, and retained compatible lineage or explicitly fresh migration lineage. Directory entries remain immutable after ordinary branching. Creation ticks/first ordinals are nondecreasing and <=n/q; equal first ordinals are legal when branches issued no identities. History.ActiveBranchId is the final row's BranchId; History.IssuanceNamespace and ReplayLineageId equal its namespace/CreationLineageId; Header.WorldGuid/LineageGuid equal History.WorldGuid/ReplayLineageId. Each assignment names the latest directory row whose FirstAssignmentOrdinal<=its ordinal; complete fork transformation preserves those intervals and appends its future row at q.

Registration must exactly correspond to the selected descriptors/typed factories. Component+tag union <=256; system Orders and IDs unique; Stage0..8; ThreadMode OwnerThread1/Parallel2; resource Kind Component1/Resource2/Tag3/EntityMembership4; access Read1/Write2; None0 and stage9 reject. Tag access read-only. Membership uses exactly S(`resource/entities/membership/v1`)=`5ae0d511-7e5f-81df-bb07-e2b259892443`, Read, Range absent; it has no caller Resource registration or component/tag schema. Access identity unique per `(kind,id)` irrespective of range. Other ranges are checked nonempty half-open intervals with End<=I; component/tag domain [0,MaximumLiveEntities), resource domain [0,PartitionCount), no worker/query-local interpretation.

Systems<=4096/resources<=4096; accesses<=256/system and65536/global; Before/After<=min(4095,systemCount-1) each and65536 globally. Unknown/self/duplicate/backward/cyclic edges reject; fixed stage boundaries cannot be changed. Charge every group's `W*(W-1)/2+W*R` before enumeration, even for disjoint ranges/existing edges; sum<=exact configured comparison limit. Actual arrays/private system/resource objects are fresh per World and cannot alias.

Runtime state rows are exactly the stateful-system/resource/authoritative-attachment set; stateless systems have no StateSchema or row. Declare missing `RegisterResource`/typed factory/state codec and authoritative attachment/persistence participant surfaces in chapter 30. No type-discovery fallback. Resources need a descriptor-bounded serialization shape for their declared domain; metadata intrinsic validity does not establish that contextual admission.

Persistent data components have exact values; tags have no values; transient membership is retained separately. Standard may use declared reset factories; StrictLocal requires exact derived rehydration or rejects. C0 has no built-in transient column. Ordinary caller-owned/unregistered attachments remain transient unless they supply a complete reviewed mutation/restore/lifetime contract; edition-1 authoritative attachments are transferred engine-owned immutable/scope-edited values.

For each entity, persistent Components, Tags and TransientSchemas are disjoint and together equal actual registered membership. Components uses Persistent Component descriptors only; TransientSchemas uses Transient Component descriptors only, without hidden serialized transient payloads. System-state rows join the exact StateSchema declared by their system registration, resource rows join their exact resource factory/schema, and attachment header Schema equals its payload header. A participant cannot substitute another record merely because its role matches. Every declared live Entity leaf resolves in the complete candidate map; opaque Guid/Joint/HistoricalEntity leaves do not use this map. Engine field prevalidation runs again after Structural before immutable stage-8 validation, so deleting a referenced target cannot bypass validation through a cached membership result.

#### M03 8.2 Executable clock/control/frame equalities

Let n=Clock.NextTick, c=Controls.Count, k=Segments.Count, b=HistoryBaseNextTick:

```text
Header.NextTick == n; 1<=n; b==0.
CompletedElapsedTicks = floor(UInt128(n)*10000000/TickRate), <=L.
NextPublicationSequence == n+1, checked <=L.
Cursors.NextControlSequence == c+1.
Controls[i].Sequence == i+1, no holes/truncation.
Controls.AppliedAtNextTick is nondecreasing and lies in [b,n).
Segments[0] == (Sequence=1, StartNextTick=b, admitted initial scale).
Segments[j].Sequence == j+1.
CurrentSegmentSequence == k.
Clock.TimeScale bits == Segments[k-1].TimeScale bits.
```

`Control.Sequence` and `Cursors.NextControlSequence` are signed `Int64` facts and use checked positive issuance; `long.MaxValue` is the exhausted next cursor, never a value to emit and wrap. The public frame receipt and operational control contexts use `long`/`long?` consistently. This does not change any existing wire kind, frame-revision type, schema field or control ordering rule.

`MaximumRecordedControls` defaults to 65,536; lower configured limits remain exact and subordinate to joint state/coexistence bytes. The initial segment additionally counts, so its capacity is this maximum plus one. No pressure truncation or implicit history reset is admitted.

There is exactly one later segment for each time-scale control, in control order. Its Sequence equals payload SegmentSequence, StartNextTick equals AppliedAtNextTick, and TimeScale bits equal payload Value, including signed zero. A same-value applied control still consumes a control/segment; no hidden coalescing. Thus `k==1+count(time-scale controls)`, `k<=MaximumRecordedControls+1`; c<=MaximumRecordedControls.

No applied control at n belongs to a capture of n: its canonical write invalidates the current marker and needs a later successful tick. For a rate r, the exact elapsed-time upper bound is `n<=floor((((L+1)*r)-1)/10000000)` using UInt128; also require n+1<=L. The next step preflights both its completed boundary and next-publication cursor before execution. A nominal long endpoint shadowed by this stronger time bound is not a claimed positive fixture.

ReplayComplete is false in this checkpoint edition. Applied controls are complete bounded *control facts* since initial World creation, not a certificate of complete gameplay-input/movie history or historical ECS causality. StrictLocal preserves checkpoint order/cursors but **does not itself authorize recorded continuation**. [M03 8.5](27-state-serialization-replay-and-recovery.md#m03-85-explicit-restore-intent-and-finite-standalone-continuation)'s separately pinned finite standalone record supplies that proof; actual Input/router/UI recording belongs to its later owner. Setting ReplayComplete=true or rebasing/truncating HistoryBaseNextTick is not an M03 pressure recovery.

Control-scene Activate0 requires Source/ExternalBindings (even empty)/OriginalSceneInstanceId, forbids Intents/DestroyMode. Join SceneInstanceId to the exact SceneInstance-kind history row and its ordinal/creation branch. RequestedSceneId is an immutable original author-input fact, not a target-World reference: when present it is nonempty/non-v8 and equals OriginalSceneInstanceId; when absent the original result is the automatic scene-instance recipe at that ordinal. Its original namespace is the creation directory row's namespace if unforked, otherwise the deepest retained ForkSource.SourceNamespace for that row. Unforked Automatic/Explicit origin agrees with request absence/presence and OriginalSceneInstanceId equals current SceneInstanceId. A ForkImported result equals the target World/kind/ordinal recipe; it does not equal or reapply the original explicit request. Preserve OriginalSceneInstanceId and RequestedSceneId unchanged through every fork. This closes the otherwise contradictory explicit-request-equals-transformed-UUIDv8 predicate without erasing source intent.

Unload1 requires DestroyMode and forbids Source/Intents/ExternalBindings/RequestedSceneId/OriginalSceneInstanceId; Edit2 requires nonempty Intents and forbids those other fields. DestroyMode Detach0/Subtree1; Reparent KeepLocal0/KeepWorld1. Controls record committed facts in typed intent order, not handles/callbacks. Historical Entity IDs must appear in complete history, not necessarily the current live set; this does not invent a creation timestamp.

Control-branch names its exact directory index/BranchId/LineageId; that row's CreatedAtNextTick equals AppliedAtNextTick and it has no SourceCheckpointDigest (ordinary owner-boundary branch, not load). Each such direct branch row has one control; load-created source-bound branch rows need none. Control pressure cannot silently omit a required branch fact.

Scan scene controls from an initially empty scene-instance set. Activate controls are a bijection with all SceneInstance-kind history rows, live or retired; each adds its never-previously-used current InstanceId and exact native/scene Source version. Edit/Unload requires that ID currently in the scan set; Unload removes it. Final set and Source versions equal state/scenes exactly. This catches empty-scene InstanceId reuse and omitted retired activation facts. Historical Source facts are checked for admitted schema/profile/version representation, not automatically pinned/reactivated; only final active sources require the retained content closure. During a fork, transformation verifies these original request/result facts against independently pinned source records before preserving them; an ordinary self-consistent checkpoint is not a cryptographic proof of its historical provenance.

## 2. Crash-safe writes

`Single`-writer save channel per target path (capacity 8). Capture the exact snapshot version and allocate a checked monotonically increasing positive `long` transaction generation for that target; refusal precedes I/O at exhaustion. A separate random `Guid` identifies the unique `CreateNew` temporary sibling but does not determine transaction order. Flush payload and metadata to durable file via `FileStream.Flush(true)`, validate digest/length, then atomically replace the target on the same filesystem with previous backup. Concurrent generation checks prevent an older async completion overwriting newer state.

On Windows, use `File.Replace` when the destination exists or a same-volume atomic move for the first write. On Linux, use rename plus directory fsync through a private native adapter where supported. A cross-volume/network filesystem without supported guarantees returns `DurabilityUnsupported` unless the caller explicitly selects documented `BestEffort` mode; never claim universal power-loss atomicity.

Recovery inspects primary/backup/known transaction temp manifests and validates digest/schema/generation. Only valid primary/backup namespaces certify committed generation; choose newest valid committed candidate, report recovered source. A complete temporary file is `Prepared`, not automatically committed: report it as an optional recoverable candidate but do not promote without an explicit recovery operation. Never delete unrelated temporary files or salvage partial JSON silently. Cancellation before replacement deletes own temporary file; after successful replacement reports committed outcome, not canceled/no-save.

## 3. Replay profile

`StrictLocal` replay requires exact engine/modules/content/runtime/operating system (OS)/instruction set architecture (ISA)/numerical profile, rate/settings and recorded initial canonical save; validate before play. It certifies observed reproduction with hashes, not proof all C#/floating-point algorithms are portable. `Cross`-platform `StrictPortable` is unavailable until a separately implemented constrained numeric profile passes declared target proofs.

A .NET 10 recording is not `StrictLocal`-compatible merely because a .NET 11 engine loads its data. Changes in just-in-time (JIT)/ahead-of-time (AOT)/BCL/single instruction, multiple data (SIMD) or compilation settings can alter reductions/rounding/order; every qualified runtime/ISA/code-generation profile is recorded distinctly. `Standard` migration may load compatible schema data after validation, but strict continuation requires the original admitted profile or an explicitly new recording; never relabel a cross-runtime comparison as exact replay.

Use registered EBIN1 binary schema codecs for runtime saves/replays; source-generated JSON or bounded XML adapters are tooling/migration choices only. Built-in union structural classification or inferred closed-hierarchy discriminators do not replace engine schema GUID/version, explicit stable kind/discriminator fields, limits or canonical field order. Default/`null` union state is not valid serialized success, and adding a case/type does not silently reinterpret an existing payload.

Record normalized tick-assigned input/actions as configured, user interface (UI) commands affecting game, asset activation versions/tick, time-scale/pause/debt discontinuity, module randomness and deterministic command order. PRNG engine streams use explicitly defined PCG32 XSH-RR transition/output with stream ID and serialized 64 bit state/increment; application `System.Random` allowed only outside strict authoritative profile unless its exact behavior/state is separately recorded.

PCG32 updates `state' = state * 6364136223846793005 + increment` modulo `2^64`; the increment is odd. In the C# output expression `uint(((old >> 18) ^ old) >> 27)`, `^` is bitwise exclusive-or; the rotation is `old >> 59`, followed by a 32-bit rotate-right. Initialize with state 0 and increment `(stream << 1) | 1`, advance once, add the seed modulo `2^64`, then advance again. Deterministic bounded-uniform `uint` uses rejection threshold `(0 - bound) % bound` with `uint` wrap, and rejects bound 0; it is not a modulo-only biased sampler.

Authoritative checksum after each committed tick includes schema-ordered state and physics warm-start/event queues; maps sorted stable IDs. Record checkpoint every 600 ticks/default and hash everytick in tests/every 60 ticks shipping replay. Mismatch stops strict replay with earliest known tick/component diff; do not continue with success label. Cosmetic rendering/audio/native timing excluded; frame-rate changes must not change logical outputs under same admitted inputs.

`Input` overflow, `DropDebt`, numerical indeterminate solve, missing version or arbitrary undeclared system state invalidates strict replay explicitly. Normal player can choose recorded recovery policy; can't retroactively claim strict sequence intact.

## 4. Device and surface recovery

Graphics faults preserve central processing unit (CPU) canonical world/assets and completed snapshots. Default `StopHost`; explicitly `SuspendPresentation` stops submissions, rejects old resource tickets, reports persistent fault. Recreate only after old backend callbacks/work safe to abandon/release under native rules; if driver unresponsive retain quarantine and refuse recovery rather than freeing live storage.

New device epoch starts fresh queues/heaps/pipelines from source manifests; reupload pinned versions; rebuild surface; resume after complete required resources ready. No old GPU handle becomes valid again. CPU scene references assets, not native handles, so replacement does not rewrite arbitrary entity-component-system (ECS) pointers.

`Audio` device changes follow the endpoint/mixer-clock policy in [Chapter 24](24-custom-audio-mixing-and-spatialization.md); input device/focus changes follow [Chapter 14](14-custom-input-actions-and-text.md). Surface resize does not alter physics clocks/origin. Replay marks device faults as observational unless gameplay policy explicitly pauses/changes canonical state, in which case it records that command.

## 5. Save/replay admission limits

The default World snapshot limit is <= 2,147,483,584 bytes (2 GiB minus 64 bytes, representable by Core's signed record-size limit). World readers bound records at 33,554,432, fields at 134,217,728, array elements at 2,147,483,584, depth at 64, and UTF-8 strings at 1 MiB; byte admission remains independent. Identity history is paged in consecutive 4096-assignment pages with equal-length GUID/metadata columns, full pages except the last, and no omitted retired rows or operational locators. The aggregate World/persistence admission domain is 8 GiB and includes active, candidate, retiring and quarantined ownership; source/transformed checkpoint bytes and scratch; replay/preparation windows; remaps; and domain/factory-freshness metadata until actual release. AssetStore decoded-asset limits remain separate. Text authoring/import adapters retain their own tighter limits; never parse claimed large counts before checking them.

Core's initial recursive EBIN structural scan is noninterruptible and runs before the visitor; codec cancellation checks cannot stop that scan or establish a latency guarantee. Check cancellation before scanning and on visitor/semantic entry, continue to hold source/candidate ownership until actual consumers unwind, and measure structural-scan duration separately from semantic/restore work and cancellation-to-terminal latency. Required codecs verify consumed length and execute no arbitrary constructors. Test torn writes, corrupt backups, migration, cancellation and generation races; verify state-equivalent restore including sleeping contacts, not just visual-scene reload. Correctly rehashed semantic-negative fixtures must preserve a demonstrable violated invariant; context-incompatible inputs are pinned against independent request/checkpoint context, while self-consistent alternative checkpoints are not intrinsically malformed merely because their digest differs.
