# Persistent state, replay, and recovery

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

## 1. Save schema and committed snapshots

Save only from committed nonfaulted world, owner-thread capture then background I/O. Header engine serialization major/minor, application schema/version, world stable globally unique identifier (GUID), tick/rate/time-scale segments, frozen spatial settings/positions and frame descriptor/revision, numerical profile, runtime/platform profile, module versions, required asset digests and payload digest. `Entity` components are encoded by schema GUID/version and permanent tagged fields under [10](10-binary-data-and-authoring-formats.md); entity references stable GUIDs remapped on load.

Header/build/replay identity includes coordinate profile `LeftHandedYUpForwardZ1`. Prior right-handed (RH) checkpoints/cooked assets lack this interpretation or carry a different profile: reject before world activation, never silently relabel/replay. An explicit `Standard` migration may reflect registered polar/axial/quaternion/tensor fields according to [03](03-shared-conventions-and-clocks.md), reverse/revalidate shape faces and recook required assets, then rebuild profile-dependent caches under fresh version/profile. Arbitrary `Vector3` fields need schema-declared meaning; unknown direction semantics refuse migration. Such a migration starts a new replay/checkpoint lineage and does not certify `StrictLocal` continuation.

Header/build/replay/schema identity additionally includes `EngineGeometryBinary32Rows2` from [06](06-owned-geometry-and-numerics-interchange.md). Same-left-handed (LH) finite geometry wire components may pass an explicitly registered `Standard` nominal-type migration without arithmetic/renormalization; validate their domain bounds and start a new lineage. Old base class library (BCL)-public binaries require an application programming interface (API)-major change/rebuild, not reinterpretation. Unknown custom fields refuse guessed migration, and `StrictLocal` continuation across the public geometry/kernel profile change is not certified. Coordinate migration above remains a separate operation.

System/physics/input/action/animation/registered module RNG state included where authoritative. `Physics` includes integer cells, both compensated high/low position parts and exact carry/frame state, poses/velocities/sleep/joints/contact warm-start state/solver settings, pinned residency identity and stable body mapping, not merely rounded visual transforms. Checksum/restore preserve this state; publishing a rounded pose never overwrites it. `Audio` cosmetic output/sample device state/graphics processing unit (GPU) handles/thread IDs/timestamps from UTC omitted; explicitly game-authoritative sound state can be authored component data but never native voice pointers.

`StrictLocal` snapshots additionally preserve all observable execution-order state: archetype schema sets, chunk ordinals and exact row GUID order, next chunk/creation ordinals, slot index/generation/retirement and free-list order, physics body/shape/joint allocator ordering and pending ordered command/event cursors. Reconstruct the same indices/generations/topology under newly allocated process owner IDs; serialized references still use stable GUIDs, never raw cross-owner handles. Pool addresses, padding, type-ID accelerators and native pointers remain excluded. Repacking rows or allocating bodies in GUID order can change floating reductions, command partitions or solver order, so it is allowed only for `Standard` loads which do not promise exact continuation. Application authoritative logic may not derive persistent behavior from the newly assigned `OwnerId`.

Restore already-canonical field bits after validation, without rerunning authoring normalization/quantization that could change quaternion/`float` bits; rebuild derived transforms/caches using the declared profile. `Physics` warm-start caches and interpolation/sleep state are restored, not rebuilt by an extra hidden tick. Include the serialized order/allocator metadata in the `StrictLocal` canonical checksum. Reject incompatible registry/layout/profile rather than silently repacking a strict checkpoint.

Canonical scalar encoding little-endian fixedwidth integers, finite IEEE binary32 bits; NaN prohibited, negative zero preserved if allowed by property's semantics. GUID canonical RFC byte order defined, strings UTF8 NFC for identity/schema names only (user text not normalized without consent), arrays in declared order/maps keys ordinal-sorted. No raw struct padding/process hash/dictionary enumeration order.

Schema migrations are deterministic bounded pure-data functions, maximum 16 steps, output validated before activation. Unknown required schema/digest/profile fails with reason; optional explicitly extension data preserved within budget. Load stages a fresh world with reservations/assets/physics state, validates references/scene restrictions, then replaces active world at `Begin`. Failure leaves old world active with `LoadFailed`, not partially loaded state.

## 2. Crash-safe writes

`Single`-writer save channel per target path (capacity 8). Capture the exact snapshot version and allocate a checked monotonically increasing positive `long` transaction generation for that target; refusal precedes I/O at exhaustion. A separate random `Guid` identifies the unique `CreateNew` temporary sibling but does not determine transaction order. Flush payload and metadata to durable file via `FileStream.Flush(true)`, validate digest/length, then atomically replace the target on the same filesystem with previous backup. Concurrent generation checks prevent an older async completion overwriting newer state.

On Windows, use `File.Replace` when the destination exists or a same-volume atomic move for the first write. On Linux, use rename plus directory fsync through a private native adapter where supported. A cross-volume/network filesystem without supported guarantees returns `DurabilityUnsupported` unless the caller explicitly selects documented `BestEffort` mode; never claim universal power-loss atomicity.

Recovery inspects primary/backup/known transaction temp manifests and validates digest/schema/generation. Only valid primary/backup namespaces certify committed generation; choose newest valid committed candidate, report recovered source. A complete temporary file is `Prepared`, not automatically committed: report it as an optional recoverable candidate but do not promote without an explicit recovery operation. Never delete unrelated temporary files or salvage partial JSON silently. Cancellation before replacement deletes own temporary file; after successful replacement reports committed outcome, not canceled/no-save.

## 3. Replay profile

`StrictLocal` replay requires exact engine/modules/content/runtime/operating system (OS)/instruction set architecture (ISA)/numerical profile, rate/settings and recorded initial canonical save; validate before play. It certifies observed reproduction with hashes, not proof all C#/floating-point algorithms are portable. `Cross`-platform `StrictPortable` is unavailable until a separately implemented constrained numeric profile passes declared target proofs.

A .NET 10 recording is not `StrictLocal`-compatible merely because a .NET 11 engine loads its data. Changes in just-in-time (JIT)/ahead-of-time (AOT)/BCL/single instruction, multiple data (SIMD) or compilation settings can alter reductions/rounding/order; every qualified runtime/ISA/code-generation profile is recorded distinctly. `Standard` migration may load compatible schema data after validation, but strict continuation requires the original admitted profile or an explicitly new recording; never relabel a cross-runtime comparison as exact replay.

Use registered EBIN1 binary schema codecs for runtime saves/replays; source-generated JSON or bounded XML adapters are tooling/migration choices only. Built-in union structural classification or inferred closed-hierarchy discriminators do not replace engine schema GUID/version, explicit stable kind/discriminator fields, limits or canonical field order. Default/`null` union state is not valid serialized success, and adding a case/type does not silently reinterpret an existing payload.

Record normalized tick-assigned input/actions as configured, user interface (UI) commands affecting game, asset activation versions/tick, time-scale/pause/debt discontinuity, module randomness and deterministic command order. PRNG engine streams use explicitly defined PCG32 XSH-RR transition/output with stream ID and serialized 64 bit state/increment; application `System.Random` allowed only outside strict authoritative profile unless its exact behavior/state is separately recorded.

PCG32 updates `state' = state * 6364136223846793005 + increment` modulo `2^64`; the increment is odd. In the C# output expression `uint(((old >> 18) ^ old) >> 27)`, `^` is bitwise exclusive-or; the rotation is `old >> 59`, followed by a 32-bit rotate-right. Initialize with state 0 and increment `(stream << 1) | 1`, advance once, add the seed modulo `2^64`, then advance again. Deterministic bounded-uniform `uint` uses rejection threshold `(0 - bound) % bound` with `uint` wrap, and rejects bound 0; it is not a modulo-only biased sampler.

Authoritative checksum after each committed tick includes schema-ordered state and physics warm-start/event queues; maps sorted stable IDs. Record checkpoint every 600 ticks/default and hash everytick in tests/every 60 ticks shipping replay. Mismatch stops strict replay with earliest known tick/component diff; do not continue with success label. Cosmetic rendering/audio/native timing excluded; frame-rate changes must not change logical outputs under same admitted inputs.

`Input` overflow, `DropDebt`, numerical indeterminate solve, missing version or arbitrary undeclared system state invalidates strict replay explicitly. Normal player can choose recorded recovery policy; can't retroactively claim strict sequence intact.

## 4. Device and surface recovery

Graphics faults preserve central processing unit (CPU) canonical world/assets and completed snapshots. Default `StopHost`; explicitly `SuspendPresentation` stops submissions, rejects old resource tickets, reports persistent fault. Recreate only after old backend callbacks/work safe to abandon/release under native rules; if driver unresponsive retain quarantine and refuse recovery rather than freeing live storage.

New device epoch starts fresh queues/heaps/pipelines from source manifests; reupload pinned versions; rebuild surface; resume after complete required resources ready. No old GPU handle becomes valid again. CPU scene references assets, not native handles, so replacement does not rewrite arbitrary entity-component-system (ECS) pointers.

`Audio` device changes follow the endpoint/mixer-clock policy in [Chapter 24](24-custom-audio-mixing-and-spatialization.md); input device/focus changes follow [Chapter 14](14-custom-input-actions-and-text.md). Surface resize does not alter physics clocks/origin. Replay marks device faults as observational unless gameplay policy explicitly pauses/changes canonical state, in which case it records that command.

## 5. Save/replay admission limits

The default save limit is <= 512 MiB; the entity cap is defined in [Chapter 12](12-entities-components-and-queries.md), and decoded-binary budgets are defined in [Chapter 11](11-assets-import-streaming-and-packages.md). EBIN record nesting depth is 64, string length is 1 MiB, and array count is 1048576. Text authoring/import adapters use equivalent bounded limits. Use a tighter profile for untrusted requests, and never parse claimed large counts before checking them. Required codecs must support cancellation and consumed-length verification, with no arbitrary constructor execution. Test torn writes, corrupt backups, migration, cancellation, and generation races; verify state-equivalent restore including sleeping contacts, not just visual-scene reload.
