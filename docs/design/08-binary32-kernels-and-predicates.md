# Binary32 kernels and bounded predicates

[Terminology and reading conventions](01-terminology-and-reading-guide.md).

This chapter supplies the no-required-FP64 numerical baseline for [06](06-owned-geometry-and-numerics-interchange.md), [07](07-spatial-coordinates-and-indexing.md), and custom physics/audio. Public geometry and ordinary internal arithmetic are binary32. Bounded integer/exact predicates are private numerical machinery, not a second user-facing coordinate family. Optional binary64 implementations have separate qualification/digests and cannot substitute for this baseline.

## 1. Algebra and naming

Apply [03](03-shared-conventions-and-clocks.md#1-space-and-owned-geometry)'s algebra and [06](06-owned-geometry-and-numerics-interchange.md#4-arithmetic-equality-and-formatting)'s public operations, including `Quaternion.Compose`, `TransformPoint`, `TransformDirection`, and `Rotate`. This chapter owns their bounded numerical kernels, not alternative names, layouts, equality, or interchange rules. Scalar implementation follows [02](02-dotnet-api-memory-and-ownership.md#5-runtime-and-performance-choices).

The kernel manifest records `EngineGeometryBinary32Rows2` and `FloatChunk32V2` separately from coordinate and runtime identity. A changed kernel/profile cannot be relabeled solely because stored component layouts match. Exact decimal unit conversion follows [07](07-spatial-coordinates-and-indexing.md)'s bounded rational contract; this profile change does not alter the geometric predicates, dyadic kernels or integration equations below.

## 2. Finite normalization and inverses

For any finite nonzero vector/quaternion, compute `m = max(abs(component))`, then each `u = component / m`, `s = sum(u * u)`, `d = float.Sqrt(s)`, and each result `u / d`, all in binary32. Use the declared stable component order; do not square original large/subnormal components. At least one scaled component has magnitude one and `s` lies near `[1, 4]`, preventing the original squared-norm overflow/underflow problem. Signed zero components preserve sign. Subnormal-preserving behavior is part of the admitted profile; flush-to-zero cannot inherit this success guarantee.

The public normalization contract retains unit-length error at most `2e-6` against an exact reference. A changed FMA/reduction order is recorded and requalified, not presumed bit-identical. Normalization success does not establish a subsystem's narrower pose/scale/bounds admission.

Quaternion inverse uses `conjugate(u) / s / m` as the ordinary binary32 candidate; avoid `m * s`, which can overflow although the inverse is representable. Neither candidate overflow nor finiteness alone certifies representability near the overflow boundary. A certified outward interval for the exact inverse components may admit a finite common-path candidate only when every exact component's nearest-even binary32 result is proved finite. Otherwise, including a nonfinite candidate, use the bounded exact fallback below. Zero input or an exact rounded component that is nonfinite returns false; the throwing counterpart raises the responsible argument failure. Inversion is not normalization and does not canonicalize quaternion sign.

Using the integer `N` encoding below, let `S = sum(N(component)^2)`. Exact inverse components are `(-N(X), -N(Y), -N(Z), N(W)) * 2^149 / S`. For nonzero input, `S` is positive and has at most 556 magnitude bits; numerators have at most 426. Round these bounded rational components directly to nearest-even binary32 without an overflowing float intermediate. Conjugation flips the sign of zero X/Y/Z and preserves the sign of zero W. Input bits `[0x0010016b, 0x00100000, 0, 0]` must succeed with finite output bits `[0xff7fffff, 0xff7fe951, 0x80000000, 0]`, even though the ordinary candidate overflows. The filter/fallback is private machinery, not required hardware FP64 or a public arbitrary-precision API.

Matrix inversion obtains the qualified binary32 BCL candidate and rejects kernel failure/nonfinite output. Validate both products against the existing absolute/product-scaled residual budget. Binary32 products are exact in binary64; an outward-rounded interval filter may decide entries separated from either admission threshold, with uncertain entries decided by exact bounded dyadics rather than guessed. `Matrix3x2` is checked in homogeneous 3x3 form.

The bounded exact reference uses a binary32 **dyadic representation**: an integer multiplied by a power of two. Let `E` be the stored exponent bits, `F` the fraction bits, and `s` be -1 for a set sign bit or +1 otherwise. For finite binary32 `x`, encode `N(x) = s * F` when `E = 0`; otherwise encode `N(x) = (s * ((1 << 23) + F)) << (E - 1)`. Then `x = N(x) * 2^(-149)`. Both signed zeros encode 0 for geometric predicates; operation-specific output zero signs remain explicit.

For one matrix product entry let `P` be the sum of integer products, `A` the absolute difference from `2^298` on a diagonal or zero otherwise, and `T` the sum of absolute integer product terms. Admission is exactly:

`A * 100000 <= 2^298` **or** `A * 500000 <= T`.

This is `abs(residual) <= max(1e-5, 2e-6 * sum(abs(productTerm)))` with exact decimal rational thresholds, not overflowing float products. Integer products/sums have fixed bounds from at most four binary32 terms. Production geometry uses fixed-limb inline storage for exact predicates; it does not use `BigInteger`. Targeted literals and direct residual inequalities test the production result without a second matrix implementation. A certified interval fast path may avoid the exact fallback; an uncertain comparison must not be guessed. Inverse candidates remain binary32 and failure remains observable.

> **Informative rationale:** The absolute floor covers near-zero entries; the relative term accommodates binary32 rounding/cancellation at large translations or scales. The factor `2e-6` is approximately 32 binary32 unit roundoffs, a bounded-operation allowance rather than a condition-number estimate or universal inversion theorem. A zero candidate has diagonal residual 1 and no product magnitude, so it refuses.

## 3. Proper camera frames

Test zero direction and parallel up against the original source dyadics. For `LookTo`, `D = N(direction)`; for `LookAt`, `D = N(target) - N(position)`; `C = cross(N(up), D)` exactly. Zero `D`/`C` refuses before normalized rounding, including antiparallel and scaled non-axis inputs. Each source `N` has at most 277 magnitude bits, `D` at most 278, and `C` at most 556. Production predicates use bounded fixed-limb inline storage; selected raw-bit witnesses exercise exact source degeneracy without requiring a second arbitrary-precision implementation.

`Cross(up, Normalize(direction))` is not a source-degeneracy test: rounding can invent a nonzero cross for `direction = up = (1, 2, 3)`. That `LookTo` input, and `LookAt` with zero position and `target = up = (1, 2, 3)`, refuse; exactly nonparallel nearby source values continue.

`Scaled32` converts an integer vector to binary32 after a common power-of-two scaling: choose `k` as the largest magnitude bit length, then correctly round each `integer * 2^(-k)` to nearest-even binary32. It does not first convert a 556-bit integer to an overflowing float. At least one component remains near unit magnitude; all are bounded. A private integer-bit implementation supplies this conversion without hardware FP64.

Construct `f = Normalize(Scaled32(D))`, `r = Normalize(Scaled32(C))`, and `u = Normalize(cross(f, r))` in binary32. Require finite derived fields and proper-frame/orthonormal error at most `2e-6`. An exactly nonzero near-parallel source cross proceeds; there is no angular epsilon that invents an axis or discards it as parallel.

View rows remain `(r.X, u.X, f.X, 0)`, `(r.Y, u.Y, f.Y, 0)`, `(r.Z, u.Z, f.Z, 0)`, and `(-dot(position, r), -dot(position, u), -dot(position, f), 1)`. The translation dot uses exact source/component dyadics and one correctly rounded binary32 result; refuse nonrepresentable output. Bounded ordinary-frame implementations may use a proven exact expansion/filter, not unqualified large-float cancellation.

## 4. Geometry filters and physics arithmetic

Shape/pair geometry uses bounded local frames before arithmetic. SAT, clipping, feature enumeration, CCD meaning/termination, contacts, joint rows, and transaction/fault rules remain those in [22](22-custom-physics-world-and-solver.md) and [23](23-custom-physics-shapes-queries-and-ccd.md); replacing their scalar foundation must not replace their geometric meaning.

Use binary32 for well-separated bounded arithmetic. Classification uses an outward interval over each actual add/subtract/multiply/divide: bound inputs, evaluate monotone endpoint combinations, then expand rounded endpoints with `float.BitDecrement`/`float.BitIncrement`. Division requires a denominator interval excluding zero. Overflow, uncertified underflow/subnormal handling, a zero-containing divisor, or an interval crossing the decision threshold triggers bounded exact fallback; never select a sign from an invalid filter. Account for FMA as its actual single-round operation, not a silently contracted two-operation proof. The alternative analytic bound uses binary32 unit roundoff `u = 2^(-24)` and `gamma(k) = k * u / (1 - k * u)` only with `k * u < 1`, plus explicit underflow terms. Count filter/fallback work against budgets and expose frequency/cost.

Exact fallback applies to source degeneracy/orientation, plane-side/turn/convexity tests, relative determinant/axis tests, and tolerances. Square comparisons only after establishing signs. Cooked rounded normalized vectors cannot certify source coplanarity. For nonzero raw face normals `a`/`b`, the near-parallel criterion uses positive `dot(a, b)` and `dot(a, b)^2 >= (1 - 1/10000000000)^2 * dot(a, a) * dot(b, b)` in exact rational arithmetic, followed by the declared plane-distance test. Never round `1 - 1e-10` to float one. Evaluate uncertain plane tests from source vertex/pose polynomials, retaining compensated translations, not from already-rounded world vertices. Fixed dimensionless predicate tolerances are exact profile constants; dimensional tolerances use the admitted converted setting bits.

The 2D two-point normal block's active-set order and mathematical feasibility thresholds remain [22](22-custom-physics-world-and-solver.md)'s. Certify determinant/inequality decisions against exact dyadics of the bounded assembled `K`/`b`; an uncertain two-row solve uses rational Cramer's-rule candidates. Select the first feasible active set before rounding its impulse to finite binary32. Rounded impulse/velocity residuals use the separately qualified binary32 solver error budget, not a false promise that every rounded residual meets a binary64-sized `1e-9` threshold. Singular tangent blocks keep their explicit diagnostic/zero-friction policy. Source classification, solver relaxation and published-pose quantization remain distinct.

Approximate closest witnesses, normalized outputs, and solver integration have their explicit error/residual contracts. An exact predicate does not certify a rounded witness or an arbitrarily stiff solver. If feature reduction/recentering plus bounded fallback cannot produce an admitted witness, return the existing `Indeterminate`/tick fault, not `Miss` or an inflated hidden shape.

Private compensation uses `TwoSum(a, b)`: compute `s = a + b`, `z = s - a`, and `e = (a - (s - z)) + (b - z)`. For bounded nonoverflowing binary32 inputs under the admitted rounding/subnormal profile, `s + e` is the exact sum. For displacement increment `delta`, compute `(s, e) = TwoSum(high, delta)` and then `(high, low) = TwoSum(s, low + e)` with a binary32 low-part addition. The low-part addition still rounds; this is bounded private compensation, not exact arbitrary-duration integration. For the specified witness of 10000 increments of binary32 `0.00001` starting at `4095`, the high part remains below 4096 and the low magnitude is bounded by `2^(-13)`. A conservative accumulated low-rounding budget is `10000 * 2^(-24) * 2^(-13)`, about `7.28e-8` units. The witness must remain within that derived bound; no zero-drift or universal submicron claim follows. Cell carry uses the exact dyadic sum of high/low near a boundary; interior fast paths do not allocate. A rounded high part at `C` with negative low part must not move the true position into the next cell.

Canonical public publication rounds the internal position once and normalizes its resulting offset/cell encoding. Internal integration does not read that rounded publication back. Rebase/carry retains compensation; teleport with clear-history policy resets it deliberately. Store both parts and exact carry/frame state in checkpoints/strict hashes. Bound accumulation error and long-duration drift with the named slow-motion/seam fixtures, not only single-step arithmetic.

## 5. Float audio without unbounded gain chains

Source/internal samples, bus accumulations/gains/filter state, and coefficients use binary32. The graph still has at most 64 buses, 256 voices, and 32 tails. Each bus/master definition has a frozen `MaximumGain` in `[0, 4]`, default 4; its current gain/ramp endpoints cannot exceed that ceiling. Admission requires every contiguous upward path segment from every possible voice-input bus to every ancestor, including the input bus itself, to have an exact product of these **ceilings** at most `65536`. The empty segment has product one. Test all segments, not only complete root paths: downstream attenuation cannot hide unsafe upstream amplification. At most 4096 bus-to-ancestor products are checked on the control path, with certified filters or bounded exact dyadic products. Deep mostly-unity graphs can set smaller ceilings; at most eight consecutive default fourfold-gain nodes may appear on a branch; attenuating nodes can separate additional such runs only when every segment still fits the ceiling. Over-budget creation/reparenting receives `GainPathBudgetExceeded` with no partial change; a gain beyond its ceiling receives `GainOutOfRange`.

With source magnitude 16, voice gain 4 and 288 voice/tail contributions, each possible input-bus stream has magnitude at most `16 * 4 * 288 = 18432`. This deliberately weakens the simultaneous global source budget: every input bus is treated as independently reaching that limit at different times. Within an unchanged tree, decompose exact filter state by its originating input-bus stream. Nonnegative filter weights sum to one even during qualified coefficient ramps, and gains are bounded by frozen ceilings; each stream's contribution along an admitted segment is therefore at most `18432 * 65536 = 1207959552`. Summing at most 64 possible origins bounds every input sum, post-gain value and retained filter state by `64 * 1207959552 = 77309411328` before rounding. Empty paths have gain one. Structural replacement resets new histories; only the bounded old output survives in its explicit crossfade.

The current 288-source envelope alone is insufficient for retained branching histories. For example, eight unity-gain filtered leaves feeding eight shared fourfold ancestors can exceed `2^32` while every segment still fits 65536. Route 256 constant stereo voices of magnitude 16 at gain 4 through successive leaves for 64 frames each; ramp each driven leaf's coefficient from the 20000-Hz value to the 20-Hz value, then retain its history while driving the next. Old leaf states coexist despite the unchanged current voice count. This is an admitted finite-history counterexample, not a reason to clip intermediates or reset ordinary ramps.

Require all rounded bus/filter/crossfade intermediates to remain within conservative magnitude `2^37`, with no hidden clipping. The maximum coefficient is the stored `0.999f`; multiplication/addition rounding keeps the effective history factor below one, and bounded tree depth/pairwise sums fit the margin below. Tests and measured workloads exercise worst-sign, branching-history and routing boundaries directly; no separate audio implementation is required. Only the final Master clamp applies.

For the noncontracted filter including node gain and at most nine pairwise-sum levels, a conservative steady envelope multiplier is `(1 + u)^13 / (1 - 1024 * ((1 + u)^2 - 1))`, with `u = 2^(-24)`: the denominator is positive and the multiplier is below 1.001. The stored cap `0.999f` is slightly above exact `999/1000`; the conservative factor 1024 bounds `a / (1 - a)` for that actual binary32 value. At most 64 bus levels plus one voice/resampling allowance therefore fit `64 * 1207959552 * 1.001^65 < 2^37`, leaving additional margin for bounded subnormal terms and crossfade rounding. The 64-bus chain with 63 nonroot ceilings/gains `3.999f`, Master ceiling/gain `1e-34f`, and two unity stereo voices at gain 4 is rejected before publication: its root products fit 65536 but upstream segments do not, and unguarded binary32 processing would overflow before Master attenuation. Graph crossfade weights are exact dyadics `i/64` and `1 - i/64`; monotone correctly rounded operations preserve the endpoint envelope. Qualified FMA/reduction variants must preserve this conservative admission rather than assuming exact convex arithmetic.

Past filter state cannot be bounded by a new route's current gain alone. A bus-tree structural reparent/replacement therefore resets graph filter histories at the admitted sample boundary, emits `AudioGraphStateReset`, and crossfades the last old stereo output to the new graph over 64 frames. The old/new mix weights sum to one, preserving the same bound; voice/source cursors are unchanged. Gain/cutoff ramps within the unchanged ceiling-qualified tree retain their filter state. Increasing a ceiling is a graph replacement, not an unchecked gain setter. This intentional reset avoids temporal amplification through repeatedly rearranged histories; it is not hidden intermediate clipping.

For cutoff, use `s = float.Sin(float.Pi * cutoff / 48000)` and `a = 1 / (1 + 2 * s^2 + 2 * s * float.Sqrt(1 + s^2))`. This is the same coefficient as `p - sqrt(p^2 - 1)` with `p = 2 - cos(omega)`, without small-angle cancellation/FP64 configuration math. Qualify the admitted endpoints in `[0, 0.999]`; ramps stay inside that closed interval. Coefficient/filter rounding belongs to the kernel profile.

Source cursors are checked nonnegative `long` whole-frame indices plus a private 64-bit unsigned fractional numerator over `2^64`, not an ever-growing float frame number. The fractional numerator retains its full unsigned bit domain; signed whole-frame indices do not narrow it. Public pitch remains float. At configuration, decompose the admitted binary32 pitch exactly and use checked `UInt128` arithmetic to round `sourceRate * pitch / 48000` to whole-step plus nearest-even 64-bit fraction; its bounded numerator fits 128 bits for the admitted rate/pitch range. Carry a rounded fractional overflow into the whole step.

Per output frame, add fractional numerators with an explicitly detected unsigned carry and add whole-step/carry to the checked frame index. Convert only the current bounded interpolation fraction to binary32. If that conversion rounds to one, interpolate from the next frame at zero fraction without changing canonical cursor state; apply the existing EOF/loop-neighbor policy. The step quantization is at most `2^(-65)` source frames per output frame, so even the complete nonwrapping `long` audio-clock extent contributes less than a quarter of a source frame of step-quantization drift. Ordinary float interpolation error remains separate.

Resident import positions use exact integer quotient/remainder of `j * sourceRate / 48000`; convert only the remainder for interpolation. Long clips, loops, pitch changes, and underrun freeze retain integer cursor/fraction explicitly. Integer phase machinery is private timing state, not a new public numeric family or a hardware FP64 requirement.

Spatial attenuation uses integer-cell rejection and bounded nearby float displacement; it does not cast world positions to double. Graph-headroom and cursor changes are intentional audio profile revisions, not a claim that all previously absurd gain chains preserve behavior.

## 6. Qualification

Use targeted bit patterns, analytically derived edge cases, direct residual inequalities and measured workloads to check the specified numerical behavior. These managed checks do not require engine/GPU binary64 and do not prove that native binary32 kernels executed; that requires the corresponding native consumer observation.

Qualification covers all finite normalization magnitudes, subnormals/signed zero, exact source camera degeneracy, scaled integer conversion ties, inverse residual boundaries, determinant/axis/coplanarity thresholds, long slow motion and seam carries, solver/CCD observations, audio cancellation/headroom/cutoff/cursor limits, and measured common/fallback operation costs. StrictLocal records actual runtime/ISA/FMA/subnormal/kernel settings. Optional wider precision is separately profiled; baseline conformance remains mandatory.
