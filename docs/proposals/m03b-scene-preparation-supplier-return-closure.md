## Precise constraint and smallest proposed owner resolution

The current supplier signatures expose **result readiness**, not **return of the producer and its Scene-funded runtime wrappers**. Adding `Returned()` to a supplier's `finally`, observing another Task, or clearing the latch in `OnPlanPrepared`/`OnResourcesPrepared` would still signal before an unproved suffix. A profiler/debugger can expose that interval but cannot supply a production ownership edge.

Tentatively require one narrowly scoped **post-last-access grant-handback contract** at the actual supplier/runtime invocation boundary:

1. **Closed membership:** exactly the ordinary planner and, when selected, the real resource preparer are top-level roles. A skipped resource role never starts. These two roles are not a bound of two nested frames: every nested call and runtime wrapper belongs to its supplier's independently derived provision.
2. **Construction order and funding:** the existing root and exact preparation use own the role before invocation can allocate or escape. Preclaim the actual closure/delegate/call/registration peak first. Retain the same claim through all supplier-owned generated publication, dispatch and context-restoration work; no new use, passive owner or unfunded scope carrier is introduced.
3. **Two distinct facts:** readiness transfers the complete plan/resource or failure into the existing rooted slots. Only the actual enclosing invoker may hand back the producer grant, after independent source/native proof covers its last funded access, including acknowledgment/release bookkeeping. The handback must identify the exact root, role and original claim, occur once outside gates, and remain legal after admission closes. It conveys no body or World mutation authority.
4. **No imaginary notification:** a managed callback that leaves another Scene-funded suffix is insufficient. Fulfilment requires a proved existing return/transfer edge, or a separately implemented, budget-aware runtime invocation primitive providing that edge. The current supplier interfaces and standard Task observation supply neither. This proposal defines the missing owner capability; it does **not** assert such a CLR API is installed.

For this candidate, that capability must cover the invokers enclosing the planner's and Rendering adapter's generated producers, and the invokers of the root's two completion Actions. Include generated state clearing and context restoration, not just `SetResult` or a method-leave notification. Physical return is unnecessary if a proved suffix neither accesses the retired grant's objects nor allocates Scene-owned state; absent that proof, the invoker must retain the original provision through its real later boundary.

Apply the capability initially only to the recorded Windows x64 managed `net11.0` lane, SDK/CLR `11.0.100-rc.3.26522.148` / `11.0.0-rc.3.26522.148`, Debug and Release separately. Do not change `global.json` or infer Runtime Async, diagnostic-mode, other-platform or NativeAOT support.

If that lane cannot provide the capability without an engine-specific async framework, new worker, ownership exemption or another unjoined observer, the smallest owner-contract resolution is to make this capability an explicit prerequisite of supported Scene preparation in Chapters 02/16/30, with its allocation accounting owned by Chapter 04. **It remains unavailable until implemented and proved.** This does not relax last access or make framework allocations free. No maintained chapter is changed here.

## Distinguishing static example

Consider a future funded, genuinely suspended **no-resource** preparation. The planner Task becomes terminal and invokes the root's plan callback while its own completion/context wrapper has not returned. Entry has already ended. The callback can publish the prepared result; another caller can dispose its body.

- Clearing the supplier latch on Task observation would allow the last ordinary part to refund producer/shared provision while the planner/runtime suffix remains unproved.
- Keeping the current latch leaves that preparation use permanently unable to end, even after the supplier actually returns, because no code reports that return.
- The proposed handback retains the original claim during the interval and returns it exactly once at the real boundary. Body disposal and Task observation cannot substitute for it.

This is a counterfactual path witness, not an executed race: the current unavailable footprint prevents entry. Tentative selection permits resolving this capability and continuing genuinely dependency-ready M05/M03-B work under Chapter 35; it does not supply a qualified Scene producer to consumers that require one.
