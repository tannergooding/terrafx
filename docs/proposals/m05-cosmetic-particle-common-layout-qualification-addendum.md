# M05 constructor-free common-layout qualification

## Result

**Tentative evidence/owner-boundary decision; no execution authorization.** The current Runtime fixtures cannot both establish the prospective deltas and admit their production charges without another step:

- They observe **loaded, actual compiled types**, not fields absent from that assembly. The Cell stride does not determine padding/GC layout in the three common classes.
- A shallow allocation observation is not a World or registration grant. `WorldOptions.ValidateAndResolve` currently calls `Registration.Schedule.ValidateLimits`; that method checks graph bytes and conflict comparisons, not these new registration-header rows. `World.AdmitWorld` prepays the existing World control group; neither boundary currently prices the proposed changes.

The smallest safe next capability is an **isolated, constructor-free baseline/candidate layout lane using the existing fixture approach and actual production declarations**. This resolves the apparent “measure before fields exist” cycle without putting changed layouts into an operational World first. It does not establish standing construction/close funding.

The [common-representation addendum](m05-cosmetic-particle-common-representation-addendum.md) still owns the exact representation; the [standing-owner addendum](m05-cosmetic-particle-standing-owner-construction-addendum.md) still owns selection, original-grant transfer and teardown. No additional feature/token or allocator is selected here.

## 1. Minimal observation-owner capability

Select explicit **test-process ownership of bounded layout subjects and instrumentation**:

- The subjects are constructor-free instances of only `WorldRegistrationBuilder`, `WorldRegistration` and `WorldLifetimeControl`, used solely to observe their actual shallow managed size.
- They are not valid builders, registrations or World owners. Invoke no instance member, disposal, lifetime/grant transition, factory, or publication on them; never pass them into production code.
- The fixture owns all subject arrays, reflection/JIT setup, reporting and resulting measurements. This is not a production budget exemption or a way to acquire uncharged World storage.
- Do not construct `World`, `WorldCosmeticCreditOwner` or `WorldCosmeticCreditStandingControl`. A null reference slot does not allocate its referent. The selected-only standing control remains a separate unqualified row.

The existing `RuntimeHelpers.GetUninitializedObject`/`GC.GetAllocatedBytesForCurrentThread` pattern can support this narrow observation. It cannot certify constructor children, native allocations, cold runtime work, cleanup overlap or last access. Confirm the three actual target types have no finalizer/critical resource path before using constructor-free subjects; otherwise stop this observation rather than execute cleanup on invalid state.

## 2. Safest qualification order

This is a future, explicitly authorized layout-evidence batch, not a probe run in this turn:

1. **Freeze baseline.** Preserve the actual production source/binaries, complete instance-field inventories and target SDK/compiler/CoreLib/CoreCLR/architecture/configuration. Record the three current shallow-size observations in fresh test processes. Keep exact case membership and ignored TRX/log evidence.
2. **Compile an isolated actual candidate.** Use an isolated checkout/artifact lane of the same production projects and ordinary repository .NET commands. Add only the three selected common field declarations and the actual referenced standing-control declaration needed for their real type identity, with their necessary private capture/read members. Wire or execute no operational World construction/lifecycle caller; qualification gates remain inactive. Do not use a shadow class, an `object`-typed substitute, test-only symbols, alternate layout, warning suppression or new runner.
3. **Observe, do not operate.** In that isolated lane, use the existing owning fixture for the same three shallow-size cases, Debug then Release. Preallocate bounded subject storage and finish reflection/type setup outside the measured interval, as in the existing layout pattern; keep subjects alive through the readout. Setup warm-up is instrumentation isolation, not evidence that production cold work is free. No World/candidate constructor, builder `Build`, lifecycle or pool/Scene operation runs.
4. **Derive and compare.** Verify the exact baseline/candidate field sets and target managed alignment/GC layout, then compare actual per-type sizes under identical lane inputs. A Boolean may occupy existing padding; pointer width alone is not the final object-size delta. Do not infer zero from default/null, and do not infer a future layout from the baseline alone.
5. **Keep the candidate off the live route.** Candidate outputs must not overwrite binaries used by ordinary World/consumer execution. No normal World test is the first consumer of an unpriced header. Promote only after the actual common-row accounting below is present and reviewed for those exact bytes.

Compiling real proposed declarations in that non-operational artifact is distinct from installing them into a live construction route. Without this isolation/provenance boundary, the safe action is to leave the common fields absent. No checkout, source/test edit, build or observation is performed here.

## 3. Accounting authority still required

| Delta | Physical owner / required admission |
|---|---|
| Builder Boolean/header change | The actual caller/registration-construction owner. It is not a World/domain allocation merely because the builder will later describe a World. |
| Immutable registration Boolean/header change | The actual registration owner, once for the shared object; its applicable registration-byte quota remains distinct from physical World funding. Extend the real registration-metadata admission/validation boundary before relying on coverage. |
| Lifetime nullable-reference/header change | Every actual World using the changed lifetime representation, including unselected Worlds. Prove coverage in the existing control provision or include the supported actual increment in original World construction admission before lifetime allocation. |

The current schedule graph/conflict validation is not evidence that the new registration-header charge was admitted. Where the required existing-boundary baseline/metadata catalogue is unavailable, that precise metadata-admission input remains open; do not silently take the difference from a World grant, declare it zero, or duplicate the shared registration charge per World.

Likewise, `FreshWorldControlBytes = 4096` cannot be called spare capacity without its actual coverage proof. Any new child allocation or changed constructor/runtime suffix is outside a shallow delta and needs its own row. A measured zero-size increment closes only that representation input for the supported target, not its complete constructor/failure path.

Make the coverage/accounting change and operational field-hook integration one coherent production revision after this evidence. Preserve the existing Chapter 04 configured ceilings and exact admission; do not enlarge limits or count the 10,304-byte Cell backing again as common-header provision.

## 4. Stop conditions and enabled outcome

Stop on mismatched source/binary identity, unreviewed fields, unsupported target layout, an inseparable constructor/finalizer requirement, or inability to isolate candidate artifacts. Unsupported/empty cases are not passes. NativeAOT and other runtime/architecture lanes need their own evidence.

A successful lane yields **three actual shallow deltas plus owner attribution**, not budget credits. Before ordinary unselected World regressions or selected-profile refusal tests, the production admission/coverage for all affected common rows must be established. Before successful selected construction, the separate complete standing header/control/backing, protected constructor/unwind/close, actual-return and domain-retirement publication profile must still close.

The next dependency-ready work is therefore this isolated layout-input qualification and the named metadata/control accounting closure—not live standing-owner construction. All selected lifecycle/operation/publisher, hosted/external-domain/restore and Scene/pool paths remain closed.
