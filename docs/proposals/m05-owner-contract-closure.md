# Remaining M05 owner-contract closure

## Status and scope

**Tentative unblockers for later user review; not an approved API/schema contract or an acceptance result.** Close four bounded extensions: live Animation state/registration/extraction, the cosmetic CPU particle producer, authored Mesh LOD, and visual picking. Preserve the implemented native-content, static extraction, shader/material/shadow, transfer and public-consumer paths. Do not wait for an undifferentiated M03-B or M04 exit.

The current capability boundary is `docs\project\Roadmap.md:9-11`. Chapter 35 explicitly separates contract-complete implementation, actual producers and consumer observations, and prohibits unresolved declarations or lifetime rules entering the affected implementation (`docs\design\35-implementation-roadmap.md:28-61,101-113`). This proposal recommends semantic decisions and identifies the declarations still requiring owner review; it deliberately does not manufacture their member names, schema tuples/tags/versions or acceptance IDs.

Only this proposal is changed. M03-B use/accounting, production code, maintained contracts, tests and milestone status are outside this edit.

## 2. Live Animation and root motion

### Recommended owner closure

1. **Keep one authoritative owner.** Animation owns bounded canonical per-entity playback state and active asset pins; Rendering owns copied derived pose/palette output. Use existing freeze-time component/resource/system codec mechanisms, with the exact engine support and cohort extension reviewed before construction. Entities retains only its lower-owned opaque registrations/ports; preserve the physical/logical dependency direction (`docs\design\29-project-setup-build-and-deployment.md:15-35,43-66`). A controller constructor cannot enlist support into an existing World. The existing `RegisterCpuExtractionSupport` operation admits components only, not hidden systems/resources, and cannot be treated as an already extensible Animation registration (`sources\TerraFX.Runtime\Entities\WorldRegistrationBuilder.cs:176-238`; `sources\TerraFX.Runtime\Entities\IWorldCpuExtractionParticipant.cs:5-12`).
2. **Close the authored and live binding projection together.** Declare the authoritative storage/author family, ordered layers/active clips, masks/reference poses, transitions and their conditions/actions, and the explicit actor-to-Scene/Skeleton/Sprite targets. Preserve eight layers and four active clips per layer, stable authored order and the existing interrupt/event rules. Recommend using the receiver Entity's exact SceneInstance/provenance to resolve Clip-declared expanded keys, only where that mapping is demonstrably sufficient. If the existing `PlayClipAsync` operands cannot uniquely select the intended occurrence/actor binding, that missing binding declaration remains a blocker; do not guess an occurrence or implicitly activate the Clip's Scene.
3. **Use existing content identity.** “Clip version” means the selected AssetId under its retained immutable package backing, not a new per-asset GUID/version service. Reconcile Chapter 20's `clipID` event-origin wording with that model. A command takes its own pin before returning; accepted playback owns a separate pin until stop/completion or actual World retirement; referenced Skeleton/Scene/Atlas values come from the same backing. The controller borrows the World and gains no undeclared disposal authority. Package replacement and caller cancellation/disposal cannot retarget or prematurely release admitted ownership (`docs\design\11-assets-import-streaming-and-packages.md:43-59`; `docs\design\30-public-api-review-surface.md:3698`).
4. **Freeze the exact state and command semantics.** The canonical projection includes current/previous local time, fractional fixed-tick/speed remainder, loop count, speed, active Clip references, layer/transition state and event cursors. Define their checked ranges, ordering, no-active state, command queue/byte limits and overflow/refusal behavior. Reserve canonical state, pins, provisional/current poses and event/output coexistence before allocation. The 4096 crossed-event Seek limit does not by itself bound normal advancement of very short looping clips; close the ordinary-tick event budget and excess outcome explicitly, without dropping events or assuming the render palette limit funds them. Preserve finite speed `[-4,+4]`, pose-only versus explicitly event-emitting seeks, whole-Seek refusal above 4096 crossed events, reverse ordering and end-before-new-start loop events. Every `SeekClipAsync` call still supplies its declared policy; the semantic pose-only default does not authorize an optional overload. Complete all supporting declarations for the already named controller methods, especially `AnimationTransitionRequest`, rather than adding convenience overloads.
5. **Respect the publication boundary.** Apply commands/sample at stage 2 before application Animation systems; external gameplay events and render output remain provisional until stage 9. A stage-2 command receipt reports application, not display, GPU completion or successful whole-tick publication. Close typed committed Animation event bodies, completion/direction/loop/source metadata, selected EventPayload registrations, producer ordering and the merge with other actually selected event producers. The current committed-event descendant set is empty; a raw `native/event-marker` asset record is not an issued gameplay event (`docs\design\13-jobs-and-frame-pipeline.md:43-55,76-103`; `docs\design\30-public-api-review-surface.md:3170-3196`).
6. **Extend persistence with state, not GPU bytes.** Close canonical Read/Validate/Count/Write/Restore, active AssetId capture, target-reference restore joins and any recorded Animation command/control forms in the same unit. Rebuild derived CPU poses/palettes before the restored marker without advancing the timeline or replaying already delivered events. Standard Branch save/restore is the available first real path; neither that path nor a serialized player proves strict recorded continuation. The current finite continuation catalogue explicitly excludes Animation movie state (`docs\design\27-state-serialization-replay-and-recovery.md:23-29,240-271`).
7. **Extend the existing extraction cohort.** Prepare current bone models, skin matrices, normal inverses, Sprite crossfade instances and bounds against the same committed frame/camera/source generation. Preserve the 2048-palette-entry and logical draw limits, explicit discontinuities and independently retained old outputs. CPU extraction must reject singular/nonfinite palettes before native graph construction. Current native Clip bounds accept only qualification zero; initially use the specified uncertain-bounds diagnostic/conservative draw path, not an invented qualification value or between-key certification (`sources\TerraFX.Runtime\Animation\AnimationClipAsset.cs:39-46`; `docs\design\20-animation-and-deformation.md:27-29,49-55`; `docs\design\21-2d-and-3d-rendering.md:7-19,31-35`).

**Required declaration owners:** Animation closes its author/state/layer/transition and controller-supporting types; Entities/Scenes/Rendering close the exact pre-construction registration, target binding and cohort ports; Chapter 10 closes any selected new descriptors/fields; Chapter 27 closes persistence/recorded controls; Chapter 30 closes public declarations and issuers. The exact storage family, missing binding operand if needed, schema assignments and complete event catalogue remain unresolved until those owners publish them. Existing native Clip/Skeleton data is reused wherever sufficient; `render/mesh.PoseMode=0` is not widened in place.

### Root-motion boundary

Retain `D = M(b) * inverse(M(a))`, chronological loop composition and `D * actorWorld`; extract from original root tracks before replacing visual root motion. Complete the already named `RootMotionRequest` as copied tick-local data and its declared stage-2 resource access. An application movement system, not Animation, translates it into supported body commands. Complete `MotionFeedback` ownership and stage-6/postcommit delivery with the actual Physics/Integration producer (`docs\design\20-animation-and-deformation.md:41-47`; `docs\design\16-scenes-transforms-and-cameras.md:130-134`).

CPU delta/state/palette work does not require the M06 solver. Collision-limited travel and actual feedback do. Chapter 32's sphere/wall witness, including center `<= 0.605001 m` with a progressing walk pose, remains M06/M07-dependent; a moving transform or hand-authored feedback record cannot satisfy it (`docs\design\32-end-to-end-integration-scenarios.md:33-37`).

**Distinguishing example:** a one-second native Clip with events at zero/end must wrap the pose while delivering the preceding end then the next start exactly once. A pose-only seek does not emit either. Save/restore mid-transition must preserve the subsequent event sequence and derived pose without a hidden tick. A single moving mesh does not distinguish these contracts.

## 3. Cosmetic CPU particles

### Recommended owner closure

- **Select one disposition:** the first pool is Rendering-owned, cosmetic and excluded from canonical World hash/checkpoint/replay state. It has no collider or authority to write Physics. Authoritative/checkpoint-resumable particles require a separate reviewed state extension; do not add a flag that silently changes this disposition.
- **Close the real producer before the allocator.** Specify the frozen emitter author data, actual spawn-command producer, typed result/counter observation and immutable billboard consumer. Bind explicit seed/stream, dimensional spatial positions, engine-distance/time velocity, positive lifetime, frame/Atlas/Material, and color/size curves. Close curve interpolation/endpoints, finite/domain rules, lifetime quantization, update arithmetic, emitter/command/recording limits and complete byte budgets. These declarations do not currently exist; this proposal allocates no new public service or emitter member names.
- **Make capacity deterministic and atomic.** Recommend expiring/integrating existing particles before processing this tick's spawn requests in stable emitter/producer-sequence order. New particles start at age zero and first integrate next tick. Admit each spawn request completely or return the specified `RejectSpawn`; count all rejected particles, leave the pool and RNG unchanged for that refusal, and fault checked counter exhaustion rather than wrap. Total live particles never exceed 131072. Define integration/expiration equality and curve sampling with literal expectations before implementation.
- **Own the random/recording lane.** Use a distinct engine PCG32 stream, never the authoritative World's stream. Record its initial state and ordered tick-stamped cosmetic stimuli under a bounded pool-owned recording contract; recording exhaustion refuses further recorded work rather than silently dropping stimuli. Equal admitted seed/stream/ticks/stimuli supports scoped cosmetic repeatability, not StrictLocal World replay (`docs\design\27-state-serialization-replay-and-recovery.md:283-297`).
- **Join real ticks and extraction explicitly.** Enlist any World/stage/cohort participation before construction. Stage cosmetic updates with tick output and expose them only after a successful commit; no render-rate advancement, failed-tick publication or canonical control/RNG mutation. Reset the cosmetic pool explicitly on World restore/replacement; do not pretend its omitted state resumed. Copy per-camera billboard output through the actual extraction participant, count eligible logical billboard draws before culling/batching, and apply existing Sprite color/order/material rules. Close billboard orientation and 2D/3D membership instead of assuming every emitter supports both dimensions.
- **Make lifetime a full owner contract.** Reserve pool, growth/coexistence, recording, output and pin storage before allocation/admission. Pool close stops spawn admission; each old immutable output independently retains its exact assets through CPU/GPU use. World/pool/result disposal and canceled waits cannot release an in-flight output. Specify unload, failed construction and cleanup/quarantine ownership; do not let an uncharged task, lease list or retained result outlive the pool's charge.

The CPU pool algorithm can begin independently of M04 and unfinished M03-B observations **after** its production author/command/result/lifetime declarations close. World/extraction integration additionally requires its actual reviewed extension and producers. No test-only emitter, fabricated World context or renderer-maintained authoritative shadow pool is an unblocker.

**Distinguishing example:** with 131071 live particles, a two-particle request is wholly refused, increments the rejected-particle count by two and consumes no RNG. A one-particle request can then fill the pool; the next one is refused. Repeating those stimuli at different render frequencies must not change tick output or authoritative state. Exact curve/integration examples remain an owner decision, not an implied implementation choice.

## 4. Authored Mesh LOD

### Recommended owner closure

**Data and producer.** Extend the selected native Mesh catalogue through its owner versioning process; preserve current Mesh 1.0 as the no-LOD path. Recommend ordered fine-to-coarse index/group sets sharing existing vertex streams, material slots and optional Skeleton binding. Keep the same logical groups/material-slot correspondence at every level so topology selection does not change stable group draw identities. Each level independently satisfies existing index/triangle/group/skin predicates; conservative local bounds cover every level. For `L` levels, define `L-1` positive finite strictly decreasing boundary thresholds and a last-level fallback. The exact schema selection/tags, maximum level count and aggregate index/group/decoded/coexistence limits remain unresolved and must be assigned before codecs/cooking.

Use native authoring and the ordinary content build as the first real producer. No automatic simplifier, imported LOD extension, morph, meshlet, new per-asset identity or source adapter support follows. Changed package versions remain independently pinned (`docs\design\10-binary-data-and-authoring-formats.md:653-664,693-697`; `docs\design\11-assets-import-streaming-and-packages.md:19-25,43-59`).

**Selection operator.** Resolve “projected bounding diameter” explicitly in Chapter 21. Recommend the larger physical-pixel X/Y span obtained by projecting the eight corners of the conservative all-level AABB through the instance transform and copied camera, divided by that camera's quantized physical viewport height. This is a proposed precise interpretation, not the existing sphere-bound rule by implication. Use existing spatial/camera conversion and binary32 numerical contracts; do not use full target height, physics geometry or another camera's projection. After normal camera/transform admission, unqualified bounds, perspective near-plane intersection or an unrepresentable projection select the finest level conservatively with the applicable diagnostic, never an empty draw. This fallback cannot excuse invalid source camera/transform data. Close projection rounding/invalidity predicates with the numerical owner before coding.

For initial selection choose the first fine-to-coarse level with diameter `>= T` at its boundary, otherwise the final coarse level. At a boundary `T`, recommend coarsening only when diameter `< 0.9*T`, refining only when `> 1.1*T`, and retaining the previous level at equality. Compare the admitted dyadics against the exact rational factors rather than silently clamping thresholds; apply adjacent transitions repeatedly for a large jump. This resolves the currently unspecified meaning of “10% hysteresis.”

**History and extraction.** The existing World-owned CPU extraction participant owns bounded derived history, not the Renderer service. Keep at most one current history slot per admitted camera/Mesh instance, stamped with exact binding, Mesh backing and target/viewport/projection context; changed content/binding/view configuration starts from the initial rule, rather than accumulating unbounded viewport keys. Repeated extraction of the same generation/context must be idempotent. Only a fully successful extraction installs history and immutable per-camera selections; refusal changes neither. Count logical groups before culling/LOD/batching. Preserve physics topology and canonical state. A frame-only rebase must transport/rebuild existing materialized state under the cohort protocol, not discard history to evade its admission/retirement requirements (`docs\design\16-scenes-transforms-and-cameras.md:160-183`; `docs\design\21-2d-and-3d-rendering.md:31-35`).

Static native-authored LOD does not require Animation. Animated LOD additionally needs actual conservative animated bounds/palettes; qualification-zero uncertainty is not a license to cull or choose a coarser unknown silhouette.

**Distinguishing example:** with one boundary `T=0.5`, sizes `0.50 -> 0.46 -> 0.44 -> 0.54 -> 0.56` select fine, fine, coarse, coarse, fine. For an exactly representable equality witness, `T=0.625` has boundaries 0.5625/0.6875; equality retains the prior level. Binary32 0.45/0.55 are not exact equality witnesses for the rational boundaries at `T=0.5`. A second camera can simultaneously select coarse for the same instance while the first selects fine; the snapshot must retain both choices and the corresponding package geometry.

## 5. Visual picking

### Recommended owner closure

**Public operation.** Close one typed asynchronous request/completed-receipt/result path on the existing Renderer, with all transitive declarations in Chapter 30. The request explicitly identifies the exact `World`, that World's genuine `RenderSnapshot`, one selected camera, an integral physical pixel and exactly one existing Surface/offscreen texture target. Validate the existing frame/owner provenance against that exact World, not just its GUID. The owner captures actual binding, viewport/metrics, snapshot/frame and target epochs; callers cannot manufacture trusted epoch values. Specify constructor/default/null rules, owner-thread admission, queue/byte bounds, cancellation, completion and disposal authority. Distinguish a qualified selection, valid zero/`NoSelection`, invalid pixel/context, stale binding/entity/frame/target and native failure; this proposal assigns no enum members or method names.

**Membership and silhouette.** Recommend a single immutable table over the snapshot's eligible entity-backed Mesh-group and Sprite logical draws, merged in ascending RFC stable draw-GUID order independently of camera submission/batching. Dense IDs are exactly `1..tableCount`; zero is background. Table entries copy qualified entity creation identity and draw GUID, never an Entity slot. Rasterization still follows each camera's existing depth and draw-order rules. Explicitly omit CPU-hit-tested UI and, for the first cosmetic pool, particles without an entity-selection contract; ratify this pickable-set interpretation of Chapter 21's `drawCount` before implementation. Duplicate/invalid mapping or a nonzero readback outside that captured table is an error, not background.

Use the same admitted skinning, selected per-camera LOD, clipping, culling, alpha mask and blended pick silhouette. Close a separate Material-owned blended pick-alpha setting with default 0.5 and finite `[0,1]` domain; do not silently reuse the existing mask cutoff. Its exact author/schema declaration and selected version remain unresolved. Static Mesh/Sprite picking can be delivered before Animation/LOD, but later variants must consume those actual producers, not synthesize their output.

**Native work and retention.** Use a real same-device R32UInt selection attachment with color-attachment/copy-source usage, cleared to zero, and the prescribed reversed-Z depth. This is separate from the graph's ordinary Surface/offscreen color output and its terminal color encoding. Close how the operation adds the ID pass to that exact snapshot/target graph and submission; raw graph options are not a substitute. Its format usages, pipeline/reflection and depth behavior must be admitted by the actual backend. Copy the requested pixel through the existing region copy into a real 1x1 R32UInt destination with copy-destination/copy-source usage, then use full-subresource texture readback. The region equals the complete destination extent; no new transfer API, transient materialization or synchronous render-thread readback is implied (`docs\design\17-graphics-device-and-resources.md:14-21,151-159`; `docs\design\19-render-graph-synchronization-and-presentation.md:7-31`).

Before asynchronous escape, retain the exact snapshot/table/target/pipeline/readback owners and any independent active-World use needed for identity reconciliation. Keep each until its actual consumer/fence/map/CPU copy ends, including cancellation and uncertain completion. Picking's new operation still needs its own finite workspace/result envelope under the existing M03-B use contract; Scene preparation's envelope is not transferable permission (`docs\design\12-entities-components-and-queries.md:39-54`).

**Reconciliation.** Resolve only against the captured exact World binding and qualified entity identity on its owner, never the graphics thread or a same-GUID successor. Recommend refusing changed frame/viewport/metrics/target context rather than auto-remapping/reprojecting in the first version. A later tick alone does not relabel the old snapshot/table or turn a returned historical identity into a live Entity. Validate context before interpreting zero; a stale result is not `NoSelection`. Binding closure must be reportable without calling into an already disposed World, while actual native consumers remain retained. Offscreen requests retain zero surface/swapchain epochs and make no presentation claim.

This depends on the real M03-B independent-use/owner-reconciliation route only where active authority survives asynchronously. Immutable snapshot/asset retention alone does not confer that authority and does not require a fictitious live-World credit. M04's real device/graph/copy/readback producers are necessary for execution, but its deferred physical-input/loss/timeout observations are not prerequisites for ordinary picking implementation.

**Distinguishing example:** submit ID 1 from an old snapshot, destroy/reuse that entity slot, then finish the real readback. The result must refer to the original qualified identity or refuse; it must never select the new slot occupant. Repeat with rebase/resize and with a same-GUID World replacement. A valid zero pixel is the separate background case (`docs\design\34-engine-acceptance-cases.md:250`).
