# M05 common-representation integration gate

## Result

**Tentative lower-representation refinement; implementation stopped before source edits.** The [standing-owner construction addendum](m05-cosmetic-particle-standing-owner-construction-addendum.md) selects the private registration route, but its sections 2 and 5 also forbid installing unpriced common fields. That restriction is reached before a safe World construction/retention/disposal batch can be completed.

The blocker is **not another particle token choice**. It is the missing representation-specific common charge/coverage needed to preserve unselected registrations and Worlds. A selected-profile refusal does not protect an unselected instance of a class whose physical layout changed.

No source/tests change and no build, test, World, Scene or pool operation runs in this turn. Do not add a permanently throwing registration method as a substitute for the selected immutable request.

## Source evidence

| Actual input | Consequence |
|---|---|
| `WorldRegistrationBuilder` has its component/provider lists, support references and `_isBuilt`; there is no cosmetic-selection slot. | Persisting the selected request requires a representation change, not just another method. |
| `WorldRegistration` has immutable component/provider arrays, support references, schedule and schema backing. Its `RestoreSources` partial adds methods only. | There is no existing generic optional-state carrier to reuse without changing semantics. The new Boolean is part of every registration's physical type. |
| `WorldConstructionPlan` already captures the exact registration through resolved options, plus the actual lifetime/domain reservation. | Do not add another independently owned grant or a restore-plan control merely to carry the same claim. |
| `WorldLifetimeControl` has no cosmetic owner or pending-construction retention field. | Its strong retaining path must be implemented; an unused local reference or marker interface is insufficient. New fields here also affect unselected Worlds. |
| `World.AdmitWorld` prepays the existing control group with `FreshWorldControlBytes = 4096`; the selected owner gate is currently false. | Neither number proves that a changed common header, new construction state, or its caller suffix fits existing funding. |
| The measured test observes only `Cell` and the array accounting input. | Its 10,304 bytes pay for neither these common deltas nor selected header/control/cleanup allocations. |

Do not encode the request in array identity/defaultness, a fake component/tag/resource/system, a recycled grant field or a process-global lookup. Do not unseal public registration types or manufacture another registration family to avoid pricing the selected change.

## Minimal representation selected for the next candidate

Refine physical storage as follows; the logical ownership and failure policy from the standing-owner addendum remain:

| Type | Additional representation |
|---|---|
| `WorldRegistrationBuilder` | One private Boolean for the explicit request. Keep the existing frozen-builder state separate. |
| `WorldRegistration` | One readonly Boolean, exposed only by the selected internal property. No per-World mutable state or owner pointer. |
| `WorldLifetimeControl` | One nullable reference to a private, selected-only `WorldCosmeticCreditStandingControl`. Null for unselected lifetimes. |
| `WorldConstructionPlan`, `World` | No new instance fields for this feature. Use their existing lifetime/registration edges; plan access observes the once-bound immutable admitted amount through that exact lifetime binding. |

`WorldCosmeticCreditStandingControl` is one real construction/retention record per selected World, not a second disposal right or a producer. Its closed data inventory is:

- The exact registration, original domain reservation and captured WorldGuid grant; the exact lifetime binding is established once.
- A readonly admitted standing amount; actual World owner-thread identity bound before storage initialization.
- Nullable actual `WorldCosmeticCreditOwner`, construction/installation/close/retained phase, and the first construction and cleanup exception references.

It owns no Task, delegate, Scene object, source callback, registry or extra U. It cannot retarget its registration/grant/reservation/lifetime. Its header and fields are a **new selected row**, not free bookkeeping.

The actual strong retention path becomes **existing World/plan → lifetime → standing control → actual credit owner/debt**. This refines the previously drawn direct edge without changing the World lifetime's sole grant/release ownership. The standing record is installed before child-owner construction; failed child construction can therefore retain its original claim and cause without inventing an owner object. Its own unescaped header allocation remains under the funded original construction caller, not an imaginary preexisting child.

Do not put the amount, phase and failure fields separately in every World and plan. Do not treat this selected-only record as permission to allocate it before complete standing admission or to omit the prior construction/close-tail gates.

## Required evidence order

1. Freeze the actual baseline and proposed field sets separately, with resolved target/runtime/compiler and binary inputs. The three common changes above need their **actual compiled** shallow-layout delta, field/alignment/GC-reference derivation and unselected constructor/call-path audit. A false/default value does not imply zero cost.
2. Use the existing managed layout-fixture approach without invoking World/candidate constructors to establish that narrow representation input. Do not measure a shadow class or report an uninitialized object as an operational owner. This is a prerequisite layout-evidence batch, not a World lifecycle test or allocation-envelope proof.
3. Attribute builder/registration metadata to its actual registration owner and registration-byte boundary. Attribute changed lifetime/control storage to the actual World/control provision. A shared immutable registration is not charged physically once per World. A zero delta is usable only if the target-specific representation/constructor evidence supports it.
4. Prove coverage in the existing provisions or revise their actual accounting before either selected or unselected construction executes with the changed types. Do not assume spare bytes in the 4096-byte control group. Where a common constructor gains runtime children or wrappers, shallow header sizes alone do not close its row.
5. Only then integrate the real private request, original-reservation attribution, standing record, lifetime edge and symmetric unwind/disposal predicates. Keep the full selected standing profile unavailable until its complete constructor/failure/close and caller-return catalogue closes.

After step 4, ordinary **unselected** World create/dispose regressions and explicit **selected-profile refusal** cases can exercise the integrated gates in Debug then Release. Successful selected construction/retention/disposal tests remain unauthorized by the current evidence: they require the complete standing profile. Hosted, external-domain, restore, operation, publisher and Scene/pool paths retain the previous refusals.

This order is not permission to change common fields in an otherwise live build and run ordinary World tests first to discover whether they fit. If common coverage cannot be established, leave the physical hook out and report the particular type/row. If the standing constructor/retirement caller still lacks a budget-aware return boundary afterward, keep that separate gate closed as well.
