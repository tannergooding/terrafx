# Implementation roadmap

The [design roadmap](../design/35-implementation-roadmap.md) defines milestone scope, dependencies, and acceptance gates. This page tracks current implementation status and remaining qualification; it does not redefine those contracts.

M03-A implementation work for the selected standalone World/provider/control/generator graph is complete. M03-B implementation is in progress on the selected Assets and Scene producer paths; the remaining persistence/history and broader acceptance work keeps M03 overall in progress. Platform, workload, and broader acceptance observations are recorded separately as later qualification work. Core exposes bounded schema-agnostic EBIN structural/payload operations, immutable exact-tuple schema/profile metadata, 25 functional content-primitive schema rows, projections of the eight frozen Foundation descriptors, immutable diagnostic records/query, a bounded coalescing ring, and a private monotonic diagnostic clock. Assets publishes four native envelope/reference/metadata schemas. Runtime publishes 60 selected standalone checkpoint/state schemas, 18 scene/prefab schemas, and 11 animation schemas. Graphics publishes 26 mesh/material/texture/atlas and rendering-component schemas; Physics publishes ten primitive/support/statistics schemas. The nonfriend consumer composes these rows with five application-role schemas into a closed 167-schema `CompiledContentSchemaRegistry`. `WorldRegistrationBuilder` freezes component/tag registration; public standalone World construction reserves WorldGuid/domain lineage, issues one Core OwnerId, binds diagnostics, initializes spatial frames, and retires its committed fresh-lineage root on disposal. The fresh-root registrar has byte-charged root, World-interest, reservation and one-key-per-root arrays, a full-GUID shared index, and old-plus-new peak-reserved growth. World now consumes immutable `EntityDescription` inputs for atomic entity creation, stable-identity lookup, typed component Has/TryGet/Set, component and tag Add/Remove archetype migration, identity/slot retirement, and synchronous scoped chunk queries. Typed columns retain the 32-KiB logical-row target and clear/move data during swap removal; a persistent canonical component/tag work plan assigns global 64-row ordinals and enforces its current/candidate byte peak. The unsafe-disabled handwritten consumer exercises real defaults, component/tag transitions, reads/writes, and query callbacks. A separate unsafe-disabled generated consumer compiles and executes the same public registration, World mutation, default, and scoped-query route without changing the handwritten consumer.

The bounded schedule retains deterministic dependency-depth execution waves, and standalone `World.Step()` issues fixed-tick contexts, runs owner-thread systems on the owner and Parallel systems on the per-World fixed pool, validates each system on normal/exceptional exit, and installs an immutable committed publication before synchronous subscriber delivery. `TrySubscribe` enforces 64 ordered registrations, monotonic positive IDs, captured-batch semantics, bounded delivery results, exact subscriber exception identity, and the specified coalesced capacity warning. Deferred commands now admit deterministic live-Entity Set/Add/Remove/tag/Destroy and same-prefix token Create/Set/Add/Remove/tag/reference/Destroy forms. Stage-7 preflight builds the sequential membership/value shadow, checks surviving references against final membership, prepares archetype/slot/identity/attachment cleanup and receipts, and installs the structural result before Extract. Token destruction cancels its pending Create and component edits; later use or a surviving reference to the canceled token faults the batch. Successful receipts carry token resolutions/cancellation and qualified destroyed-identity vectors; transferred Entity attachments release once after committed destruction. Authoritative references are revalidated after stage-7 playback and Extract before publication. Standalone time-scale and identity-branch controls plus current-frame candidate/commit operations are implemented; the frame-cohort currently has no selected Scenes/Rendering participant and therefore does not claim their retirement behavior. Focused component accessor generation now emits explicit field-tag paths/accessors and is tracked for deterministic output, invalid input, relevant/unrelated edits, addition, and removal. World-owned generation-bound hierarchy links are assigned during atomic Scene activation; descendant-first `DestroySubtree` and preflighted `DetachChildrenKeepWorld` now share the atomic command path. SceneInstance hierarchy transactions now stage typed intent and atomically revalidate/commit at the owner boundary; no placeholder hierarchy was added.

Component default and codec-validation providers run through real create/set/migration operations and writable query-scope closure. Typed required/optional Entity-reference field bindings validate same-World live targets on create, Set, migration, and writable query close; immediate and deferred destruction refuse targets still referenced by surviving component or transferred-attachment values. Deferred structural references are checked against the final sequential shadow, including explicit same-batch clears/rebinds, and full membership/reference scans run after stage-7 playback and Extract. Invalid values reject before commit; invalid values discovered after a writable query span fault the World and publish its first `LastFault` diagnostic. Create/Add/Remove preflight closes registered Derived dependency membership; Derived rebuild and restore execution is issued by the later candidate-restore owner. ResourceState schemas resolve exact Content metadata and typed nested/FixedArray paths; typed factory/codec families register together and freeze in `WorldRegistration`, with unique identity and partition-domain checks. Fresh per-World `T[P]` storage is charged against both the admission domain and the resource/system-state subbudget. `World.Create` executes each registered resource default and codec validation over the complete partition set under revoked operation-scoped bindings; the unsafe-disabled consumer witnesses this public registration and initialization path. Systems traverse resource partitions through invocation-scoped access declared by their registered range; persistence Read/Restore/Count/Write operations still require the real persistence owner. Stateless and stateful system instances execute through the frozen schedule; their provider state Read/Restore/Count/Write roots remain persistence-owned. Owner-thread disposal releases instances in RFC-SystemId order, publishes a bounded preprepared cleanup report, and continues through every safe release. Cleanup fallback causes are prepared before factory callbacks, exception-finalization failures retain their exact cause and sealed report, and pre-reserved quarantine capacity keeps failed instances and their admission-domain charge strongly retained. A factory that returns an already-owned or still-reachable prior instance is rejected. Typed AttachmentState descriptors/readers and factory bindings with complete field closure/provider roots are frozen by `RegisterAttachment`; World operations validate captured fields and optional same-World Entity references. CallerOwned transient World/Entity attachments now support scoped Set/TryGet/Remove, budgeted table growth, and detachment on owner destruction/disposal without disposing caller values. Transferred installations issue distinct positive IDs and release each detached value after replacement, removal, Entity destruction, and World disposal. Release failures produce bounded reports with exact cause identities, continue safe cleanup, and quarantine values while retaining their domain reservation. The selected A route admits fresh standalone World roots; validated retained-history vectors, shared-key lineage edges, independent history interests, full `K`/66561-reference history capacity and handoff/replacement belong to later persistence/lineage owner operations. World-owned hierarchy links are assigned during Scene activation; descendant-first `DestroySubtree`, preflighted `DetachChildrenKeepWorld`, and queued SceneInstance transactions now share atomic World command playback. The handwritten and generated public consumers pass Windows x64 NativeAOT Release; Linux NativeAOT, M02 target-profile qualification, production count/byte-boundary cases, and baseline performance workloads remain later qualification evidence. A persistent component/tag work plan now orders partitions by archetype key, chunk ordinal, and row; structural changes rebuild it under the checked epoch, and growth is charged against current-plus-candidate `MaximumWorkPlanBytes`. Queries traverse that plan synchronously within each system invocation.

`Ready to start` means the next unit has accepted prerequisites, not that the entire milestone is contract-ready or implemented. `In progress` records actual implementation work; `Blocked` names the missing decision or capability and the unexecuted observations. `Qualification pending` means implementation is present but required observations remain; it is not a completed prerequisite milestone. `Complete` requires the design milestone's entire exit boundary. A partial feature, empty suite, managed build, or reference helper cannot stand in for a required engine/native/AOT observation.
