# Implementation roadmap

This page tracks current milestone state and open gates; it is not implementation history. Milestone scope, dependencies, and acceptance criteria are defined in the [design roadmap](../design/35-implementation-roadmap.md). Build and qualification commands are in [Building](Building.md). Use Git history for provenance and ignored artifacts for detailed test output.

| Milestone | Status | Current state and remaining gates |
|---|---|---|
| M01 - Repository and implementation readiness | Complete | Repository and first-unit prerequisites are established. |
| M02 - Core ownership, numerics, and spatial data | Qualification pending | Selected implementation and managed regressions are complete. Target-profile NativeAOT and performance/capacity qualification remain. |
| M03 - Worlds and native semantic content | In progress | M03-A selected World, Scene, control, provider, and generator work is implemented. Production Standard/StrictLocal Save, selected Assets/Scene producers, typed Mesh/Skeleton/Clip package codecs, package-backed Mesh-to-Skeleton/material/texture and Clip-to-Skeleton/expanded-Scene/Atlas binding validation, and static BindPose `render/mesh` component registration/preparation/grouped CPU extraction now exist. Restore-side stable identity ledger reconstruction can rebuild the complete history/index and target locator maps under a preflight storage ceiling. Internal package-backing identity scopes retained Sprite residency across package replacement. Candidate World construction, exact replacement capture, Load, and host schedule adoption remain open. |
| M04 - Native host, input, and presentation resources | Implementation complete | M04-owned Windows/Linux Platform, recipient routing, text/clipboard, D3D12/Vulkan graph and WSI paths, snapshot residency, and host recovery are implemented. Native graphs exercise four color attachments, later-pass copies to and from rendered attachments, sixteen sampled images with eight sampler bindings, eight-UBO native pipeline layouts across Frame/Material groups, and cross-slot transient allocation retention; staging ranges are fence-owned and native descriptor heaps exercise exhaustion, rollback, and reuse. Color/depth attachment actions are supported for the admitted shape. Windows keyboard routing and the focused physical Xbox GameInput button/device-removal/reconnect lifecycle are verified. The UI-owned capture integration check and real driver/OS loss, submitted-work/presentation timeout, and uncertain-work retirement observations move to M09; the production UI provider is owned by M08. Physical TSF IME testing is deferred with user acceptance unless issues are reported. WSLg uses llvmpipe and has no physical evdev input. |
| M05 - Renderer, animation, and source adapters | In progress | CPU kernels/layout, offline shader compilation/reflection, package-backed static Mesh/Sprite extraction, Atlas residency/batching, camera projection data, built-in Sprite C0, and opaque, alpha-masked, and premultiplied-blended PBR Mesh C0 with optional sRGB base-color/emissive, linear packed metal/roughness/occlusion, linear normal, and linear RGBA vertex-color inputs are implemented. Chapter 21 specifies perspective-correct vertex-color interpolation and componentwise modulation of base-color RGBA; colors do not affect emissive or metallic-roughness-occlusion terms. The bounded normal-map path is single-sided opaque PBR with authored UV0/tangent streams and normal scale; mirrored transforms are refused. Static BindPose Mesh skinning consumes the real extracted per-frame palette, four authored influences, and CPU-derived inverse-transpose bone normals across the existing PBR alpha and texture variants; live animated palettes remain separate. Its Vulkan vertex-storage pipeline is enabled only when `vertexPipelineStoresAndAtomics` is advertised; unskinned Mesh pipelines do not require that feature. Masked draws compare linear base-color/texture/vertex alpha to the authored cutoff; Vulkan enables helper-invocation demotion when supported and refuses the mask pipeline if not. Blended Mesh draws use extracted back-to-front order, premultiplied source-over, and depth test without writes. Mesh C0 supports up to 256 camera-layer-matched, unshadowed point lights per camera with Chapter 21 flux/range attenuation. Directional cascade split, camera-corner, and light-fit CPU kernels exist, but native shadow passes remain blocked: Chapter 19 requires RenderArea to fit both the graph output target and selected attachment, while a 1024-pixel atlas tile can exceed the snapshot output extent; an owner-approved attachment-scoped render-area contract is needed before native shadows. Spot lights remain refused pending their contracted cone, attenuation, and shadow paths. Sprite C0 draws real snapshot passes into HDR, applies camera clears/tone mapping, and retains package-backed Atlas pages. Mesh C0 uses reversed-Z depth, captured transforms, material factors, default ambient irradiance and emissive; texture maps require authored UV0, linear minification/magnification, no mip filtering, and clamp addressing. Mixed Sprite/Mesh composition remains refused. Both paths reject unsupported inputs and initial target writes that cannot establish full contents. M03-B Load/restore, source adapters, dynamic animation/particles, remaining PBR, and applicable native/AOT/consumer qualification remain. |
| M06 - Standalone custom physics | Not started | Dimensional cooking, solver, queries, CCD, and checkpoint qualification remain. |
| M07 - Custom audio and subsystem integration | Not started | Custom mixer/endpoints and integrated subsystem observations remain behind their applicable prerequisites. |
| M08 - Editor, extensibility, and release qualification | Not started | Editor/tooling, closed modules, M08-owned acceptance, and release measurements remain. The production UI disposition provider needed by the deferred M04 capture check is owned here. |
| M09 - Missing validation | Qualification pending | Close the deferred M04 UI-capture integration and real native loss/timeout/uncertain-retirement observations after the production UI provider and safe native stimuli are available. These observations do not block unrelated implementation. Physical TSF IME testing remains deferred by user acceptance. |

## Next work

1. Close exact M03-B restore state-transfer, candidate-construction/issuance, and host schedule-adoption actors before implementing Chapter 27 Load and restored-World extraction.
2. Select an explicit bounded source/output subset and a second independent adapter with overlapping native semantics before source-tool implementation; do not infer formats or approximations.
3. Keep live animation and particles behind their owner contracts. Extend Mesh beyond its bounded C0 subset only with the applicable shadow, light, animation and material variants. Obtain the Chapter 19 attachment-scoped shadow render-area contract before native directional-shadow integration. Complete native/AOT/consumer qualification separately from M05 implementation and M08 release qualification.
